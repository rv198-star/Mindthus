# SRA v0.3 Runtime Integrity Implementation Review

Date: 2026-09-04
Base: `origin/main` at `542ad7fd938e23ed1409b8b1eaca0f73dd4f3c36`
Candidate: `fix/sra-v0.3-root-cause-rebuild`
Review type: process-independent runtime/integrity review

## Independence Boundary

This review used a second isolated Git worktree and a separate review-only attack suite.
It did not read the method/domain review findings before completing its own probes. The
same assistant operated both reviews because the external fresh Codex carrier was not
authenticated in the OCI environment. Therefore this is process independence, not
model-identity independence.

## Review Question

Can the v0.3 runtime detect or refuse changes to authoritative inputs, Agentic judgments,
carrier evidence, derived execution surfaces, final decisions, and trace chronology while
still repairing derived artifacts without rewriting judgment authority?

## First-Pass Findings

The first implementation candidate passed its existing lifecycle tests but failed five
additional integrity probes:

1. Repair could accept a changed `raw-input.json` and rebuild all hashes around it.
2. Repair could accept a changed Agentic judgment and bless a new judgment hash.
3. A receipt record could point outside the run directory rather than to the fixed
   per-stage stored receipt.
4. A trace event timestamp only had to be non-empty; it did not have to be a parseable UTC
   time.
5. In one direction, `run.json` carrier metadata could disagree with an intact trace and
   Repair would prefer the state value.

These failures allowed Repair to turn an authority conflict into a clean derived state.

## Root-Cause Corrections

The runtime was revised so that:

- the prepared raw-input hash is an immutable repair anchor when recorded state exists;
- recorded judgment hashes are repair anchors and changed Agentic judgments are refused;
- Repair reconstructs only derived packets, surfaces, comparison, final copy, trace, and
  cache state;
- receipt metadata must use the fixed `receipts/<stage>.receipt` relative path and remain
  inside the run root;
- trace timestamps must parse as timezone-aware UTC values;
- carrier metadata from state and a valid trace must agree in both conflict directions;
- invalid or conflicting carrier evidence stops Repair rather than being silently
  rewritten;
- malformed runtime content fails closed into a structured blocked report;
- prompt, output schema, dispatch, and command surfaces are rebuilt and compared, not
  merely checked for existence.

## Final Executable Evidence

The isolated final runtime review reran five adversarial probes against the final
candidate:

```text
repair after Agentic judgment mutation                PASS (refused)
repair after raw-input mutation                        PASS (refused)
state/trace carrier conflict                           PASS (refused)
receipt path outside run root                          PASS (blocked)
non-UTC or malformed trace time                        PASS (blocked)
```

Result: `5/5 PASS`.

Equivalent permanent regressions are recorded in:

```text
tests/test_sra_v03_runtime_lifecycle.py
```

The normal repair path also remains covered: derived prompt, schema, dispatch, command,
packet, comparison, final-copy, trace, and cache corruption can be rebuilt while recorded
Agentic judgment bytes remain unchanged.

## Integrity Claim Boundary

The runtime provides deterministic reconstruction and detectable contract drift for local
run artifacts. It does not claim tamper-proof storage, an external trust anchor, complete
context, correct challenge projection, absent hidden host context, or semantically correct
priority.

A caller requiring adversarial security against a writer who can replace every local
artifact still needs an external signature, append-only store, or separately controlled
receipt system. That is outside this repair.

## Verdict

**PASS for the declared local runtime-integrity and repair boundary.**

The final candidate no longer uses Repair to bless changed raw input, changed Agentic
judgments, or conflicting carrier evidence. It safely rebuilds derived artifacts within
the recorded authority boundary.
