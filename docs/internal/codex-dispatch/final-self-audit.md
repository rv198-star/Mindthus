# TPlan 与 Dispatch 最终自查

2026-11-18。审计基线 `f19d9e65e`。一个主会话串行审计两项技能，取证范围为该版本的规则和运行时，以及前两批已结束的 A、B 四个执行轮次。使用已有计数，未新增模型试跑。

## 发现与处置

| 项目 | 基线问题 | 已落实的行为 |
|---|---|---|
| 纠偏 | TPlan 可以把同一对象的第三次处理送进反螺旋检查；独立 Dispatch 的主路径更偏重“派出、收回”。长任务缺少主会话重新判断方向的明确时机。 | 对长任务在首条说明约定一个可观察的检查点。A 在检查点、恢复或交接时，用原目标和最新证据回答“哪条验收差距缩小了、再做一步会知道什么”。如果反复处理同一细节却没有新证据，就换验证方式、简化或暂停该路径。B 工作期间可以自己做同样的判断。见 [TPlan 入口](../../../skills/tplan/SKILL.md) 与 [Dispatch 检查点](../../../skills/codex-dispatch/references/batch-handoff.md#check-direction-without-shadowing-b)。 |
| 并行和过频联系 | Dispatch 已经要求同一份交付先由 B 实现自测、交固定版本，再由 A/C 验收。但 TPlan 的通用协同说明曾在反馈缺少关联时直接要求追问，容易在原回执已有答案时另起一次交互。 | 两个入口统一按固定版本交接；没有另行分配的其他交付，A 就等待。先查现有记录，无变化的等待超时用已有游标退避。普通问题随批交付；涉及权限、共享契约、其他任务的依赖，或确实阻塞决定时，合并成一次有证据、点明所需决定的联系。见 [协同协议的使用步骤](../../../skills/tplan/resources/collaboration.md) 和 [Codex 跟进规则](../../../skills/codex-dispatch/references/host-operations.md#dispatch-and-reconcile)。 |
| 缓存和上下文 | 模型调用的缓存输入占比已经较高；重复读取整份历史、重发契约或反复查询仍会产生额外输入和主会话步骤。 | 同职责、已授权且适合续接时复用原会话。固定角色、范围和验收放前，新的轮次标记、产物版本和变化放后；第一次派工仍给完整说明，后续只补差异。TPlan 常规跟进先读恢复摘要，涉及授权、版本、验收时再查相应完整记录，写入仍使用精确快照。一次完整性优先的独立审计保留独立上下文。见 [短续接提示](../../../skills/codex-dispatch/references/host-operations.md#keep-follow-ups-small)。 |

## 历史缓存基线

| 完成的批次、会话 | 用量记录数 | 输入 token | 其中缓存输入 | 未命中输入 | 缓存输入占比 |
|---|---:|---:|---:|---:|---:|
| Dispatch 首批，A | 65 | 8,975,908 | 8,640,256 | 335,652 | 96.26% |
| Dispatch 首批，B | 38 | 3,879,207 | 3,584,384 | 294,823 | 92.40% |
| TPlan 联合批，A | 80 | 15,618,641 | 15,203,200 | 415,441 | 97.34% |
| TPlan 联合批，B | 51 | 9,904,132 | 9,587,072 | 317,060 | 96.80% |
| 合计 | 234 | 38,377,888 | 37,014,912 | 1,362,976 | **96.45%** |

口径：在明确的开始和结束事件内，按会话对累计 `input_tokens` 和 `cached_input_tokens` 求增量，再按批累加。234 条有效增量均与对应的 `last_token_usage` 一致，无计数重置或缺项。分母是输入 token，缓存是其中一部分；四行合计按 token 加权。A、B 各自使用一个模型，角色和上下文长度不同。报告只保留聚合值。

两个具体观察：

- 联合批的 A 向 B 实际派工 **1 次**，另有 **9 次**只读等待查询。查询没有给 B 发消息，但每次返回都可能使 A 再处理一次上下文。优先合并无变化的等待，而不是规定 B 定时汇报。
- 对该批已关闭的 Mission，用它固定的 writer 读取一次 `snapshot.get`：完整 `data` 的紧凑 JSON 为 **9,769 字节**，只取 `mission_id`、`resume` 和 `expected_snapshot` 为 **711 字节**。这是一个状态读取示例；具体决定仍需取出相关的原始意图、约束、反馈或审查记录。字节数不折算成 token 或费用。

[OpenAI 提示缓存指南](https://developers.openai.com/api/docs/guides/prompt-caching#preserve-conversation-history)建议保持可复用前缀，并把变化追加在后。技能能控制交接文本和读取范围；底层缓存参数由宿主控制。本次没有测量修订后的节省幅度。后续从相近的自然批次比较每项已验收交付的**总输入、未命中输入、模型步骤和主动联系次数**，同时保留模型、任务范围和上下文差异。

## 验证

反螺旋、Mission Pulse、协同状态机、打包和发行边界合计 **162 项专项回归通过**。其中包含重复处理同一对象、普通进度不改主线、阻塞回到主会话、正在执行的写入范围保持占用、修订后按新版本再审。检查点自查、问询合并和续接文本是 Agent 的工作约定；自然使用中的改善用上述下一批指标验证。
