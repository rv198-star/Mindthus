# Codex 多模型会话派工：功能草案

状态：v0.2，联合接入，2026-11-18。本文定义 `codex-dispatch` 的用户可见行为；宿主接口、授权和反馈如何落地，见[设计](design.md)。

## 解决什么问题

主会话 A 要把一项工作交给不同模型分别设计、实现或审计。用户应当能在派工前看懂并决定用哪组会话；派工后，各会话自行解决职责内的问题，值得保留的设计偏差随成果回到设计方。用户通常只需参与一次组合选择，以及真正需要他决定的设计变更。

用户要配置或安排分工时进入本流程；仅讨论模型或协作方式时停在建议阶段。临时查代码、比对资料等一次性工作优先使用当前会话的 **SubAgent**。需要不同模型持续承担职责、保留返修上下文或独立审计时，使用**独立 Codex 会话**。本技能主要服务后一种场景；用户明确要为 SubAgent 配置模型时，也使用相应宿主的清单。技能可以单用，也可以由 TPlan 主会话调用。

在 Codex 的 TPlan 协同中，A 默认执行已安装的 Dispatch，用户无需再点名。沿用同一批的目标、合同和授权；完整授权组合直接校验，其余按 Dispatch 一次选择。A 仍是唯一 Mission writer 和验收人。单独用 Dispatch 时无需 Mission。

## 正常使用路径

1. **先取模型列表。** 确定准备在哪个宿主、以哪种会话工作，读取那里实际公布的可选型号、支持的推理档和默认档。用户已点名的模型也要核对。会话使用的提供方不同时，分别核对。
2. **能力不清楚，就做一轮联网查证。** 只查会影响本次分工的问题，例如某个具体版本是否适合跨文件排障、某条成本信息是否适用于该渠道。优先看官方模型卡、发布说明或有明确任务和版本的评测。用户已有的同类任务经验一并纳入。查完仍不清楚的地方，在方案中说明。
3. **给出可选的整组方案。** 默认准备两至三种有实质差别的组合，推荐其中一种，并说明适用条件和取舍。每个会话列职责、首选模型及推理档、按顺序的一至两个替补模型及各自推理档。合格选项不足就展示实际数量及缺口。用户指定的人选、档位和独立审计要求贯穿每个方案。
4. **默认弹出选择提示。** 用户可以选一组、用自然语言改一项、提出整组搭配，或暂不派工。提示同时说清将复用或新建哪些会话、由谁向谁派什么工作。收到明确选择后才执行列明的动作；预选或沉默时保留方案。宿主没有选择控件时，在主对话中提供同样的选择和自由输入。用户已明确给出完整组合及执行授权时，核对通过即可执行。
5. **确认一次，按批交付。** 接手方知道目标、设计版本、可改范围、验收条件，以及什么情况值得立即回报。在范围内自行选解法、定位、验证；主会话继续自己的工作。需要独立审计时，审计方对固定版本给结论，主会话负责采纳或发回返修。
6. **把偏差带回设计。** 接手方对照基准设计记录实际偏差、证据、处理和建议。已经解决的随本批交付；继续执行就必须改变目标、对外契约或验收条件时，立即把冲突交给有权决定的人，暂停受影响部分。设计方逐项回写新版本，或记录保留为局部例外的原因。

## 用户会看到什么

示例：A 已在本机使用 Astra 6.2 / high，准备让 B 实现导入功能、C 独立审计。以下型号和档位仅演示提示的写法；运行时按现场清单生成。箭头后是该会话的第一替补。

> **请选择本批的会话组合。** 两组都保留当前设计会话 A（Astra 6.2 / high → Astra 6 / high），新建 B、C。确认后由 A 向 B 派工，待 B 交付后将固定版本交 C 审计，两份结果都由 A 读取。A 的替补只用于另行交接主会话。

| 可选方案 | B · 实现（首选 → 替补） | C · 独立审计（首选 → 替补） | 为什么选它 |
|---|---|---|---|
| 方案一 · 按已定设计执行（推荐） | DSF 4.1 Flash / high → Qwen 3.8 Flash / high | Sol 6.2 / high → Opus 5.5 / high | 已有字段契约和验收样例，B 可整批实现，C 集中检查边界。 |
| 方案二 · 加强实现方排障 | Sol 6.2 / xhigh → Sol 6.1 / xhigh | Opus 5.5 / high → Gemini 4 Argon / high | 预计要追查多条读写路径，愿意把更多推理投入给 B。 |

用户可以直接回复“用方案一”，也可以说“按方案二，B 改成 high，其他照旧，开始”。主会话校验修改后的组合后执行。若用户只说“我倾向给 B 用 Sol”，主会话保留其余约束，补全受影响的选项供确认。

## 首版验收场景

以下是实现时要验证的行为，本轮交付物为文档。

| 场景 | 应看到的结果 |
|---|---|
| **F1 · 两类会话**：先要求临时查证，再要求多模型开发和审计 | 前者走当前会话的 SubAgent 规则；后者给出独立会话分工。指定 TPlan 时，只有 A 管理 Mission。 |
| **F2 · 先取清单**：目标宿主缺少本机有的型号，或只支持部分推理档 | 每个可执行组合都来自相应目标清单。锁定项不可用时指出具体缺口。 |
| **F3 · 能力存疑**：清单里出现陌生版本；另一次使用已验证的同类模型 | 前一次做一轮有来源的联网查证；后一次直接组合。断网或查不到时向用户显示剩余未知。 |
| **F4 · 组合选择**：打开提示但没有提交；随后自由输入修改 B 的档位并确认 | 等待期间创建和发送次数均为零。确认后 B 只收到一份按新档位执行的指令；C 在 B 交付后收到对应版本。 |
| **F5 · 替补**：首选服务确认失败；或仅仅是首次发送的结果未知 | 前者按已经确认的顺序使用合格替补，告知实际执行组合；后者先核对原会话，避免两个执行者同时写。 |
| **F6 · 本地解决**：方案按单页写，实际接口返回游标，仍可读全 | 实现方补遍历和跨页验证，随交付列明偏差；设计方回写“读至末页”并关联版本。过程中无需请示。 |
| **F7 · 重大冲突**：源端只保留最近 100 条，验收要求完整历史 | 受影响部分停下，带证据和需要决定的问题交回 A；其他独立工作继续。 |
| **F8 · 审计返修**：C 已审 v1，B 交回 v2 | A 把 v2 和验收条件交 C，依据 v2 的审计结果判断是否收口。 |
| **F9 · 已知会话**：用户在 Codex 中只启用 TPlan 协同，已授权复用 B | A 进入实际安装的 Dispatch，核对目标清单、档位、替补和已有授权；复用原批的合同和意图，一次发送、同一 Mission 登记回执。 |
| **F10 · 新建晚到 ID**：创建将首条 Brief 一并发送，先返回待建引用 | 先持久化目标和派工意图，再发送一次。未知时占用原任务写入范围，依据原宿主和首轮证据一次绑定正式会话。只有关联到正确来源和版本的反馈能进入验收。 |
