# 请求

/mindthus:explain 把以下操作说明说清楚。

# 源材料

操作者在测试环境运行 `reportctl validate --input <已导出的配置文件>`。退出码0表示静态校验通过，不表示线上配置已经生效。退出码非0时停止，保留输出交给项目维护者。只有校验通过且维护者确认目标环境后，操作者才运行 `reportctl apply --environment <维护者确认的环境> --input <同一配置文件>`。成功输出的变更编号要记入交付记录。此文档没有定义失败后的自动重试或回滚，不应从静态校验结果推断生产影响。

# Explain输出

流程是：**先在测试环境校验配置文件；校验通过且维护者确认目标环境后，再应用同一份文件；成功后记录变更编号。**

### 1. 在测试环境做静态校验

操作者使用已导出的配置文件运行：

```text
reportctl validate --input <已导出的配置文件>
```

根据退出码处理：

| 退出码 | 含义与处理 |
| --- | --- |
| `0` | 静态校验通过。它不表示线上配置已经生效；应用前仍需维护者确认目标环境。 |
| 非 `0` | 停止操作，保留命令输出并交给项目维护者。 |

### 2. 满足两个条件后应用配置

只有**静态校验通过**，并且**维护者已确认目标环境**，操作者才运行：

```text
reportctl apply --environment <维护者确认的环境> --input <同一配置文件>
```

`<维护者确认的环境>` 使用维护者确认的目标环境；`<同一配置文件>` 使用上一步通过校验的那份文件。

### 3. 记录成功结果

将成功输出中的**变更编号**记入交付记录。

### 失败处理与结果边界

原文没有定义失败后的自动重试或回滚。静态校验结果不能用来推断生产影响。
