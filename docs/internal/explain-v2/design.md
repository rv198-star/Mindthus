## Core — 本次改变什么

当前 Agent 描述信息及其关系，程序生成版面、图形和阅读交互。V2 将这种能力从 TPlan 的专用进展视图扩展到 Explain 的通用 HTML 表达。

Explain 仍是默认人向交付 Skill：方法形成判断，同一 Agent 使用 Explain 组织结果；HTML 是按需表示方式。V2 只升级 HTML 生成机制，保持 V1 的语义保真、权限与交付边界。

用户批准的是原方案整体保留，仅修订两点：吸收部分 controlled-writing lint；实际检测 Node，Node >=20 可用时优先使用，否则回退 Python。此前“避免引入 Node 路径”的建议由本决议替代；其余已给出的判断继续有效，不因未被再次点名而失效。

### 原方案完整承接

V1 = Delivery Surface；V2 = Presentation Compiler。D1 是完整 V2 的最小验证切片，不是把 V2 缩成 lint + Node 探测，也不是永久只保留四类组件。

| 原判断 | 承接方式 / 阶段 |
| --- | --- |
| 模型负责表达什么，程序负责怎么画 | Source → Explain Draft → Presentation IR → Renderer → Host Adapter；D1 核心 |
| 短 Markdown/组件稿，不让模型反复手写 HTML/CSS/SVG | D1 核心；内部 IR 由程序产生 |
| 按信息形状选组件，sheet/doc 分别服务概览与线性阅读 | D1；布局选择服务理解，不强制所有回答卡片化 |
| 七类组件：callout、flow、sequence、tree、timeline、table、progress/range | D1 先 callout/table/flow/progress-range；D2 验证后 D3 扩其余三类 |
| 确定性自动布局、共享样式/主题与必要阅读交互 | D1；节点位置、箭头、换行由程序生成，不要求复制参考项目的全部主题 |
| 同源内容适配对话内 HTML 与离线单文件 | D1；保持实际宿主适配，文件仅显式导出 |
| 源稿可恢复，支持复现与局部更新 | D1 实现，D2 做恢复/定点更新验收；不能只留一句可选描述 |
| 行号 + 组件 + 正确示例的机械诊断 | D1；定点语法修复最多两次，不引入语义 AI Review 循环 |
| Explain 默认人向交付，判断与验收仍属上游 | 沿用 V1；HTML 按需，不增加独立 Agent/model pass |
| TPlan 专用 renderer 是设计输入，不推倒重来 | D1 用现有只读视图验证；D3 逐步复用表示组件，状态/计算/验收不变 |
| 借机制，不整体集成或 fork 参考产品 | 保留；Node 优先后可按需复用预打包组件，不继承其整个产品运行体系 |
| 先最小实现，再同源 A/B，收益成立后扩展 | 沿用 D0 → D1 → D2 → D3，保真和真实交付体验优先 |
| raw HTML/SVG、HTML always-on、视频与 ask 的原边界 | 任意 markup 不进 MVP 正常路径；HTML 不全局自动；ask 保留 V2.1 候选，视频保留 V3/Companion 候选 |

上述两点修订是对完整方案的局部调整。Python 统一入口等具体工程选择属于实现方案，不把它们冒充用户逐字指定的要求；实现中仍以单一语义来源和低维护成本为准。


## Mainline — 一份内容、两条渲染路径

```text
上游结果 / TPlan 只读视图
          ↓ 当前 Agent 使用 Explain
紧凑 Markdown 稿件（按需增加组件块）
          ↓ 一次解析 + 结构检查 + 写作提示
Presentation IR（仅内部表示）
          ↓ 实际环境选择
Node renderer（优先） / Python renderer（回退）
          ↓ 共享页面资产与相同内容语义
HTML fragment / app_block payload / 显式导出的 HTML document
```

普通 Explain 文本交付继续直接进行，不为使用 lint 或 IR 而强制所有回答调用编译器。进入 HTML 编译时，解析、lint、渲染在一个入口内完成。IR 由程序产生，用户和 Agent 不必另写一份大 JSON。

### 1. 单一可移植入口

拟采用 Python 入口 `render_explanation.py`，负责读取稿件、生成 IR、写作提示、探测环境、选择后端、包装输出。Python 沿用项目已有运行基础；Node 是有则优先的附加能力，不要求用户安装两个新环境。

拟提供 `--engine auto|node|python` 供自动运行和开发验收使用；普通调用使用 auto。Node renderer 接收规范 IR，不重新解析 Markdown、不维护第二份 lint 规则。CSS、基础阅读交互、标签与主题资产共用。

Node 可复用预打包的图布局实现，D1 先以最小依赖为准；Markdown 与组件块的共同语法仍由唯一 Python 解析入口定义，不在 Node 重做解析。Python 后端实现完整 MVP 组件，使用较简单的确定性布局。两者可以像素不同，内容、节点、边、箭头方向、标签、数值、单位、限定和引用必须相同。

Python 回退仍交付可用的 HTML、图形和必要阅读交互，不把请求改成纯文本或 HTML 源码。某种布局确实无法完成时，明确报告能力缺口，保留源内容；不能丢弃信息后标记成功。

### 2. 环境选择规则

| 条件 | auto 行为 |
| --- | --- |
| 当前进程 PATH 中的 Node 可执行，版本 >=20，随包 renderer 可加载 | 使用 Node |
| Node 不存在、版本过低、版本探测失败/超时，或无法执行 | 使用 Python，记录回退原因 |
| Node renderer 资产丢失、摘要/协议版本不符 | 报安装完整性错误；不把损坏包冒充正常的无 Node 环境 |
| 稿件语法错误、未知组件或引用无效 | 返回源位置与可修正示例；不换后端掩盖错误 |
| Node 已开始渲染后出现未分类崩溃、超时或非法输出 | 报 renderer 错误；不盲目自动重跑另一后端 |
| 显式指定 node 或 python | 固定该后端；不可用时明确失败，供稳定复现 |

探测在实际执行用户和 PATH 下完成，设置短超时，使用参数数组调用子进程。只检查版本和本地入口健康，不读取密钥、用户 shell 初始化文件或其他账户目录。

不依赖“安装了 Codex，所以一定有 Node”的推断；也不自动安装/升级 Node、修改 PATH 或联网安装依赖。Node 20 是本设计的最低兼容探测线，不是自动安装该版本的建议。发布前以真实打包依赖与测试确认最低版本。

诊断至少区分 `engine_selected`、`fallback_reason`、结构错误和写作提示。探测结果可在单次进程复用；环境变化后重新探测，不建立复杂的长期状态服务。

### 3. 稿件与最小组件

保留普通 Markdown 的段落、标题、列表、表格、引用和代码表示；显式组件只用于普通表达难以呈现的信息关系。D1 冻结一个可跨后端执行的语法子集，不要求兼容参考项目的全部扩展语法。

D1 第一批为 `callout`、`table`、`flow`、`progress/range`，搭配概览式 `sheet` 与线性阅读 `doc`。标题、布局、语言等元数据只保留实际需要的字段；首屏和分组仍由具体理解目标决定，不强制 3–8 个面板。

- `callout`：结论及其重要条件；状态样式不能创造验收结论。
- `table`：已有比较维度；保留未知、部分覆盖与原始标识。
- `flow`：输入明确节点、边、方向和标签；程序只布局，不推断依赖或因果。
- `progress/range`：只呈现源值、单位、依据、覆盖范围与上下界；没有百分比时显示阶段/未知，不从任务数捏造总体完成率。

组件编号和 IR 引用是局部展示标识，不替代业务对象或证据 ID。D1 测试节点名重复、中文长标签、分支、合流、回边及含标点标签，不以删边解决排版困难。未知语法明确诊断，不默默忽略。

支持声明式折叠区、必要导航、表格窄屏滚动等阅读交互。外部提供的 HTML/SVG 当作内容转义；D1 不开放原样执行任意 markup/script 的逃生口。特殊表现先扩展受限组件，不退回模型手写整页。

## Runtime Support — 部分受控写作检查

V1 的 [expression-modes.md](../../../skills/explain/resources/expression-modes.md) 已明确采用 STE-inspired 表达纪律，且自然准确优先。V2 将可机械检查的部分实现为建议，不引入严格 ASD-STE100 合规或新的语义裁决。

### 初始吸收范围

| 规则 | 处理方式 |
| --- | --- |
| 句子/段落过长 | 给出位置与“考虑拆分”的提示；保留因果、否定和条件 |
| 明显冗余表达 | 小型白名单提示，例如“进行优化”可改“优化”；不使用宽泛正则自动删词 |
| 术语不一致 | 仅按明确提供的项目词表/任务映射提示；不凭相似度把不同概念合并 |
| 指令中的对象或数量模糊 | 只有可机械定位的明确上下文才提示核对；不补造截止时间、数量或行动人 |

阈值是开发期可调整的预警参数，不是写作合格线。D1 可以先以中文步骤 35 字/描述 45 字、英文步骤 20 词/描述 25 词、段落 6 句作为校准种子；这些来自参考实现，不主张其对 Mindthus 中英混合输出已验证最优。误报按固定语料集中归因，再决定保留、调阈值或删除规则。

### 保真边界

默认 `warn`，支持 `off`；提示不阻止 HTML 生成，不自动修改稿件，不触发强制重写或新的模型调用。语法/安全错误与写作建议分开报告。

“大约”“可能”“尚未验证”“至少”等可能承载证据强度或数量边界，保持原意，不把它们一律当作废话。“方法论”“闭环控制”等有效术语不进入全局禁用词表。主动语态、通俗用词等以 Explain 的语境判断为主，不以词表替代受众与领域判断。

代码、命令、路径、URL、标识符、逐字引文、机器字段和原始日志从可改写对象中排除。明确标记的反例仍保留原文；普通负面事实不能因为表格状态为 no 就被排除出可读性检查。

每条提示包含规则、源位置、原因和可选建议；相同根因去重。正常交付不向用户逐条播报无行动价值的 lint 噪声。当前 Agent 只采纳有收益且不改变含义的建议，允许零次修改；不为清零警告循环加工。

语法修复与上述建议不同：编译失败时允许按行定点修复，最多两次；仍失败则报告实际缺口，保留上游结果。不增加语义 AI Review/refine 流水线。

## Mainline — 沿用 V1 的交付与 TPlan 边界

### 交付表面独立于渲染引擎

Node/Python 选择不改变用户要求的表面：

- 对话内 HTML：输出一份 fragment；有真实可用宿主适配器时提交。同一视图可包装成已有 app_block 形式，不在核心实现宿主外壳。
- 文件导出：仅用户明确要求保存、下载、附件或交接时，生成完整 UTF-8 单文件 HTML。
- 两种结果都内联所需样式/脚本/图形，默认不发起外网请求；无运行服务器、CDN、远程字体或首次使用时下载依赖。

开发期可以构建并打包资产；终端用户使用时不需要 build/npm install。普通 HTML 内容生成、提交表面、实际可见可交互和文件存在分别记录；离线浏览器通过不代表对话内已验收。宿主表面缺失时保持该交付要求未完成，不用附件、截图或源码块冒充。

显式导出的页面携带可恢复的本页交付稿，供复制/提取、复现和局部修改；保存的是本页稿件，不是原始会话、隐藏推理或全部源材料。对话内不为此自动持久化文件，沿用当前稿件即可。

D1 支持按明确块标识更新已有稿件并重新渲染；未改块的稿件、限定、引用及样式选择保持不变。无法唯一定位块或缺失源稿时报告问题，不猜测覆盖。D2 验证“导出 → 恢复 → 再渲染”语义一致及“只改一个块、其余不变”。默认不建立全局页面档案或自动清理服务。

### TPlan 保持原权责

TPlan 的工作量计算、状态、依赖、证据、验收和继续授权沿用当前实现。D1 先用其固定只读视图验证通用组件，保留现有专用 renderer；不为了统一样式重写整个 TPlan。

通过 D2 后，D3 才逐步复用通用组件。迁移必须保持原首屏顺序、未验收/未知等提示、区间份额、不混单位、不重复父子统计以及标准执行报告链接。通用 flow 不能替代 TPlan 标准执行树并声称相同权威。

## Guardrails — 防止借鉴变成范围扩张

借鉴短稿、组件语法、自动布局、机械错误定位和自包含输出；不整体安装、fork 或依赖参考 Skill 的配置/更新/缓存服务。复用第三方代码时记录精确版本、来源、许可及必要 notices，并纳入构建/分发检查；当前 D0 未复制其实现代码。

HTML 不全局 always-on；视频、配音、外部动作、部署平台和在线 Agent 交互不进入 V2 MVP。

`ask` / 页面回复保留为 V2.1 候选：只展示上游已有的开放决策，收集选择/评论并形成待用户提交的回复；Explain 不创造决策，不把预选建议视为同意，不直接执行动作或修改 TPlan 状态。视频保留为 V3/Companion 候选，独立设计与验证。这里保留原判断和后续位置，不表示当前批次开发或承诺这些版本发布。

共享语义规则只维护一份。若双路径开始要求第二套大解析器、词表或业务模型，先收敛为共同子集，而不是继续扩平台。

## Runtime Support — 证据与验收口径

D1 工程测试验证可运行、保真、机械规则和打包；不证明模型更快、用户更易懂或总成本更低。

D2 将两类证据分开：固定同源稿件验证渲染内容/交互；同模型同源材料的配对运行验证实际 token、时间及理解效果。最小覆盖技术流程、比较报告、TPlan 进展三类任务；样本和指标先固定，再采集。

同一 Agent 没有第二个独立模型，不等于工具调用后没有续轮推理/上下文重读成本。记录总输入、缓存输入、输出、工具轮次、渲染耗时、读取工具结果及最终交付耗时；尤其不能忽略 HTML 回传到对话的体量。未知费用记为未测。

参考项目的轻/重上下文基准只作假设来源，不能搬成 Mindthus 的收益承诺。若 V2 输出更短却丢了重要条件，判为保真失败，而不是 token 优化成功。额外模型/渠道调用遵循届时实际授权，不因设计文档而获得调用权限。
