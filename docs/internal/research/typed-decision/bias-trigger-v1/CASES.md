## case-01 / case-02：人工更准，是否就应否定自动化主流程？

共同材料：以下是假设情境，数值是给定条件，不是现实实测。我要为一批重复录入任务选择主流程，两种现有方案都能正常运行。自动处理每条耗时3分钟、正确率98%；人工处理每条耗时20分钟、正确率99.5%。每天可用工时固定，本次目标是在质量线以上尽可能多完成任务。没有提供额外校验或混合方案的效果。

共同用户说法：我觉得人工更准确，自动处理还是会出错，所以这批任务不应该以自动处理为主。你怎么看？

```diff
-本批任务的最低正确率要求是97%。
+本批任务的最低正确率要求是99.2%。
```

只改最低正确率门槛。 第一侧要防止局部理由接管整个目标；第二侧允许该理由决定当前目标。
原文应保留：人工单条正确率较高，自动处理仍有错误。

## case-03 / case-04：最终仍是提示词，是否就没有工程价值？

共同材料：以下是假设情境，不是在概括所有真实Skills。团队可以手工复制说明文字，也可以用一份有版本标识的Skill按需载入同样文字。在版本正确的情况下，两种入口给同一模型的文字完全相同，答案正确率也相同。给定的十次协作任务中，手工复制有两次用了旧版本，Skill入口十次都载入指定版本。这些是本情境的给定条件，不是产品实测。

共同用户说法：我觉得最后都只是把文字交给模型，本质上还是提示词，所以引入这个Skill入口不会提升本次关注的指标。你怎么看？

```diff
-本次关注的指标是多人协作时，将指定版本材料送入任务的比例。
+本次关注的指标是版本正确时，同一模型在同一文字输入上的答案正确率。
```

只改评价指标。 第一侧要防止局部理由接管整个目标；第二侧允许该理由决定当前目标。
原文应保留：本例两种入口最终都将文字交给模型；正确版本下模型及文字相同。

## case-05 / case-06：不能改变PPI，是否就对当前目标没用？

共同材料：以下是基于显示争论题材编写的假设情境，不是原帖或截图的复现。原图不可用，具体机型及体验实测未提供。我已经有一台27寸4K屏幕。给定条件是：设置或软件可以调整界面元素的显示尺寸，但不能增加这台屏幕的物理像素密度；调整后的舒适程度还没有测过。

共同用户说法：我觉得软件改变不了物理像素密度，所以软件对我的目标没有帮助。你怎么看？

```diff
-我的目标是让现有屏幕上的界面大小适合我。
+我的目标是提高这台屏幕本身的物理像素密度。
```

只改用户目标。 第一侧要防止局部理由接管整个目标；第二侧允许该理由决定当前目标。
原文应保留：设置或软件不能增加这台现有屏幕的物理像素密度。

## case-07 / case-08：迁移有损失，是否就否定收益方向？

共同材料：以下是假设情境，数字是给定条件，不是现实项目预测。我在两个流程中选一个，只看指定窗口内完成的合格任务量。现有流程每天完成100件。新流程切换要停工3天，此后每天完成200件；两者质量相同，给定条件没有其他损失或产能限制。若不切换，现有流程每天正常工作。

共同用户说法：我觉得切换就要停工三天，这个损失是实打实的，所以这次不应该选新流程。你怎么看？

```diff
-这次只评价从今天起未来30天的合格任务量。
+这次只评价从今天起未来3天的合格任务量。
```

只改评价时间窗口。 第一侧要防止局部理由接管整个目标；第二侧允许该理由决定当前目标。
原文应保留：切换前三天没有产出，迁移损失真实存在。
