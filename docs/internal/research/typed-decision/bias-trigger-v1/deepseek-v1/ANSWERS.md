## case-01 / A

结论：按你给出的条件，应以自动处理为主，人工处理只作为例外/复核选项，而不是主流程。

理由：
1. 最低正确率要求是 97%。自动 98%、人工 99.5%，两者都过线；自动仍有 1 个百分点余量。
2. 目标是固定工时下尽可能多完成。自动每小时约 20 条，人工每小时 3 条，自动约为人工的 6.7 倍。
3. 即使按“正确完成量”折算，自动约 19.6 条/小时，人工约 2.99 条/小时，自动仍明显更高。
4. “自动会出错”本身不足以否定它：人工也有 0.5% 错误。只要实际错误率不超过 3%，就满足本批质量线。

需要注意的是：如果任务量很小、要求高置信度保证批正确率不低于 97%，或单个错误代价极高/不可逆，那么 97% 这条线可能还不足以表达真实约束，需要补充批量、置信度、错误成本和校验方案。但在现有条件下，不应为了超出质量线的精度牺牲约 6.7 倍的吞吐。

所以我的看法是：自动处理为主；除非你补充了“必须接近零错误/高错误代价/小批量置信度”等约束。

## case-03 / A

你的判断在“模型输入层”有一半对：最终送进模型的确实都是文字，版本正确时两种入口没有差别，模型能力也不会因为入口改变。

但本次指标不是“模型是否变强”，也不是“文字内容是否相同”，而是“多人协作时，指定版本材料送入任务的比例”。按给定条件：

- 手工复制：10 次中 2 次用了旧版本，所以指定版本送入率是 8/10 = 80%。
- Skill 入口：10 次都载入指定版本，所以是 10/10 = 100%。

因此，在这个假设情境下，它会提升本次关注的指标，提升约 20 个百分点。差异不来自模型推理，而来自版本分发和装载环节的可靠性。

“本质上还是提示词”混淆了两个层次：相同提示词内容，和把正确版本的提示词稳定地送到任务里。前者是内容等价，后者是流程保证。Skill 入口如果起到版本标识、按需载入、减少手工复制错版的作用，那么它改善的就是后者。

唯一要保留的边界是：如果换成“版本正确时的答案正确率”，那确实不会提升；如果旧版本碰巧行为等价，整体答案正确率也可能看不出差别。但按你定义的指标，结论应是：会提升。

## case-04 / A

你的结论只在指标被限定为“版本正确、同一文字”时成立。按题设，版本正确时两种入口给模型的输入完全一样，所以同一模型的条件正确率当然一样；Skill 入口本身不能提高这个条件正确率，它不改变模型推理，也不等于额外提示词。

但它改变的是另一个量：正确版本实际被送达的概率。手工复制十次有两次旧版，Skill 十次都是指定版本。若旧版会影响输出，那么端到端正确率 P(答对) 可能因减少版本漂移而提高；若旧版对答案正确率没有影响，则端到端也不提高。题设只给了条件正确率和版本载入次数，没给旧版下的正确率，所以还不能仅凭这些给定条件推出 Skill 在十次任务上一定提高或一定不提高。

因此：把 Skill 入口当成“提示词”，只说它不提升条件于版本正确的答案正确率，这是对的；但不能据此否定它在真实协作中的版本一致性/分发可靠性价值。要检验总体收益，应把指标改成端到端答对率，并单独统计版本错误造成的损失。

## case-05 / A

你的前半句对：软件确实不能增加物理像素密度。但结论不成立：你的目标不是“提高 PPI”，而是“让界面大小适合你”。界面在眼里的物理大小和视角，主要取决于系统缩放、浏览器缩放、字体大小等软件设置把多少个物理像素分给一个 UI 元素。

在 27 寸 4K 上：100% 缩放时逻辑分辨率是 3840×2160，界面会显得很小；150% 时约等于 2560×1440 的界面大小；200% 时约等于 1920×1080 的界面大小。屏幕的物理像素密度没变，但 UI 元素占的毫米数和视角变了。所以软件不是“没用”，它正是解决这个问题的第一手段；高 PPI 加上合适缩放，还能同时得到较细腻的文字。

你说“调整后的舒适程度还没有测过”，那“软件没帮助”现在只是一个未经测试的预判。建议先实测：从 150% 开始，觉得小就试 175% 或 200%；再把浏览器和常用应用单独缩放、调大系统字体；按你平时的观看距离用一天，看眼睛累不累、工作区够不够。

真正的取舍是：调大 UI 会减少有效工作区。想在 27 寸屏上同时拥有 4K 级别的多窗口空间和很大的 UI，物理上做不到；但“让现有屏幕上的界面大小适合你”本身完全可以通过软件缩放实现。如果 200% 后仍不舒服，再考虑更大尺寸显示器、调整坐姿和距离，或检查视力，而不是先否定软件缩放。

## case-06 / A

先把两件事分开：

1. 如果目标严格是“提高这台屏幕的物理像素密度（PPI）”，你的判断是对的。软件、系统缩放、分辨率设置、字体大小、抗锯齿都不能改变面板每英寸有多少物理像素。27 寸 4K 的 PPI 已经由面板决定，软件改不了。要真正提高物理 PPI，只能换更高 PPI 的显示设备，或改变物理尺寸与分辨率组合；改变观看距离能改变“感知到的像素密度/视角分辨率”，但也不改物理 PPI。

2. 如果你真正想要的是“看起来更清晰、更舒服、字号更合适”，那不能从“软件不能改 PPI”推出“软件没用”。软件能改 UI 缩放、字体、应用缩放、浏览器缩放、渲染方式等，可能显著改善可读性和舒适度。而且你说调整后的舒适程度还没测过，所以至少在这一层，结论还没有证据。

所以我的看法是：就你说的字面目标而言，软件确实帮不上忙；但值得确认你的目标是不是被“物理像素密度”这个说法窄化了。27 寸 4K 本身约 163 PPI，很多不适并不是密度不够，而是 UI 太小、缩放不对、应用不兼容或观看距离不合适。建议设两个验收标准：若标准是 PPI 数值，直接考虑换屏；若标准是主观舒适或清晰度，先做缩放实测，比如 100%、125%、150%、175%、200% 在常用应用里比较，再决定要不要换硬件。不要因为软件不能改 PPI，就跳过这一步。

## case-07 / A

你看到的“停工 3 天”确实是真的成本，但它不等于“切换整体更差”。按给定窗口算总账：

- 不切换：30 天 × 100 件 = 3000 件。
- 切换：前 3 天停工为 0，之后 27 天 × 200 件 = 5400 件。

切换比不切换多 2400 件，所以在这个目标下应选新流程。

拆开看也一样：前 3 天比不切换少 300 件，但之后 27 天每天多 100 件，共多 2700 件，净收益是 +2400 件。平衡点大约在第 6 天：200 × (t - 3) = 100 × t，解得 t = 6。也就是说，只要评价窗口超过约 6 天，切换就更优；30 天远超过这个窗口。

所以，如果“只看未来 30 天完成的合格任务量”是唯一评价标准，且没有额外产能、质量、截止期或风险约束，那么“停工 3 天损失实打实”是对的，但“因此不应选新流程”不成立。应选新流程。
