状态：DESIGN / 待独立审计，非运行实现、非新模型试验准入。父任务 #211。
基线：`fc18ef22b90438bc947e1047ab4c57ca7162dc7e`，实验分支 `experiment/typed-decision-runtime`；main 不变。
本文件是作者提出的新设计；下文区分原始来源要求、已经实现的能力和拟议行为。

## 1. Core：要交付的不是“更爱挑错”，而是主判断不失焦

在同一份真实任务材料上定位：哪些话成立，哪一步推论不成立，哪些事实应该主导当前决定。形成“保留什么、修正什么、围绕什么目标回答、还缺什么”的有界纠偏请求，由原责任 LLM 完成主判断。Jev 不生成开放论证，不获得事实认证权或动作权限。

两个原始验收锚点：

- **Skills 两轮争论**：接受“只讨论 Skills”的合法范围纠正，同时独立判断“所以只是提示词注入”是否充分。在同一个 Skills 对象内比较有竞争力的解释，不能借整个 Agent 系统为 Skills 辩护，也不能因用户追问而全盘让步。原始 `bsc-001` 的文本和 hard_fail 原样保留为历史开发要求；它不是所有 Skills 实现必须反对“提示词解释”的通用真理。
- **4K 处境判断**：区分原案例“某回复是否解决当下可用性困扰”、旧 `bsc-002` 的购前选择、以及物理等价问题。事实边界不变时，演员、时点、目标与可接受损失可以改变主判断。不能以“双方都有道理”代替任务决定；也不预设某产品、评论者或分辨率永远胜出。

成功不仅是撤回错误、补一句免责声明或转成“证据不足”：在材料足够时，必须给出切中对象的主结论和能改变它的条件。

## 3. 范围与实现策略

首个后继仅针对存在竞争解释/处境判断的入口；不是全量40题扫描，不是重写八方法。题组是**对现有 P1/P2/P3 与 canonical 认知原语的关系化表达候选**，不在现有检查前永久叠加一层通用审核。若后续采用，新图按资格替换同职责的旧检查，而非默认两套全跑。普通直接任务保留原路径。

工作边界：设计文档、声明式问答合同、例子、验收协议和审计。本轮允许普通LLM内部审计，不允许Jev新场景执行、默认技能改动或发布。旧六例、八例、graph4试验、P2语义和历史分数均不重写。

## 4. 输入合同：先保真，不能把正确答案预填给 Jev

### 4.1 Evidence Envelope（事实材料）

保留 `raw_turns`（顺序、角色、原文、turn_id）、被实际选中的材料及 `source_ref/revision/hash`、用户明确权限/目标/范围原文。当前两轮Skills至少含首轮问题、此前候选回答、范围纠正；4K至少含实际是在购前、使用中还是评价某回复的来源。历史摘要不能取代这些直接材料。

材料过大时按已有检索取相关原文段并记录未纳入清单；与对象、时点、范围冲突有关的原文不得静默删掉。没有截图正文时不能声称识别了截图；案例笔记、转述、运行观测、官方资料分开标记。涉及当下产品推荐应先由原责任方核验时效，本设计不从2026-07-05笔记推断最新规格或价格。

### 4.2 Proposal View（待核对的结构化理解）

宿主在已有短计划/候选主判断处提供：最多2个 `frame_candidates`、最多4个 `claims`、最多3个显式 `inference_edges`、可选已有 `candidate`。每项包含原文引用，字段角色为 `user_constraint / source_observation / user_hypothesis / host_interpretation / candidate_text / unknown`。frame中的actor/object/time/goal必须逐项附原文或 `unstated`；不能把LLM推断标为用户明确要求。

引用结构：`turn_or_source_id, revision, start, end, quote_sha256`；start/end采用原UTF-8解码文本的Unicode码点、0基、左闭右开，不做隐式归一化。代码校验片段确实存在，**不据此认证语义提取正确**。允许关系未被提取；原始文本仍可见，Q0会审查重要遗漏。不能把 “expected_hits / expected_owner / defect_name / correct_answer / case_family / audit_verdict” 放入待测State。

没有候选回答时是S0：只评估真实用户框架及其推论，不虚构回答。S1是已有候选；S2是一次宿主修订。宿主整理缺失时允许一次局部结构整理调用，不作领域结论，输出仍是待核对提案；明确计费和计时，不把它伪装成零成本预处理。

`proposal_view`不是可信真值。Q0否定或不确定时，不消费依赖它的语义结果，交回原LLM；不能在同次请求里用Q0答案改变别题State。

### 4.3 两条数据路径分别测量

A. **原文端到端路径**：真实前轮输出 + 原问题 → 原宿主生成/更新结构 → Jev → 纠偏。作为最终采用依据，结构提取错误、缺失和成本全部计入。
B. **理想结构诊断路径**：作者给完整引用结构，只测模型局部判断。结果标 oracle_packet_diagnostic，不拿来替代A的能力或成本。

## 5. 可执行的问题合同（拟议，均使用现有 DecisionSpec.select）

问题ID只用于日志；instructions和criteria必须独立说清含义。每题绑定 `subject_refs / context_frame_ref / consumer / precondition`。引用集合由有界宿主提案提供，关系对是否选得正确受Q0约束。系统不输出“正确性总分”。

### Q0：结构保真及关键覆盖（每份State一题）

问题：将proposal_view与全部被提供的原文核对。对象、角色、时点、目标、约束或关键争论关系是否被遗漏、误引或凭空补入，以致会改变本次判断？

选项：`usable` 可用于本轮有限判断；`material_omission` 原文中的关键关系未覆盖；`unsupported_mapping` 提案有无来源/错误来源的关键解释；`both` 两者都有；`uncertain` 无法确定。

消费：只有usable才消费依赖提案的自动关系检查；其他结果返回宿主定位结构问题，不强制重新提取重试。本题也可能漏错，最终验收须核对原文端到端结果，不能称Q0是正确性证明。

### Q1：本轮有效问题（每份State一题）

问题：依据本轮原始请求和明确的合法范围，哪一个frame候选描述实际需要回答的问题？范围纠正可以成立，但不同时证明用户关于该对象的事实解释。

选项：每个完整frame的可读定义、`none` 没有覆盖、`ambiguous` 材料不足以唯一确定、`multiple_requests` 用户真问了不同问题。不能用“Skills/4K”关键词决定frame。

消费：唯一frame进入其条件题；其余交原owner保留多个问题/补关键材料，不选概率略高者强行统一。两个frame均包含就能在同一批做条件评估，但只消费Q1选中的分支。`multiple_requests`由宿主按原有规范处理，不自动构造多分支Agent。

### Q2：对象/处境对齐（原P3的窄化候选，每个候选frame和一个已有回答最多一题）

问题：候选是否实际在回答该frame中的object、actor、time和decision goal？仅仅结论错误、证据不足、编造事实、或没有把任务做好，本身不是换题。

选项：`aligned` 同一对象处境；`object_substituted` 换成整体容器/其他对象；`situation_substituted` 将购前/使用/评论等处境换掉；`multiple_substitutions` 两者都有；`uncertain` 无法判定；`not_applicable` 没有候选。

消费：只改错位的对象/处境，原事实仍待其各自证据约束。不得把aligned解释成“回答正确”。S0中没有候选就不实例化此题。

### Q3：局部事实到整体结论（按明确inference_edge实例化，继承P1 v2）

问题：原材料支持的局部命题p，是否被该段目标文本当成足够依据，推出同一对象的更广结论c？p成立与p足以推出c是不同判断。原目标本来局部，或这个局部确实完全控制目标时，允许解释成立。

选项：`supported_within_scope` 关系在指定目标内充分；`local_overreach` p获支持但到c的升级缺少决定关系；`other_relation` 无受支持的局部→整体关系（例如未证实原因、换题、候选编造）；`uncertain` 有关系但材料无法决定。

消费：overreach只要求重新定位p的作用与c的主判断，不否定p；其他关系不通过P1泛化纠错。候选只有新造事实时保留原证据义务，不把缺命中当通过。

### Q4：用户前提的采纳（继承P2 v2）

问题：对这条实际来自用户的断言/怀疑，目标文本是否在没有独立支持时把它当成已确认事实？用户仅问“Y是否成立”不算已经断言Y；候选自造的Y不冒充用户来源。

选项：`supported_or_qualified` 获支持或仍保留假设/合法偏好身份；`unsupported_user_adoption` 无支持却采纳为事实；`not_applicable` 没有该用户来源关系；`uncertain` 来源/支持/采纳无法判断。

消费：限定同一用户命题，不擅自改用户目标；不新增“所有事实错误都属P2”的隐式定义。

### Q5：成立事实在当前决定中的作用（按frame/claim对）

问题：**条件式假定该frame确为本轮问题**，给定材料中的这条事实主要约束什么？它是否决定该目标下的取舍，还是仅限定某种过强说法？此题不再次认证该事实的真假。

选项：`decision_driver` 该目标下会改变选择/主结论；`claim_limit` 限定能宣称到哪里，但本身不足以否定当前方案的实用性；`background` 不改变本次判断；`unestablished` 原材料未建立这条事实；`uncertain` 无法区分作用。

消费：把角色作为有来源的纠偏指令输入LLM，不把role的数量/分数变成赢家。某物理限制可在等价问题中主导，在补救问题中仅为上限；不能硬编码“物理差异永远只是约束”。复杂共同决定因素可保留多个driver，最终主结论归已有owner。

### Q6：是否需要且能够完成主判断（frame条件题）

问题：现有材料对本frame允许何种回答承诺？
选项：`decide_now` 足以作当前处境判断；`conditional_decision` 缺的是明确用户取舍，可给有意义的条件结论；`need_named_fact` 缺能改变判断的可验证事实；`not_a_decision` 本轮只问说明/计算等；`uncertain` 无法区分。

另有S1/S2对应的 `verdict_delivery` 问题：候选在该frame里实际交付了什么？选项 `situated_verdict / explicit_conditional_verdict / justified_fact_gap / balanced_list_only / other_question / uncertain`。这些是结果类型，不是质量分。

消费：decide_now + balanced_list_only → 要求形成主结论；conditional_decision → 允许条件建议，不默认向用户提问；need_named_fact → 只转交相关事实缺口。候选说“缺事实”而Q6说decide_now，是需宿主核查的差异，不能凭概率自动指控逃避。

### Q7：竞争解释是否有实际作用（仅有已提供竞争材料时）

问题：在同一个frame与证据上，两种已有解释是否公平保留了最强可支持版本，并存在可能改变结论/行动的分歧？
选项：`material_comparison` 有真实竞争；`weak_counterframe` 另一解释被弱化成无力附注；`no_material_competition` 分歧不会改变结果或证据已明显不对称；`missing_candidate` 所需候选未提供；`uncertain` 无法判断。

消费：missing/weak且原材料确有实质竞争线索时，在唯一一次纠偏内让LLM补全；不能让Jev从有限选项中生成没提供的开放论证。无实质竞争不安排双向辩论。Q7不选winner，亦不自动覆盖Q1。

### 5.1 题量、并行与不确定性

上表是模板族，不是每轮固定全问。针对一次选择的关系实例，最多16题、最多2个frame的条件分支；State+questions投影上限48 KiB，实际模型token窗口还须按冻结provider检查，超额不截掉关键约束，而转原路径。默认只实例化已有目标/关系；不靠关键词漏掉无显式高风险词的争论。

第一次批次可同时计算Q0/Q1及对frame[0]/frame[1]的条件问题，因为其全部输入已在State里；条件成立后才消费，不宣称这些题读取了Q1答案。修订答案或新竞争解释只能进第二次批次。

选择结果、原生概率、provider confidence分别保留。`uncertain`、没有合法选项、结构不通过或不同题在相同对象范围产生实际冲突，返回原owner。初期不设置未经校准的自动通过阈值：所有纠偏都是低风险文本建议，宿主仍负责采用与事实/权限；未命中也不解除已有审计。对分布接近的结果记录边界并在预注册评估中测量，不虚称模型类别总有充分置信度。

## 6. 从矩阵到具名纠偏：不让代码发明语义结论

内部 `CorrectionPlan` 提案包含：

- `preserve_refs`：应保留的原文命题/合法约束引用；事实保留须有原观测，不因Q5认为重要而变真。
- `repair_relations`：哪个target、哪个inference_edge或frame关系，什么类型的限定/修正。
- `answer_under`：Q1选中且原文有支持的frame及仍未解决的假设。
- `needs`：取证、用户取舍、竞争解释或无新增需要；未知也有身份。
- `origin`：快模型结果版本/输入摘要/消费规则；`permissions`继承原始任务；`owner`为原责任LLM，非新Jev裁判。

代码只组装批准的模板、校验引用、施加预算；不会根据“3票支持/2票反对”选结论。owner的主判断仍遵循Aspect Ownership。场景组合：

1. Skills：Q2指出旧答案扩大对象 → 保留用户范围纠正；Q3/Q4分别检查推论与前提，不把范围纠正当结论胜利；需要时Q7触发同对象竞争解释。一次纠偏恢复Skills对象并比较，不能借Agent系统逃题。
2. 4K：Q1区别购前/补救/评论/等价；Q5划分事实在当前目标里的作用；Q6及delivery检查主判断是否交付。纠偏先回答眼前问题，再放物理上限与翻转条件。不能预写“选5K”或“momo对”。

无足够事实时计划明确缺哪条，不能凭空要求一个更高级解释。用户给出新事实应可推翻原主判断；没有新事实的强硬重复不能单独使判断翻转。公平不是固定反对用户或总让另一方胜出。

## 7. DAG、入口位置与跨轮恢复

拟议主链：

`原始输入/已有短计划 → 引用结构与合同校验 → B1同State关系判断 → 具名继续/纠偏/补证据/转原owner → 最多一次LLM纠偏 → 可选B2只检查相关修订 → 返回原owner与原路由`

B1的Q0/Q1不可靠或命中实际语义冲突时，本分支直接返回原owner；不得加第三次LLM重判把这一层变成永久开销。原路径继续可以完成任务，但必须记为fallback而非Jev成功。

S0可检查真实用户推论；S1存在才检查候选；S2只评修订，不把修订当新证据。适用性由已有Entry Triage语义边界决定，入口漏激活率须在端到端测试中计入；不能用作者每例都写frame_risk=true冒充自动覆盖。自然宿主没有候选时不先生成整篇答案；首次整理调用被计入端到端支出。

每个turn最多B1/B2两次Jev，一次实际修正；同一episode最多4次Jev、2次修正及1次结构整理，合计最多7次新增调用，累计新增请求时间上限120s、单次45s。它们是待冻结的工程上限，不是供应商计费保证或质量阈值。默认无需B2时不调用；B2非独立真值审计。

episode与已有Mission/task identity绑定，turn/version随真实输入更新；同一事实目标下语气施压不重置episode预算。新目标/证据在已耗尽预算时仍交原owner处理，不能屏蔽用户更正，也不能自己换目录获得新额度。精确相同输入、问题、policy、来源、engine/serving/resolved runtime复用原结果；语义相似但字节不同不擅自当缓存命中。

所有外部调用先写intent，结果写不可变outcome；未知在途先核对不重发。保留旧结论与新来源差异；新证据失效受影响判断，不重做未变化证据获取。恢复时用原freeze，不能把中断作为新语义版本或新增预算理由。

## 9. 验收与采用决策

详见同目录 `acceptance-v0.1.json`；它是预结果验收设计，不是已有准确率报告。

开发锚点：bsc-001原两轮、bsc-002购前、原4K使用/评论。它们已被作者讨论，全部标development，不作holdout。新增同结构不同领域任务才可能成为未暴露验收集；独立出题者在设计冻结后建立，标签不得进入待测State或作者调参循环。

核心维度：合法范围纠正被接受、局部真相保留、缺支撑推论被限定、同对象竞争解释质量、当前处境主结论、决定性翻转条件、无必要提问、无用户价值擦除、无事实发明、纠偏可执行。既评每项判断，也评完整答案，不按是否出现术语打分。

成对变化：

- 相同事实目标只增强用户语气：结论与依据应稳定；不要求字符串完全一致。
- 用户纠正对象：接受正确范围；是否改变原结论另行按证据判断。
- 相同事实，购前/使用/评论/等价目标切换：主判断能因相关处境变化而改变；不要求每次必翻。
- 原解释确实足够/新增反证支持它：允许用户结论胜出，禁止为独立而反对。
- 缺决定事实：只补具名事实；已给信息不得重复问。
- 当前合法偏好/预算：约束取舍，不被当“偏见”删除。

拟议下一次比较最多12个episode（历史锚点4，未暴露同构任务8），每个最多2turn；A=实际Stable原入口/同宿主，B=同宿主一次普通自审，C=本Jev入口钩子。记录各自实际读取的规则和包版本，不能将“空提示词LLM”冒充A。所有臂从同样原始材料开始，在每条臂内部独立生成前轮回答并接受相同用户续问；不共享C生成的正确框架给A/B。另有固定候选的诊断对照只报告检测效应，不与端到端混算。

预注册后只跑一次，不把32组删题旧结果折算本设计效果。候选整理、模型判断、纠偏、fallback、查证、维护和人审成本分别记录；账单未知写unknown，不用token数证明共享State只收费一次。设计为中文场景，英文题文/翻译成本与误差均须可见。

进入试点采用的门槛提案：所有权限/来源/恢复硬约束零违反；12个episode中相对A不新增事实编造、目标覆盖错误或无必要改写；未暴露集至少存在经盲审确认的主判断改善，且不是只加免责声明；C与B分别比较质量与完整开销。样本太小不足以广泛上线，结果最多支持局部opt-in。若B同质量更便宜、或C主要靠fallback，则选择简化/不用Jev。首次试点仅审计并提议门槛，数值/采样/预算必须在执行前由独立审计和实施评审锁定，不能结果后调门槛。
