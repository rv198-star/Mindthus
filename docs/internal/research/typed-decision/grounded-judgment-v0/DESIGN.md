## 要证伪的主张

少量原文定位和关系判断，能否发现原Agent遗漏的具体推导问题，并在保留正确内容的同时改善答案？
若精细提示给原Agent就能达到同样结果，或原答案已经充分，则不归功于Jev。
本设计不增加方法选择题，不默认用户错，不把抽象或复杂解释当作更好答案。

当前③的已实现合同是路由替代：router.py 的 PRIMITIVE/THESIS 主要消费为通用instruction；
第二层追加方法原文后重问同组题；没有首份答案的定点Jev复核。
这里增加的是原文关系与答案落实检查，不是修复旧合同违约。

## 输入与候选：不给Jev预先挑好的语义答案

输入为全部授权原文文档及会话顺序，保留角色、版本、时间、图片可用性、来源身份。
程序按换行和固定标点切句；句子不改写。引用格式：
`{document_id, revision, sha256, start, end, exact_text}`，start/end按Unicode码点半开区间。
每句保留前后邻句并同时提供全文，避免切掉否定、条件或引语。
用户主张、历史助手话语、可用来源、缺失图片分别标记，历史助手自述不升级为事实。

定位选项由全部编号句自动生成，加 none / ambiguous；每个位置均可被选，不按关键词筛“可疑句”。
目标与对象可选择同一句，不能为凑槽位发明实体。每句可有相邻两句的机械连续窗口候选；
同一原文多个角色不视为错误。首版限定短窗口：候选连同特殊项≤255；超限就记该原型不覆盖，
不截掉不利上下文、不引入前置LLM摘要。完整F历史可能超限，必须在未来实现前计数；
若超限，可另用明确标记的开发摘录，不能宣称覆盖完整历史窗口。

Jev只选这些原文位置和固定关系类型；程序检查ID、范围、版本、原文逐字匹配、选项成员及依赖。
这证明引用存在，不证明语义正确。语义定位错误单独计分。
运行时不得由前置LLM提名命题、写摘要或生成候选解释；设计期通用模板与公开开发例允许人工编写。
针对未来未见文本不临时手写“正确候选”。

## 紧凑题组与类型分工

前置仍为三轮。题目从10项明确为13项：增加ER、T依据TB，并把含糊的I拆为I_T/I_R；
不增加关系数量、发现上限或前置轮数。Choice选位置/关系，Noul判断具名命题，Score只评条件影响。
它们不重复投票；Score不决定发现真假，失败不清除已成立发现。

| ID / 类型 | 题面及答案空间 | 消费 |
|---|---|---|
| G / Choice | 当前仍有效的用户目标或成功条件主要由哪一窗口表达？全部编号窗口/none/ambiguous。不得换成助手希望用户追求的目标。 | 目标引用。 |
| O / Choice | 当前主请求要求判断的对象或命题由哪一窗口表达？同上，不自动选择最大的对象。 | 对象引用。 |
| C / Choice | 全文当前主请求中，哪一明确结论最值得核对其依据？同上，允许没有；不引用本轮尚未返回的G/O。 | 待核对结论，不预判错误。 |
| P / Choice | 哪一原文前提被用来支持已选C？全部窗口/none/ambiguous；不替作者补强。 | 一条前提。 |
| E / Choice | 围绕已选C，哪一窗口提供最直接相关的候选支撑或反证材料？全部窗口/none/ambiguous；不引用同轮P，不预判它支持P。 | 候选材料引用。 |
| ES / Choice | 已选E的来源身份是什么？给定案例条件/可直接核对的原始材料/来源转述/未经验证的现实主张/缺失/不能定位。 | 来源身份及事实口吻；直接材料不自动支持P。 |
| ER / Choice | 在所给条件下，E与已选P的语义关系是什么？支持/反证/无关/不能判定。 | 证据关系，不能由ES推导。 |
| R / Choice | 给定范围和条件下P→C是什么关系？充分支持（含同义、机制解释或其他有效推导）/部分支持但C扩大范围/矛盾/无关/证据或条件不足无法判断。 | 与S共同消费，允许正常推导retain。 |
| T / Noul | “按已选G的成功条件评价O时，C回答了该目标，而不是另换目标。”true支持此命题；false不支持此命题，单独不等于确认错位。 | 配合TB区分否定与未知。 |
| TB / Choice | G/O/C对目标匹配判断提供什么依据？明确匹配/明确不同目标（指出G与C中的冲突原文窗口）/信息不足/无法定位。明确不同须使用已编号原文；不能只给标签。 | 目标错位的依据门；原文位置复用G/C或其机械子窗口。 |
| S / Noul | “在明确给定的条件和范围内，P足以支持C完整强度，不需另加未证前提。”true支持充分性；false不支持，不等于P为假。 | 推导充分性；不认证现实事实。 |
| I_T / Score | 假设C确实替换了G的目标，不纠正这个目标错位对回答有多大影响？0无实质影响/1措辞限定/2改变建议或主要结论。 | 只在目标错位发现成立后排序。 |
| I_R / Score | 假设P不足以支持C且需限定或重查，不处理这条推导对回答有多大影响？同一0/1/2量表。 | 只在推导问题发现成立后排序。 |

TB的Choice选项可以用机械构造的 `different_G_C` 表示已有G/C窗口对，不要求Jev另生成解释；
若冲突无法在这对原文内指出则选择信息不足/无法定位。程序验证引用，不验证冲突语义。

| 轮次 | 可用输入 | 返回字段 | 消费时机 |
|---|---|---|---|
| 1 定位 | 全量编号原文、来源元数据、当前主请求；无模型预提名 | G/O/C | 返回后校验引用与主请求一致性；不把独立选择视为自动一致。 |
| 2 候选支撑 | 原文及已返回G/O/C；无本轮P/E | P/E，均只针对已选C | 返回后校验引用；E关联P尚未成立。C无有效位置则跳过依赖题并登记原因。 |
| 3 关系 | 原文、有效G/O/C/P/E及缺项；无本轮R/T/S | ES/ER/R/T/TB/S/I_T/I_R | 返回并适配后才组合发现；I是预定义假设的条件值，不读取同轮发现。 |
| 首稿检查（非前置） | 已组合发现、原文、已存在首稿 | 定位/落实原子结果 | 返回后才决定一次修订；不反向补写前置记录。 |

E为none时ES=缺失、ER=不能判定；不额外发问求齐。若P是明确给定的案例条件，R/S仍可进行
条件推导，结果标记 `conditional_on_given`；没有独立E不阻断此分析。对现实P未获验证则标记
`premise_unverified`，只能说“若P成立则……”，不能将条件内充分支持转换成外部事实认证。
元数据与ES冲突（例如缺图却选直接核对）时隔离该项，记合同/来源冲突。
所有三轮和13项成本如实计量，不假装一次请求。

首版只处理一条关系，最多产出两项发现（目标错位、推导越界）。其他争议保留为覆盖限制，
不让模型额外提名更多关系、不构造全句对矩阵。多命题完整覆盖不是本原型目标。

## 明确组合规则

### 共用组合器入口，适配器分别负责来源

共用记录：`question_id, refs, value, semantic_state, unresolved_reason, basis_refs,
provenance, raw_result_ref`。位置/关系value使用上表枚举；命题semantic_state为
`support / deny / unresolved`；无位置为 `unlocated`，合同错误为 `invalid`，均不得当deny。
T的deny还须TB=明确不同目标且G/C有效一致，才能成为有依据否定。
这里的unresolved是消费状态，不直接决定计分。规范要求的证据不足、条件未定或目标未明确，
在原文依据与原因正确时可以是成功的原子判断；低置信度、定位失败或合同错误导致的未完成判断则不能。
用现有value、semantic_state、unresolved_reason、basis_refs对照独立规范表区分，
不修改适配器或组合规则；详细分母及条件反转口径见 [验收定义](ACCEPTANCE.md#失败分层)。

- C/Jev适配：暂定Noul≥0.8→support、≤0.2→deny，中间unresolved；Choice合同有效且所选
  概率≥0.8才消费，否则unresolved。保留供应商原始概率及来源；数值门槛不是准确率保证。
  低T加TB信息不足仍是未决，不会因低概率自动形成目标错误。
- B/Agent适配：要求直接输出支持/有依据否定/未决及原文依据，关系取同一枚举；没有原生概率，
  `probability=null, provenance=agent_categorical`。不要求自报置信度，不套Jev数值门槛。
  缺失依据、弃权或无法定位映射为对应未决；程序不能把结构有效当语义正确。
- 两臂均保存缺项、弃权、引用失败、覆盖差异。相同的是组合器输入语义与发现模板，不是宣称
  两类判断概率等价。阈值仅属于新设计的Jev适配，不触碰旧EFFORT合同或旧阈值。
- I_T/I_R：Jev保留等级概率加权值；B给同量表的0/1/2条件评级，来源标记为Agent等级判断，
  不伪装概率。两者只在对应发现成立后按值排序；未知则固定目标发现在前，平分同样处理。
  不用影响分判真假或跨臂比较“置信度”。

### 最小消费表

以下“发现成立”仅表示该组合满足输出条件，仍可被独立审阅判错，不是事实认证。

| R与S（引用有效） | 输出 | 保留与限制 |
|---|---|---|
| 给定条件下充分支持 + S support | retain该推导 | 同义、机制解释和其他充分推导一视同仁；标明假设/现实证据上限。 |
| 范围越界 + S deny | limit，推导问题成立 | 保留P在给定范围的成立部分，限制C外推。 |
| 矛盾 + S deny | recheck，推导问题成立 | 并列P/C；不给证据不足的一方自动判真。 |
| 证据/条件不足，或S unresolved，或R/S冲突 | unresolved，可请求检查 | 不计为已发现错误，不自动否定P/C；可答有依据部分。 |
| 无关 | unsupported_relation，可请求检查 | 不确认为越界；保留定位/关联遗漏，不能把选错P当C已错。 |

目标维度另行消费：T deny + TB明确不同目标 + 有效G/O/C冲突依据 → reanchor；
T低值但TB信息不足 → `unresolved: insufficient_basis`；G/O/C无有效位置或TB无法定位 →
`unresolved: unlocated`。后两者可给带引用的检查请求，不能统计为已确认目标错位。
T support + TB明确匹配保留目标；其他互相冲突组合保持未决。

没有有效发现时宿主正常回答。未决检查请求作为限制说明提供给首稿，不单独触发额外模型检查或修订。
方法未决不阻断整题。ER反证P且P是现实主张时，只允许带冲突说明的条件推导；
ES身份本身不决定支持/反证。目标发现与推导发现最多各一项，按各自条件I排序；同一原文
产生互相矛盾的动作时登记组合冲突，不发冲突指令。充分的局部推导可保留，同时纠正它被用于不同目标的问题。

发现载荷是程序填入原文的固定模板：
`finding_id, goal_ref, object_ref, premise_ref, claim_ref, evidence_ref/origin/relation,
relation, keep_exact_text, limit_target_exact_text, action, uncertainty, source_question_ids`。
例如limit的纠偏要求为“保留P在原范围成立的部分；回答G时不要仅凭P断言C；说明还缺什么关系证据”。
不用Jev编造长解释，也不只输出“注意定框”。宿主负责自然语言结论，可以提出带原文依据的异议。

## 消费示例：设计预期，不是实际模型返回

开发材料参考旧 cases.json 的 E-window，以及 F-window 历史 m9/m12/source-limit。
下列为人工缩短的开发反例，不能替换封存原题，也不作为未见验收样本。

**Skills：只改变给定案例条件，S2/S3逐字不变。**

共同文本：S2“请判断这个Skill是否可以完整地视为模块化提示词。”
S3“这个Skill可以完整地视为模块化提示词。” G/O=S2，C=S3，P=S1。
两版本仅S1变化；它是人为给定条件，不是已核验现实实现；独立E可为none。

```diff
-S1：这个Skill的组成是按时注入的文字。
+S1：这个Skill的组成是按时注入的文字与独立执行的结果校验程序。
```

应改变：R/S由充分支持/support变为范围越界/deny，action由retain变为limit；待检验主张S3不加强措辞。
不应改变：文字注入的组成价值、G/O、T目标匹配、案例条件的来源身份；后者不能被描述为现实验证。
消费：“保留S1中的文字注入部分；在含独立校验程序的条件下，限定S3的完整性主张。”
这不是实际E-window新评分；真实E缺实现证据时应条件化讨论。

**4K：只改变目标，物理前提和待检验主张逐字不变。**

共同文本：F2“给定条件：软件不能增加这台屏幕的物理像素密度。”
F3“仅据F2，就能断定软件不能满足F1所述目标。”
F4“这是开发用假设情境；原图不可用，不声称核验过现实体验。” G/O=F1，P=F2，C=F3。

```diff
-F1：我的目标是用软件让这台4K屏幕的界面大小适合我。
+F1：我的目标是用软件让这台4K屏幕的物理像素密度达到同尺寸5K屏幕水平。
```

应改变：P→C由条件不足/未决变为给定条件下充分支持/support；前者不能判软件必然满足或不能满足目标，
后者可retain“在给定条件下不能满足”。不应改变：F2局部物理前提、F3原字面、目标确由F1提供、
T匹配（两版C都谈当前目标）、F4证据限制。不能制造买前/买后故事或宣称调优实测成功。
第一版消费为检查请求：“F2只排除增加像素密度，尚未说明界面大小可调性”，不是已确认目标错位。

以上diff中的其他句子均保持逐字一致；两组都只是公开dev，不计入未来8例holdout。

## 首稿检查：有界，不能反复追分

宿主首稿只消费原文与有效发现；不带预期答案或评审标签。原文发现最多2项。
首稿存在后机械编号其所有句子；检查轮每项一个Choice定位“与该发现相关的首稿句/none”，
一个Noul判断“这份首稿是否落实指定keep/action且没有把证据上限升级”。同State含全文，
定位与落实若不一致记未决。最多4题、1次Jev批调用；没有有效发现则不调用检查。
检查未落实才允许原宿主一次定点修订；修订后不再Jev复查、不生成第三份。
全部保留首稿、检查、修订及异议，独立验收同时看首稿与最终稿，不择优交付。
当前设计上限：前置3次Jev + 检查1次Jev；宿主首稿1次 + 修订最多1次。
这些额外轮次、冷却和费用必须全计入；本轮没有执行授权。
