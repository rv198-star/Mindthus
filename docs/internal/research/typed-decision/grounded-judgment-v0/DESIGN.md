# 原文绑定的定点判断：设计草案 v0

状态：DESIGN ONLY；2026-09-28。父结论提交：`5b1e5db8864e6119e5eecc531be6781a62c681d0`。
只提出新能力合同，不修改③冻结实现、不授权模型批次、不继承旧实验资格。
旧六案、四项R2 CLOSED和默认采用 NOT QUALIFIED 不变。
依据：Owner本轮设计方向；[类型化裁决原则](../../../methodologies/typed-decision-principles.md)。

## 要证伪的主张

少量原文定位和关系判断，能否发现原Agent遗漏的具体推导问题，并在保留正确内容的同时改善答案？
若精细提示给原Agent就能达到同样结果，或原答案已经充分，则不归功于Jev。
本设计不增加方法选择题，不默认用户错，不把抽象或复杂解释当作更好答案。

当前③的已实现合同是路由替代：router.py 的 PRIMITIVE/THESIS 主要消费为通用instruction；
第二层追加方法原文后重问同组题；没有首份答案的定点Jev复核。
这里增加的是原文关系与答案落实检查，不是修复旧合同违约。

## 输入与候选：不给Jev预先挑好的语义答案

输入为全部授权原文文档及会话顺序，保留角色、版本、时间、图片可用性、来源身份。
程序按换行和固定标点切句；句子不改写。引用格式：
`{document_id, revision, sha256, start, end, exact_text}`，start/end按Unicode码点半开区间。
每句保留前后邻句并同时提供全文，避免切掉否定、条件或引语。
用户主张、历史助手话语、可用来源、缺失图片分别标记，历史助手自述不升级为事实。

定位选项由全部编号句自动生成，加 none / ambiguous；每个位置均可被选，不按关键词筛“可疑句”。
目标与对象可选择同一句，不能为凑槽位发明实体。每句可有相邻两句的机械连续窗口候选；
同一原文多个角色不视为错误。首版限定短窗口：候选连同特殊项≤255；超限就记该原型不覆盖，
不截掉不利上下文、不引入前置LLM摘要。完整F历史可能超限，必须在未来实现前计数；
若超限，可另用明确标记的开发摘录，不能宣称覆盖完整历史窗口。

Jev只选这些原文位置和固定关系类型；程序检查ID、范围、版本、原文逐字匹配、选项成员及依赖。
这证明引用存在，不证明语义正确。语义定位错误单独计分。
运行时不得由前置LLM提名命题、写摘要或生成候选解释；设计期通用模板与公开开发例允许人工编写。
针对未来未见文本不临时手写“正确候选”。

## 紧凑题组与类型分工

按真实依赖分三小轮：G/O/C三个Choice；绑定C后P/E两个Choice；绑定P/E后五项关系判断。
Choice选位置/关系，Noul评估一个具名命题，Score只决定有多个已确认发现时的修订优先级。
它们不是三次投票；低Score不推翻事实关系，Score失败不清除已确认发现。

| ID / 类型 | 完整问题意图与选项 | 消费 |
|---|---|---|
| G / Choice | 当前仍有效的用户目标或成功条件主要由哪一原文窗口表达？选全部编号窗口/none/ambiguous；不是选助手认为用户应追求的目标。 | 目标引用；不得推断买前/买后。 |
| O / Choice | 当前请求要求判断的对象或命题由哪一窗口表达？同上；不是自动选最大的全局对象。 | 对象引用。 |
| C / Choice | 哪一明确结论最直接影响G对O的判断，值得核对其依据？同上；允许没有需要核对的结论。 | 待核对结论，不预判错误。 |
| P / Choice | 原文中哪一前提被用来支持C？选全部窗口/none/ambiguous；仅选择实际声称的推导，不替作者补强。 | 一条具名前提。C为none时跳过。 |
| E / Choice | 哪一可见窗口提供独立于P重复断言的证据？选全部窗口/none/ambiguous。 | 证据引用；没有证据不等于P为假。 |
| ES / Choice | 就P而言，E是什么证据状态？直接可核对材料/来源转述/主张或例子/冲突材料/缺失/不能判定。 | 限定事实口吻；元数据已明确图片缺失时不能选直接核对。 |
| R / Choice | P与C在原文中的关系是什么？同义或机制解释/部分支持但结论扩大范围/与结论矛盾/不相关/材料不足无法判断。比较对象、量词、条件和时点；简单解释可以充分。 | 明确保留或限定哪条推导。 |
| T / Noul | “按G的实际成功条件评价O时，C回答了当前目标，而不是换成另一个目标。”true支持此命题；false不支持此命题，不表示C事实为假。 | 目标错位发现。G/O/C有效才激活。 |
| S / Noul | “在原文给出的条件和范围内，P足以支持C的完整强度，无需添加未证前提。”true支持充分性；false不支持充分性，不等于P错误。 | 控制结论是否可原样保留。P/C有效才激活。 |
| I / Score | 已确认的此项问题若不处理，对回答G的影响多大？0无实质影响，1措辞/限定，2改变建议或主要结论。不是置信度、不是语义真伪。 | 最多两项发现的排序；只有发现存在才消费。 |

同一请求题目不能引用本次尚未返回的选择。G/O/C各自针对全文的当前主请求定位，
三者不一致则相关分支未决；P/E第二轮明确引用已经选定的C。E选择可见的直接支撑材料，
第三轮ES再判断其是否真正支持P，不能由程序把候选关联写成已证实关系。
三轮是真实依赖开销，不把10题批量接口假装成一次请求；若成本已超过价值，可以否定这条设计。

首版只处理一条关系，最多产出两项发现（目标错位、推导越界）。其他争议保留为覆盖限制，
不让模型额外提名更多关系、不构造全句对矩阵。多命题完整覆盖不是本原型目标。

## 明确组合规则

新草案消费阈值建议：Noul≥0.8为支持，≤0.2为不支持，中间为未决；Choice须合同有效且
所选概率≥0.8才消费，否则未决。它们是待冻结设计参数，不是已校准准确率，绝不修改旧阈值。
Score保持等级概率加权值，不取整冒充离散等级，不以精度容差修补错误返回。

1. 引用无效或供应商合同错误：隔离该项；无引用不生成纠偏指令，保留错误及原回答路径。
2. G/O/C有效、T不支持：发出 `reanchor`，指定G/O/C原文，要求按G重新判断；不自动反转C真假。
3. P/C有效、R为范围扩大、S不支持：发出 `limit`，保留P在原范围内的成立部分，禁止仅凭P断言完整C。
4. R为矛盾、S不支持：发出 `recheck`，并列冲突位置；证据不足时不指定哪句一定为真。
5. R为同义/机制解释、S支持且T支持：发出 `retain`；简单说明足够，不再造“更深层”反驳。
6. R与S不相容、引用关系含糊或任何前提缺失：该关系 `unresolved`；给出可支持部分和限制，
   不自动阻断整个任务，不把方法未决当作事实缺失，不根据Jev判断授予权限。
7. ES仅为转述/主张/缺失时，明确证据上限。可以评价“此推导不成立”，不能宣称已验证外部事实。
8. 两项发现按G优先、再处理P→C；I仅排序。同一原文同时要求保留与删除则作为组合冲突，
   不发互相矛盾的强制指令。无有效发现时宿主正常回答。

发现载荷是程序填入原文的固定模板：
`finding_id, goal_ref, object_ref, premise_ref, claim_ref, evidence_ref/status,
relation, keep_exact_text, limit_target_exact_text, action, uncertainty, source_question_ids`。
例如limit的纠偏要求为“保留P在原范围成立的部分；回答G时不要仅凭P断言C；说明还缺什么关系证据”。
不用Jev编造长解释，也不只输出“注意定框”。宿主负责自然语言结论，可以提出带原文依据的异议。

## 消费示例：设计预期，不是实际模型返回

开发材料参考旧 cases.json 的 E-window，以及 F-window 历史 m9/m12/source-limit。
下列为人工缩短的开发反例，不能替换封存原题，也不作为未见验收样本。

**Skills：简单解释可成立。**
S1“这里的Skill只有一段按时注入的文字，没有工具或验证步骤。”
S2“就这个Skill而言，它是模块化提示词。” G/O在S2；P=S1，C=S2，E=S1（给定案例条件）。
期望R=机制解释、S支持、T支持，action=retain；不得强加工具编排以反对用户。
条件反转只把S1换成“这里的Skill还规定工具执行、失败停止和结果验证”，并令S2为
“这些工程价值全都只在提示词措辞”。期望限定S2的“全都只”，保留文字注入的重要性；
不能把有验证规则说成已执行验证。真实E-window没有完整实现证据，应条件化区分定义口径，
不是直接宣判用户错。若定位只抓用户首句而漏掉“所以”的推导，记定位/覆盖失败。

**4K：物理上限不自动否定调优价值。**
F1“我已经有这台4K，只想把界面调到可用，不要求达到5K锐度。”
F2“软件不能增加物理像素密度。” F3“因此调缩放没有价值。”
F4“原图缺失，争论内容仅为转述。” G/O=F1，P=F2，C=F3，E=none/转述限制。
预期keep=F2，limit=F3，理由为P不能独自排除G中的可用性收益；不能断言某设置实际流畅或已解决全部担忧。
条件反转：只把F1目标改为“我只接受软件使物理像素密度达到5K”，F3改为
“因此软件不能满足这个目标”。此时充分性应支持，不得为了纠偏继续强调调优收益。
另设目标未给出版本：期望目标ambiguous，而不是沿用历史助手的买前/买后故事。

## 首稿检查：有界，不能反复追分

宿主首稿只消费原文与有效发现；不带预期答案或评审标签。原文发现最多2项。
首稿存在后机械编号其所有句子；检查轮每项一个Choice定位“与该发现相关的首稿句/none”，
一个Noul判断“这份首稿是否落实指定keep/action且没有把证据上限升级”。同State含全文，
定位与落实若不一致记未决。最多4题、1次Jev批调用；没有有效发现则不调用检查。
检查未落实才允许原宿主一次定点修订；修订后不再Jev复查、不生成第三份。
全部保留首稿、检查、修订及异议，独立验收同时看首稿与最终稿，不择优交付。
当前设计上限：前置3次Jev + 检查1次Jev；宿主首稿1次 + 修订最多1次。
这些额外轮次、冷却和费用必须全计入；本轮没有执行授权。
