独立初审结论：C01 的基本分层及 C02 的局部实验范围可以保留；尚不能据此认定完整 Decision Contract 合格。主要疑点集中在 C02 上游判断的实际用途、重检语义，以及 C01 义务处理与完整方法执行之间的边界。我未读取标签、模型结果或停止结论；这是同类模型独立上下文评审。

**可保留项**

- **C01 入口判断与义务判断不必然冗余。** 前者选择处理方式，后者保留不能因路由消失的约束。C01-R22 把字段校验升级为任务验收，应被义务拦住；C01-R12 只报告实际观察，不能继续拦截。C01-R08 与 R21 同为第三次修补，但新证据及确定补丁改变处理方式；这对比说明不能按词语或次数机械判定。
- **C01 同 State 两问合批合理；owner→读取对应方法→applicable 是真实依赖。** 新 owner 改变方法文件及判定前提。R16 与 R19 能区分“明确调用”与“适用”：请求 WAE 不会使资源分配问题符合 WAE。
- **C01-R26 路由 TVG 有 canonical 支持。** 它要求修复既有段落的实际可执行性，提供独立规范，但未规定最终改写。TVG `When To Use` 明确覆盖 downstream use、action、handoff strengthening。R14 的确定术语替换则适合直接执行。2.1 修订是在澄清已有边界，不能仅因其改变 R26 答案就认定过拟合；不过“一切非机械编辑都进 TVG”仍不成立。
- **C02 utility 与 support 有独立含义。** R06 是成品缺失而来源具备规则；R05 是来源本身没有规则；R01 要求不存在的测量。把来源充分性单独保留有真实下游作用。
- **C02 没有直接僭越 TVG 最终退出权。** `c02.py:77–82, 177–181` 保留 original-tvg-agent、`exit_state=None`。局部判断没有变成 freeze。不能把实验简化直接认定为篡改完整 TVG。

**关键缺陷与尚待判定的问题**

1. **C02 没有充分说明 utility→action 为何需要顺序调用。**

   `c02.py:93–103` 中，utility 的 outside_scope/conflict/unclear 有明确门控用途；adequate 与 deficit 都进入同一 action 选择。传入 `weaknesses` 的只是两个标签，没有指出缺失哪条行为、哪项理由或哪个限制；action 仍读完整原 State，重新判定改不改、改什么。

   因而不能说 utility 完全无用，也不能仅凭多传一个模型标签称其为“真实语义依赖”。当前证据支持**门控依赖**，尚未支持**动作选择必须后置**。同 State 投机合批 action、最终由 runtime 决定是否消费，也是规范允许的设计。

   辨识案例：R02/R08（足够）、R06/R07（不同缺陷）、R03/R09（已有必要内容但含重复）。应检查上游 adequate 与后续 rewrite 矛盾时如何处理；当前代码没有显式冲突策略。

2. **C02 support 重检并未检查新成品是否受到来源支持。**

   `c02-local-contract.json:15–20` 问的是“已有证据能否满足目标”。即便重写擅自加入成功率、删除禁止覆盖预约的限制，来源对目标仍可能是 sufficient。`c02.py:174` 以“都读 artifact”为由认定两个问题都受重写影响，混淆字段访问与语义依赖。

   重检 support 可以保留作防御性检查，但不能称为新成品的事实忠实性审计。真正需要的是“成品中的实质主张/限制是否与来源和 veto 一致”，或者明确把这项完整交给原退出 owner。R02、R08 是适合制作受控变体的母例：只改成品、保持来源及目标不变，能直接区分两种问题。

3. **C02 utility 有整体化趋势，但不能据此要求机械拆成三个 TVG 分数。**

   `c02-local-contract.json:5–12` 将实际用途、缺陷、作用域、目标冲突压成单选。作为“一段文本下一步是否可在此处理”的路由合同，可以成立；作为“局部弱项诊断”，它没有留下哪一轴不足。完整 TVG 要区分 Thickness、Grounded Insight Yield、Density，并先满足 thickness 再压缩；这里主要依赖 action 选项中的文字约束落实。

   R03/R09 尤其重要：重复存在不等于已经实质妨碍用途，合同写的是“obscures an important limit / obstructs use”，而样例中的禁止覆盖等限制仍相当清晰。**compact_preserve 与 leave_unchanged 都有可辩护空间**，不能先认定唯一 gold。需要独立标准界定“有意义的读者负担”，不能把简短漂亮当价值增益。

4. **C01 known_obligations 的“已知”与“未解决”语义未闭合。**

   `c01-semantic-r1.py:87–88, 153–154` 对任何非空 known_obligations 无条件 fallback，即使模型判断 clear。若此字段只允许“尚未解决义务”，该行为合理，但需要字段合同明确；若可包含持续有效、已经满足的限制，代码过度拦截。

   R22 只能证明未解决义务应保留。R12 没有带旧义务，不能证明系统能识别其已解决。应增加“R12 语义不变，但保留已满足的证据边界义务”的案例，区分字段约束与运行时缺陷。

5. **C01 保留的是路由，不是完整方法保真。**

   `read_sources` 读取完整入口 SKILL，owner 后读取所选 SKILL，优于复制关键词表。但入口还引用条件性 primitives；MPG/SELA 有伴随读取及主从关系要求。当前只返回单一 owner，未证明这些义务完整传给下一执行者。

   R06 对 R20 可检验方向与路径的主 owner；却不能检验 R20 后续是否保留 SELA support。若仅宣称“建议下一主 owner”，可接受；若宣称完成 canonical 介入或完整执行，就超出证据。

**优先区分的实验问题**

- 原合同是否含糊、引擎是否误解、runtime 是否错误消费结果，应分开评价。
- C02 顺序调用 action 对比同 State 合批 action：看动作正确率、冲突率、调用成本，而非仅看 DAG 长相。
- 给 action 正确、错误、缺省的上游标签，观察它是在合理使用诊断，还是被标签锚定。
- R26/R14 加普通写作及轻微语气改写邻近例，检验 C01 修订是否扩大 TVG 过度介入。
- R03/R09 先允许多种合理动作，再以实际读者用途评价；不以作者偏好的压缩动作当唯一真值。
- 成品注入无来源断言或删掉重要限制，检验重检与最终 owner 谁真正承担忠实性责任。
- R18 检验高后果执行范围，R03 检验过期资料；均不能以 fallback 成功推导完整语义能力。

**允许与不允许的修订范围**

允许：补足 known_obligations 字段语义；明确上游结果的消费和矛盾策略；收窄或重命名 support 重检；提出独立版本的动作合批实验；澄清 C01 普通编辑与用途缺陷的边界；保留“仅主 owner 建议、完整执行待原 agent”声明。

不允许：为了匹配现有输出修改 canonical；把已有样例措辞植入通用路由；将来源 sufficient 改写成成品正确的证明；用局部 adequate 宣告整体 TVG freeze；结果揭晓后悄悄重定义 gold、修订额度或通过标准。若需要新成品忠实性问题，这是合同语义变更，应另立版本，不能当无关紧要的措辞修复。
