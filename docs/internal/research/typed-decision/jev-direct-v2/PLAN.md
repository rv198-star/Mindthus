## Architecture and source boundary

The offline, versioned routing_cards.json is a declared curated projection, not lossless full text. All ten skill entries are represented; eight methodology owners are routable, using-mindthus is reference-only, case-prep is explicit-only and delegated to an authorized host outside this text-only pilot. Core, applicability, exclusion, neighbor boundaries, output and composition are derived from pinned SKILL + methodology sources. Source hashes are checked before routing. Cognitive cards retain framing, whole-object, situated-goal, anti-spiral, evidence-based root replacement and aspect ownership.

Layer 1 sees exact user/source documents with conversation order and authority plus ALL cards and cognitive descriptions. No LLM organizer, candidate nomination, task-specific summarization or supplied route enters its State. Noul assesses applicability, required detail and cognitive obligations; Choice sets handling/roles/scopes/relations; Score describes intervention depth, never an authorization or numerical optimizer. Pair relations are speculative and consumed only when both methods are selected.

One optional layer 2 is activated by Jev's detail-need observations. At most two topics are read in original SKILL + public methodology form, ordered by observed detail need. Deferred topics are explicitly recorded, not called read. All cards, cognitive descriptions and original input remain visible. Layer 2 re-evaluates the whole catalog; a weak first-layer method is not permanently pruned. Detail-capacity overflow is explicit, never truncation. No third routing call. Initial State ceiling 60,000 UTF-8 bytes respects the existing shared 64KiB projection guard; request ceiling 240,000 bytes respects the existing transport. These are local byte bounds, not claimed token counts. Official Jev is pinned to jev-1.13.0.

The downstream current Codex gets original input, actual selected SKILL/methodology contents, roles, source scopes, conditional dependencies and active cognitive obligations; not the using-mindthus entry or all routing cards. It begins execution, not candidate selection. A material routing objection is explicit and remains a degraded result; no silent method substitution. No named method is not a prohibition on answering. Genuine permissions, evidence and required prerequisites remain binding. Sequential dispatch denotes within-answer order, not independent multi-job artifact acceptance or external runtime mutation.

Selection constants are provisional low-risk development policy, frozen before outcomes: role winner probability >=0.50; primitive/conditional companion Noul >=0.60; detail Noul >=0.55; at most two extra topics. Applicability and depth remain observations, not a second answer gate. No after-results tuning. An MPG trend/system-efficiency mainline requires the explicit source-derived SELA support observation and actual loading, not an unconditional keyword rule.

## Endpoints

Primary: delivered user task quality, original fact/constraint fidelity, material reasoning defects, unnecessary non-delivery. Secondary: pre-route LLM count, actual loaded methods, primitive obligations, layer2 frequency, deferral/fallback, all provider/host calls, reported input/output/cache tokens and request time, full arm wall time. Call time is not wall time; token counts are not settled dollar bills. Route confidence and method labels do not count as quality.

E/F use existing dimension definitions. A checks correct order/format; B distinguishes shape from factual evidence and offers grounded minimal validation; C preserves direction while testing feasible exposure/carrier and exit/appeal floors; D derives feasible hybrid structure before allocating six person-days, preserves appeals, and defers nonessential cosmetics. Equivalent sufficient routes tie. There is no requirement that Jev win. If quality is equivalent without measured net reduction, no adoption claim; isolated benefits justify only bounded follow-up, not default release.

No change to main or default Skill. Preserve the source manifest, question and policy versions, actual prompts/reads/replies and complete evidence tree. Engineering PASS, live path delivery and semantic comparative conclusions remain separate.
