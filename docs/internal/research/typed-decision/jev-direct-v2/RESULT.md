用户原始请求与证据 → 全方法精简路由说明/认知约束 → Jev首轮同State多维判断 → 必要时最多一轮具名原文细读 → 程序加载目标方法/范围/主辅依赖及认知约束 → 当前Agent执行。

- 运行前LLM候选整理/摘要调用为零；不存在先由LLM筛几个方法的步骤。
- 第一层看到10份技能条目说明（8可路由、using-mindthus参考、case-prep显式专用）和6个认知原语，保留完整原始用户材料、顺序和权限。精简说明明确是设计阶段的语义投影，绑定24个正式源文件，不冒称全文无损等价。
- Noul/Choice/Score全部使用，71个有合同的问题在同批评估处理方式、方法角色/范围、跨方法关系、认知义务与细读需要。Score只描述程度，不计算授权或强行胜者。
- 第二层只追加至多两个具名方法的原始SKILL和公开方法正文；保留全目录与用户原文，最多再判断一次，未读主题和容量缺口如实记录。不递归加第三层。
- 宿主直接拿到选中方法及必要的配套原文、范围和认知义务，不加载整篇using-mindthus入口。方法未知不自动拒绝回答；条件性配套义务和冲突依赖需要具名有限答复/异议，不伪称全面路由合格。
