# using-mindthus 主线路由与多方法协作：设计候选 v0.1

状态：DESIGN_CANDIDATE / 未实施 / 未取得语义或采用资格。基线 `7306ba9aca90da23d84210939999e802ce8e041a`；关联 #211。本轮交付问题合同、消费规则、验收与调优机制；不启动付费推理、不改默认入口、不覆盖 D3/R1/R2/R3 记录。

## 1. Core：安排判断责任，不是排列方法分数

入口应给出完成当前任务的最小充分判断安排：什么可以直接做，什么缺证据，什么需要方法，谁负责哪个结论，哪些方法提供支持或约束，哪些产物是前置条件，哪些已有结果可复用。允许多条有效解题路径，不以唯一方法标签作最终真值。

Noul 评估命题成立性（可以多项同时为真）；Choice 区分职责、状态和依赖关系；Score 描述一个明确有序维度上的影响。三种类型在复杂协作路径中共同发挥作用，不把同一问题换三种格式投票，也不要求简单请求凑齐三类。适用概率不是价值，置信度不是主导权，影响程度不是权限。

LLM 负责开放式任务/解释提案、必要的同范围仲裁和方法执行；Jev 或其他兼容引擎承担版本化的局部判断；代码核对身份、来源、预算、形状和已经确定的依赖。读取/执行的权限来自原宿主。TPlan 仍拥有任务状态，不能变成一个与 WAE 争夺语义答案的普通方法标签。

## 2. 当前与目标的差量

旧 C01 graph4 返回一个当前 owner；已完成的关系纠偏是 `relationship-frame.v1`，且禁止叠加旧路由。这里提出的是同一 `entry.run` 的后继显式 profile `mainline-composition.v0.1`，不是已经存在的第三模式，不新建执行平台。

保留 Engine / Serving / ResolvedRuntime 和 DecisionSpec / Session / 原宿主。复用来源校验、精确引用、调用日志和 episode 锁；任何适配改动要有自己的契约和回归。新 profile 不能继承旧实测资格，也不能把旧失败 root 重新打开。

之前生成的概念图仅作讨论材料：三种类型不是三层串行；Jev 不负责开放式提取所有判断事项；defer/degrade 不能直接当 support/constraint 的同义词；无限回箭头不是 DAG。后继执行次序由 `dag.json` 表述，节点引用问题 ID；补充输入与版本修正展开为前向节点，不返回旧版本。

## 3. State 合同：保留原文、判断提案和执行状态的身份

`state_id/episode_id/turn_id/revision` 由既有责任方绑定。State 至少由下列有界材料构成；本设计使用字段名表达逻辑合同，不要求新建数据库。

| 字段 | 内容和责任 |
|---|---|
| documents | 用户原话、来源记录、既往助手输出、候选各自保留 id/version/kind/text。摘要保持摘要身份；原文不可改写以取得通过。 |
| authority | 原责任人、允许动作范围、风险、预算、未完成义务和真实授权引用；不得由模型生成授权。 |
| issues | 至多3项未决判断提案：id、object、deliverable、scope、question、原文refs、begin/commit所需输入。可复用现有短计划；不为分诊先生成完整回答。 |
| method_catalog | 从8份当前正式 Skill 原文生成的入口/边界卡及全文hash；仅供粗筛。固定抽取来源，不以人工AND/OR特征重新定义方法。 |
| loaded_contracts | 已选候选的完整正式合同及必须加载资源/伴随规则。粗筛结果不足以宣称适用或已读取。 |
| existing_outputs | 原责任方提供的产物、对象/时点、来源/版本、有效条件和未决项。旧summary或Jev信号不自动成为有效方法产物。 |
| proposal | 方法节点、所属issue/职责范围、拟交付产物、明确条件、候选依赖与合并方案；均为待核对提案。 |
| observations | 按每个问题保存原始status/value/uncertainty、来源类别、模型身份、是否消费、未消费原因和政策版本。 |

引用采用现有精确文档/版本/Unicode片段/hash机制。原责任方或有界整理器提出位置，代码只证明引用存在；G01判断该表示是否忠实。错误候选可以被忠实描述，G01不要求候选先正确。没有controller/thesis就保留空位置。

不把 expected、标签、作者评分、审计答案或验收集内容放入测试臂 State。每个问题正文必须含可读的对象及条件；不能只靠 ID 告诉模型含义。模板实例化追加只读 Binding（JSON中的名称、位置、来源片段），值来源必须可追溯，不允许把未返回的同批答案插入其他题目。

## 4. 问题组与选择性实例化

逐题完整题文、类型、选项/等级、输入、激活、前提、消费和反例在 `questions.json`；八方法绑定在 `method-bindings.json`；可读版由同一JSON生成 `question-catalog.md`。问题组不等于API请求。

1. G01–G05：表示保真、未决事项覆盖、当前处理状态、义务作用范围、方法名称的实际用法。
2. M01–M05：八方法候选粗筛、完整合同适用性、独立贡献/职责、前置缺口、正式伴随规则触发。
3. R01–R04：已有产物复用、职责范围重叠、同范围主导仲裁、指定产物的有向依赖。
4. S01–S02：影响程度是否可评，以及该缺口影响交付到什么程度。不是优先级总分。
5. V01–V03：具体路由提案对事项的覆盖、步骤的增量必要性、方法/目标/证据是否越权。

### 按材料而不是按模型类型分批

- 已明确的普通低风险动作由原入口直接处理；不额外扫描三类。
- 提案/短计划已存在时，G组、S组、M01和已具备合同的M02–M05可以共享快照。对明确命名方法，G05区分真正调用、审查对象或仅提及。
- M01只解决需要读取哪些完整合同。显式调用及正式伴随义务不能被粗筛低分静默移除。候选过多时输出coverage_overflow并交回原责任方，不截断成假唯一。
- 读取新合同或取得真实产物之后才形成新State。M05确实触发尚未读取的伴随合同，走一次前向companion_load/evaluate节点；不返回旧批次，不重新评已有效的其他关系。可以同批提出有明确前提的角色/依赖问题；前提不成立的答案保留但不消费。
- V组必须看到实际拟采用的路由提案，不审不存在的计划。没有方案生成时不凭空构造一个API依赖；若方案已存在可与其他问题合批。

当前设计容量（待工程和校准验证，不是供应商限制）：issue≤3，完整候选每issue≤3，整体不同方法≤4（伴随合同计入），有向候选产物边≤6，每批≤48题、投影≤98304字节。超额按原文交回宿主，不删证据或用高分裁掉强制关系。8方法粗筛最多3×8=24题，不等于每任务都问24题。

## 5. 结果消费：确定规则与未决语义分开

完整规则表在 `policy.json`，优先序如下：

1. 代码先处理真实权限、陈旧或缺失引用、未知外部intent和总预算。已知未完成硬义务不因模型说clear而清除。可分析被审对象的缺陷，不因对象有缺陷自动阻止分析。
2. G01失败只使对应issue/提案及依赖它的步骤无效；确有全局原文/权限错误才扩大范围。G02发现事项覆盖缺口时保留已确认的直接动作，路由完整性保持unresolved，由原宿主一次补齐清单；不循环全局否决。
3. G03先分开复用、直接、补事实、未决判断、背景和未知。显式方法请求保留为用户约束：读取并检查，不等于直接强制执行；方法被当审计对象时不自动获得当前owner。
4. M01仅影响读取候选。M02与M03分别回答能否开始和当前贡献。`适用 + covered`可以同时成立；`适用 + support`也成立。`不适用 + primary_candidate`是真冲突，交回该issue仲裁，不投票。M04解释不足究竟是外部事实、前置产物还是范围不符；不能要求方法的最终答案预先存在。
5. M05触发正式伴随要求时，代码落实可追溯的read/check义务；它不是对是否遵守合同的投票。伴随未知时查对应材料或让宿主判断，不记为not_needed。SELA与MPG互相提及不是循环边：读取合同是幂等资源节点；方向产物→路径判断才是语义依赖。
6. R01将复用限制在同对象/时点/条件/来源。partial只能覆盖明示部分，剩余义务保留。当前已有有效方向产物可以免除重做方向分析，但不自动免除当前必须读取合同的要求。
7. R02只在相同/重叠的结论范围触发R03。不同子问题可各有主方法。R03在完整合同限定内选当前结论的负责人，保留其他方法的支持/约束；选择none/unknown交回宿主。不能把全部任务压成唯一owner，不能强迫丰富解释获胜。
8. R04以“节点A的产物P→节点B的特定消费”为边。needed_to_begin阻止B开始；needed_before_commit允许独立的准备工作但阻止依赖结论的承诺。conditional必须有条件引用和其实际状态；未知条件不触发承诺。没有具体产物或acceptance_ref就不能从方法顺序惯例造边。出现三方主导循环或产物依赖环时不做两两投票淘汰；只冻结相关连通分量，宿主一次重构/合并范围；代码不猜断哪条边。
9. S01未建立可评性时，S02结果不消费，不设为0。S02只安排当前同一就绪集合内的审视先后/请求深度建议，依赖、用户期限、权限、强制核验优先。最终方法深度遵守各方法合同。没有通用`适用概率×影响×confidence`公式。
10. V01指出某事项覆盖不足，不能仅靠同义问题数掩盖；V02只移除确已重复且没有合同义务的步骤；V03指出越权则修复相关范围。一次有界计划修订后，复查相关V题；不重问整张图。

### 数值政策是待验证参数，而非真理

初始只用于离线/影子研究：Noul p≥0.8视作positive、p≤0.2视作negative，中间unresolved；M01粗筛用p≥0.2保留候选并对未保留者记not_evaluated，不计不适用。这些是作者提出的起始参数，不是官方通用安全阈值。后续在独立校准部分选定、再锁定；资格只覆盖验证过的后端/语言/分布。

Choice显式unclear/status非ok直接保留；分布用于诊断，不把confidence当跨题优先权。低置信选项的自动消费阈值只有在校准后才能打开；未校准时仅给原LLM建议，不能通过“全部退回”伪装质量。

Score0–3定义见S02。返回的加权期望不四舍五入成事实等级。影子规则：S01 positive且P(level≥2)≥0.8才建议先审；否则按稳定原issue顺序/用户优先级处理，显示混合分布。相同均值但0/3双峰与1/2集中不得宣称等价确定度。缺少原生分布的后端记录unknown，不伪造Noul或confidence。

## 6. 执行与原痛点接入

产物为稀疏的 RouteProposal：issues、steps(method/role/scope/inputs/outputs/contract_refs)、mandatory_reads、artifact_edges(condition/release/evidence_refs)、reuse、deferred、unresolved、合并责任人与claim ceiling。plan不是授权或已执行记录。

宿主读取正式方法并运行所需最小部分，证据中分开记录：推荐、读取、实际执行、产物存在、产物验收、最终任务验收。仅把方法正文塞入提示不算native skill activation；无法观察原生激活则该资格项unknown。

现有Skills/4K关系检查是before-route/before-answer的按需子图，不是整个入口。复用有效快照/题义的结果；变化只失效受影响节点及后继。未被激活不记为检查通过。纠偏子图中一次修正/复查和新路由共享一个episode额度，不能叠加旧C01和D3预算。

拟议MR工程上限：每episode最多4次快速判断批次（含按需关系检查/复查）、1次原文/事项整理、1次语义仲裁、1次具名修订，共7个插件模型请求；180秒总插件请求时间、45秒单请求。此为新profile候选，尚未改D3额度。方法本体/真实工具工作不隐藏在这7次里：另受原任务预算，全部计入端到端成本。容量不足即显式交回原宿主，不能复用旧答案作新判决。仲裁和修订只在真实问题出现时用，不是固定额外两调用。

运行时动态设计为例外：最多一份声明式局部候选，替代而非叠加已有仲裁/修订预算；仅影子/原宿主建议，不继承固定合同校准资格。必须保存题文、范围、消费和版本；发现通用价值后进入下次离线设计，不在生产里递归改题。

## 7. 不在设计阶段宣布语义正确

本轮能核对：题型符合接口、选项/刻度明确、每题有消费、前提无环、权限与来源边界、各种出口可测试。不能由文档审计宣布：Jev识别准确、多方法组合有收益、问题组彼此独立、计费一定只计算一次State、默认应当采用。

验收与持续改善见 `evaluation.md`、`acceptance.json`、`iteration-policy.json`。真正质量标准是原任务结果与必要判断/证据覆盖，方法名匹配只作诊断。已暴露Skills/4K、旧6/8例和本轮设计例子都是开发资产，不能重新命名为盲测。

## 8. 实施顺序与完成定义

MR-01：本设计与离线合同校验。MR-02：一轮独立设计审计及最小consumer/实例化接线，保留旧模式。MR-03：分离开发/校准，真实同State混合三型、方法产物和多方法消费；内部有界修复自行推进。MR-04：独立封存任务对比、影子观察与采用决议。MR-04不复活旧formal-abc，也不把两例痛点覆盖当全部路由覆盖。

每一轮运行有自己的开始前冻结，允许下一轮改变已证缺陷；冻结不是停止研发。内部问题由实现者归因、修复、回归、冻结后继继续推进。只有目标/权限/费用上限/不可逆风险等需要用户决定时才请求决策。
