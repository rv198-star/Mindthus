# 验收、校准与内部迭代机制 v0.1

这是设计候选，不是实测结果或新的费用授权。验收目标：最终任务更可靠、必要判断不漏、多方法职责与产物交接正确、额外开销有回报。不得以19题都返回合法格式、方法名命中率或多数模型同意代替任务效果。

## 1. 四层证据各自回答什么

| 层 | 验证对象 | 合格声明上限 |
|---|---|---|
| L0 合同/程序 | 完整题文可编译、三类型映射正确、引用/权限/无环、计数/恢复和全部消费分支 | 工程符合已声明合同；不证明语义正确 |
| L1 开发诊断 | 每题和组合为何命中、漏报、误阻断；输入/题义/消费/宿主的贡献 | 这些已暴露开发案例上的行为；可调优 |
| L2 独立校准 | 概率分段、Score边界、候选召回和放行覆盖的风险 | 冻结政策在该分布/后端上的候选参数；不算最终盲测 |
| L3 封存任务对比 | 自然输入、自动整理、候选发现、多方法实际消费、最终质量与总成本 | 有范围的对比结果；是否采用另有门槛 |

设计审计可以指出合同歧义和漏分支，不能预言模型一定理解。任何层出现错误先定位；层间不得自动继承PASS。

## 2. 用例覆盖与数据隔离

`acceptance.json` 给出24个开发验收条目，每项含任务材料、正确路径的允许集合/必要性质、反例变形、禁止结果和待执行测试阶段。它们不是24份独立holdout，也不是已经测量的24个成绩。

覆盖所有8方法的适用与不适用、无方法、先补事实、强制调用边界、同范围主辅、不同范围双owner、阶段接力、TPlan状态/语义分工、既有产物复用、局部阻塞、预算/并发/中断、Noul/Choice/Score联合和Skills/4K原痛点。

拟议小规模数据安排：DEV使用这些24条及其反例展开；CAL另取24个episode；LOCKED另取36个episode。CAL/LOCKED必须由未参与实现的出题流程从新原始来源准备，每部分至少12个不同source_family。数量是研究起始计划，不是足以证明总体非劣的样本量；本轮不生成伪装盲测的新样本。

隔离单位是原始来源/任务家族，不是换词后的单题。成对变形、同业务模板、翻译版、两轮对话、从原错误生成的邻近例必须处于同一partition。覆盖类别可以相同，来源family不能重叠。用literal hash+near-duplicate人工复核防止近重复；没有向量检索系统也必须作家族归并。Skills/4K与历次路由/6例/8例只在DEV，记录exposure ledger。

角色：builder只看DEV；calibrator固定题义，在CAL上选择政策参数；test custodian持有LOCKED输入与事先标准；blind evaluator只看原任务、必要材料和匿名/随机顺序的产物；dispute adjudicator核对分歧。不同上下文不等于统计独立，同模型也有共同偏差，明确记录实际隔离。无法保持这些角色的数据隔离时，降格为开发验证，不标独立验收。

## 3. 实际比较：机制收益与引擎收益分开

建议同任务配对三臂，模型/工具和计费边界在第一次测试臂调用前固定：

- A：真实非Jev原版 using-mindthus 路径，实际安装/调用可观察。不能把一段仿写提示当原版；不能让历史一次安装成功代替当前运行证明。
- B：相同后继判断任务与方法合同，以已授权普通LLM作判断并由同一个宿主执行。保留该后端自然的yes/no/unknown、类别和等级，缺概率就是unknown；不得把自报0.8当经过校准的Noul。
- C：本后继问题组用固定TypeSafe Jev；同一普通LLM宿主承担开放生成、仲裁、各方法执行和最终回答。

C对A回答整体设计是否有增益；C对B回答采用快速判断器的系统差异。B无原生概率时必须使用预登记的categorical消费版本，不能凭伪概率套C的阈值；这种对照不是纯引擎因果隔离。要隔离题型收益，另做受控question-format消融，不把不同政策造成的差异全部归于模型。

A/B/C从同一原始任务和同等可用工具开始，不把人工准备的完美J列表或正确路由只喂给C。B/C共用同一版本的有界整理模板，但各次实际整理费计入各臂。机制定位子实验可以共享固定proposal，以隔离引擎；这与raw end-to-end分开报告。普通宿主为当前已授权CPA型号，固定试验不静默切备用；OpenRouter仍只准Jev。

原版A不可运行、原生方法读取不可观测或任一比较臂未完成时，记录blocked/unrun，不换提示替身。不影响已完成工程和开发证据的保留，但不能发布完整三臂比较结论。

## 4. 每个episode怎样判定成功

测试前冻结task_contract：必须保留的事实/主体/范围/偏好/权限，必须解决的判断与产物，允许的不同处理路径、条件回答/具名取证是否为正确结果、不可接受错误。

最终每项返回 improved / equivalent / degraded / unresolved / technical_failed。比较依据是原任务能否成立，不是产物更长、更多术语、更多方法，或是否等于作者私下答案。

每项至少分开记录：
1. 事实与来源归属：无编造、无把“当事人”变成“你”的越界。
2. 有效目标与范围：接受合法更正而非顺从无据结论。
3. 必要判断覆盖：包括主判断、支持和边界，不漏后续关键决策。
4. 协作执行：实际方法资料读取/步骤/产物/消费可观察；读了正文不等于执行成功。
5. 可行动性：结论/条件或合理的具名取证完成当前要求；缺资料时请求资料不必判失败，但目标本来可决定却一直回退是失败。
6. 额外负担：无必要加载、重写、阻塞、延迟与成本。

输出质量采用上述分项0/1或not_assessable，不用加权总分抵消事实/权限错误。judge分歧保留，先锁各自原判断再裁决；材料外新知识不静默填入评分。方法名仅为过程诊断；确有canonical必须读取的条款则独立检查。

同一Jev的S2复查是回归信号，不作最终裁判。匿名产物审阅不提供方法路由结果、模型名或预期方法；可追溯原始来源，但不看实现内部评分。所有弃权、缺材料、错误和技术失败在总分母内；只在Brier等不适用于无共识gold的诊断里单列排除，并公布分母。

## 5. 量化诊断与采用门槛

问题层：候选召回/误引入，Noul校准曲线/Brier/不同阈值precision-recall，Choice混淆（尤其missing_fact与方法输出未知、支持与主导），Score有序误差与完整分布。无共识标签不计算“真值校准”。同家族相关样本不当独立重复。

图层：未覆盖必要issue、假依赖/漏依赖、阶段错误、无效全局阻塞、false reuse、冗余方法和实际auto_handled比例。必须同时报自动消费覆盖和条件下错误率，避免“全回退所以准确100%”。

任务层：所有episode的improved/equivalent/degraded/unresolved/technical_failed；原痛点与各协作类型分列。总成本包含原文整理、合同读取、路由、方法推理、工具、纠偏/复查、回退、失败/重试、审计、开发维护；未知金额不记0。请求时间、整轮墙钟、并行关键路径、开发时间分别记录。

候选晋级（不是生产许可）的预登记初始规则：
- L0全部硬约束/恢复测试通过，任一权限绕过、未知intent重发、原始事实改写均阻止晋级。
- DEV所有具名已修缺陷闭合，并保持反向控制；不要求所有可争议方法标签一致。负面用例不能事后删掉。
- CAL上按受限参数网格选取可行政策：`errors among auto-consumed`与`coverage`一起报告；不具备有效概率的引擎单列。不能只调低门槛以通关。
- LOCKED质量先于经济性。提议把允许的任务成功率下降界设为5个百分点作为待核定起点；在LOCKED开启前必须固定最终delta、关键错误定义和统计方案。按source_family配对/聚类计算差值区间，lower bound未超过-delta则non-inferiority为INCONCLUSIVE而非PASS。36个相关episode很可能只能提供描述信号，不能靠点估计宣称普遍等效。
- 任一关键事实/授权伤害或显著子类退化，不靠平均收益抵消；不得默认采用。质量条件成立后再看p50/p95完整时延、全部可观测费用以及任务收益。不知道账单时仅能给时延/调用收益，不能给精确费用节省。
- 全部保留为可选实验，进入有界影子观察还须按实际场景校准；默认开启/发布由Owner另作决议。接口可替换不意味着后端资格自动转移。

## 6. 调优闭环：允许改，但一轮只回答一个清楚的问题

完整机器规则在 `iteration-policy.json`。每次变化记录 failure_id、原始证据、主要归因、最小修复、预期影响、可能误伤、受影响测试、语义/输入/政策/宿主版本与费用。

归因顺序：实际链路与来源 → 原文/提案映射 → 问题语义与候选空间 → 原语类型与刻度 → 模型概率/校准 → 确定性消费/依赖 → 宿主执行与产物 → 评分合同歧义。接口bug不是模型能力上限；模型误判也不能用无穷工程补丁掩盖。

先从已保存结果离线复算/重放，能验证的别重新付费。输入或题义变更必须新请求身份；同语义只改消费阈值可以在DEV/CAL复算，但真正删题、改State/批次布局、改变实际方法链必须新有界调用。保留被改变但未消费的原始答案，不生成解释伪装原先模型理由。

一个development cycle最多3个语义候选、最多2个连续无增益的live诊断批次。达到上限先作内部anti-spiral复核、等量替换/删减/縮小范围或保留旧champion，不机械向用户申请继续。只有新证据支持的新假设和仍有效的总预算，才登记下个cycle；不能改名字重置未决调用或隐藏消费。

同轮不边跑边改。候选题组在批次前冻结；它失败后归档并进入下一版本。已成功且identity未变的结果复用，不要求“每次修一下就跑全部历史模型”。影响关系变更则跑关联回归与代表性反向控制，工程代码改动按项目范围回归。

## 7. 消融：不是只会加题

分别比较：去掉某个可选题/组的实际新请求；保留原返回只改变消费规则；重复同一冻结完整请求估计波动。三者分开，不把mask旧答案称为实际少问一题。记录实例集、State、题文/政策、真实使用量和最终宿主产物。

Noul组看是否保留同时成立的多个方法；Choice组看职责/依赖和作用范围；Score组看审视先后/深度是否提高收益而不突破义务。删Score后若任务质量/总开销无差别，就合并/缩减Score激活，不为凑齐三型到处评分；核心复杂协作合同仍支持三者联合。

批量/分开发问的计费差异是独立探针。官方说明只作设计参考，不继承其示例比例；当前项目历史观察过新增/删题答案不完全一致，保留该风险。任何按State共享计费作出的预算优化，都需要同模型/同材料/同问题的实际usage/账单证据。

## 8. 防止保留集被用于调参

CAL用于选择阈值，不用于反复修改题义。CAL结果推动语义变更时，该partition降格DEV并重新准备校准数据。LOCKED打开后不改题、阈值、标签、仲裁规则或删除失败；失败推进新开发版本，当前测试集永久成为已暴露回归资产，下一正式验收使用新来源family。

试验中发生未知调用先核对原执行，技术失败按冻结规则记录；同输入同identity不能换目录重发。已知本地失败且需要修复时，用独立技术修复身份，并明确是否影响对比可比性；没有完整对照就不作净收益声称。

本机制把“内部研发持续迭代”与“运行中无限纠偏”分开：普通问题由实现者持续处理，旧证据始终保留；用户只处理改变目标、权限、重大投入或不可逆风险的决策。
