# 主线路由独立审计：收缩默认执行面，保留必要判断能力

审计对象：`9cc8f846e638aa81317c3c2982423760f7d8fcca` 的 mainline-composition-v0.1。用户本轮要求是审计，并明确允许一定可恢复偏差、担心过重。本轮仅审计及记录处置，不修改被审题文、政策、DAG或运行代码；以下轻量方案是作者处置/下一版建议，不是已实施或已测有效。

## 结论

**不建议按当前完整机制一次性实现。19个模板可以留作设计资产，首版应实现少量常用判断，其他按明确需要展开；独立统计验收不能挡住可回退的低风险实用验证。**

需要降低的是默认流程负担，不是把多方法协作砍回单选，也不是把Noul、Choice、Score重新变成三选一。允许选另一条同样有效的方法路径、合理的轻微深度/排序差异、原宿主能纠正的局部偏差；不接受伪造来源/已完成证据、模型越权、忽略真实权限、未知调用重复发送，或靠全部回退伪装高准确率。

## 3. 下一版最小实用路径（建议，不是新运行合同）

### 常用路径

原宿主先处理已明确的直接动作与真实权限。需要方法判断时，复用现有短计划/原请求；仅在缺少候选合同等必要材料时补一次读取。相关材料齐备后，同State优先合批：

- **Noul**：保留可能同时成立的方法适用性（M02；必要时先做M01发现候选），不强制8选1。
- **Choice**：方法在本次的主导/支持/约束/不参与角色（M03）；确有多方法关系时补具体产物依赖R04。
- **Score**：多事项中尚未解决的缺口对交付的影响（S02），只作深度/关注顺序建议，不授权、不改变依赖、不自动按分数排除方法。

原宿主结合正式合同形成并执行最小方案。没有必要为每次路由再生成完整方案、再逐项审查、再仲裁、再复查。目标是正常材料齐备时一批评估，确需新增合同/产物时补下一批；这是实施目标，不是已验证时延或绝对请求上限，复杂任务不能为凑请求数删材料。

### 条件分支

| 真实需要 | 才展开的检查/处理 |
|---|---|
| 新增/修改了影响路由的语义提案 | G01保真；确有多事项清单时G02或V01选合适位置查覆盖，不把两者固定重复跑 |
| 当前处理模式本身未明 | G03；显式方法名意图不明才G05 |
| 有义务作用范围争议 | G04；已有权限和职责直接保留，不让Jev重新授权 |
| 方法开始条件不满足且需要定位 | M04；没有定位价值不再增一次请求 |
| 正式伴随条款触发需要判断 | 原宿主判断或M05；读取义务完整履行，已有合同和有效方向产物复用 |
| 两个方法争同一结论 | R02/R03；主辅已由正式合同和现有判断明确时直接复用 |
| 已有有效产物/真实前置依赖 | R01/R04；不实现通用计划搜索、任意递归依赖平台 |
| 新方案出现具体漏项、重复或越权风险 | V01/V02/V03中相关项；不默认三项全部再问一遍 |
| 已有候选出现原Skills/4K类偏离 | 使用已有一次具名纠偏及必要复查；不重建模块 |
| 仍不确定或超出插件预算 | 原宿主继续该范围；保留已完成工作与未知，不要求用户重新批准普通内部修复 |

不为轻量版新建另一套日志、任务引擎、默认多Agent审核或运行时设计器。引用、调用intent/outcome、预算、恢复用现有实现。19模板可以保留为扩展库存；首版并非把每题都实现成必须过的门。

## 4. 容错：允许合理偏差，不允许伪造确定性

**可接受并记录的情况**：两种合理方法路线不同；主辅排序或分析深度略有区别；局部措辞经原宿主修复；低风险处Jev判断不稳而交回原宿主，原任务仍推进；边际收益不足的可选检查暂时不用。这些不应自动成为批次失败、全局阻断或新增防线的理由。

**必须处理的情况**：必要子判断持续漏掉、关键依赖被绕开、无据事实被用作关键结论、用户有效目标被替换、真实权限被模型推翻、伪造读取/实测/来源、未知在途调用重发。此类发生时保护相关动作并归因修复；不能用平均高分抵消。区分修改了原始证据与候选里可改正的表达瑕疵，不把每个非关键措辞问题升级成整个系统不能试用。

没有一个用户批准的“可错5%”数字。本轮只确立误差按实际后果分类；允许偏差不是预先同意任意错误率，更不是保证零错。

## 5. 首轮验收也做减法

建议从既有24条覆盖库存选一批**8–12个有代表性的原始任务**（建议数量，执行前明确入选和标准），包括直接/缺事实、单方法、同时适用但无需重做、主辅、阶段接力、两个独立子问题与部分等待，Skills/4K作已暴露回归。第一次结果前锁定材料和评价标准，不看结果后筛掉失败。

相同任务、相同宿主，对比真实原处理路径与轻量Jev建议路径。暂不为纯引擎归因再增加B臂，也不以前置概率校准为由等待。原版路径未实际运行就不能宣称对原版更好；但可以继续报告功能链与开发观察，不陷入环境准备阻塞所有工作。

主要看四件事：**最终任务是否可用；必要判断/主辅/交接有没有遗漏；是否减少不必要的重写或阻断；总耗时/调用/可观测费用是否值得。**判定 improved/equivalent/degraded/unresolved/technical_failed，允许合理替代路线。Jev分数不是最终评审依据，全回退也不是成功。少量测试只能支持有界试用，不宣称全局统计非劣。

不需要让每个中间标签都等于作者期待。轻微可恢复偏差进入改进记录，不对每条增加新检测题。反复出现、影响主目标的缺陷做一次有证据的修复；删题/合并/缩小激活与改题同等合法。沿用内部有界迭代和原调用恢复纪律，无需为这轮减法另建治理平台。
