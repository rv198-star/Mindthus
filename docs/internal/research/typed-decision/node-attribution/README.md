## 四个不同的问题，分别怎么查

### 1. 入口同时承担了两种责任

一种是语义判断：“这件事是否需要方法、是否缺关键事实”；另一种是遵守已经解析好的
显式方法请求。当前 `explicit_method` 已是经过 D0 校验的结构化字段，却仍让 J1 用
文字规则记住其分支影响。5 个视图在这里出现了冲突。

**设计候选**：代码处理明确调用约束，语义节点判断信息缺口和适用性。显式调用不等于
适用，更不等于执行权限；真实信息缺口与义务仍能阻断。这还不是已验证修复，本轮不改
J1/J2 同批或正式 DAG。普通低风险任务为何“必须”用方法，也需先稳定判准；现有标签
保留，EDSP 必要性的争议不能通过回头改答案解决。

### 2. 义务检查可能混淆了“研究对象的问题”和“当前执行的障碍”

L22 要求分析一个虚构推荐助手：渲染器擅自解释模糊标准并改排序，职责应该在哪里收口。
请求本身不修改系统，也不作真实购买推荐。J2 的问题同时提到 framing / ownership
以及“before proceeding”，因而可能把**需要 WAE 解决的问题**读成**连开始 WAE 都不行**。

这只是从题目与控制路径推导的机制假设，模型未给出解释，不能把推测写成已证实根因。
对照 L29：当前请求要把尚未举行的投票写成已获选，确有本轮证据义务，应当阻断；
且其 `known_obligations` 已能触发代码保护，不能把这一保护全记为 Jev 功劳。

要验证 J2，需对照“仅分析含缺陷的对象”与“本轮就要据此宣称/执行”，冻结独立标签，
同时测误拦与漏拦。不能只把 L22 改到 clear 就宣布完成。

### 3. 方法选择有一个实错，也有很大的盲区

按冻结标签，有 22 个有效视图明确需要非显式方法选择；实际只有 14 个到达 J4，
另外 8 个被 J1/J2 提前挡住。14 个中 13 个符合标签，但样本由前置层筛选过。
实际选对的输出只有 SRA、EDSP、MPG、WAE；SELA 唯一观测输出来自 L19 的错选，
3L5S、TVG、TPlan 没有这批成功分类证据。owner 的 unclear/no-match 也未观测到。

L19 的长期数字化方向已认可，当前要判断服务商锁定、格式可迁移性与工时暴露。
按冻结合同这是 MPG；中文版却选 SELA。需要检验它是否被“数字化效率”话题带走，
没有抓住“方向已定，正在选承载路径”的当前问题。不能因为英文这一次正确就认定
翻译已解决该类边界问题，也不能拿 13/14 证明八方法路由可靠。

### 4. 适用性检查的拒绝能力根本没有被测到

17 次 J5 全部 yes。L27 的 WAE 排序编号、L28 的 MPG 文字替换，本来应能检验
“点名也不适用”；但它们在 J1 就回退了，所以 J5 没看过这些反例。

L19 错选 SELA 后 J5 通过，只说明它没挡住这条已知错误路径。J5 问的是“适不适合
开始”，J4 问的是“当前由谁主导”，两者并不等价。没有独立适用性 gold 时，不能仅凭
J4 错选就机械给 J5 标错；也不能把串两个相似判断当成独立保险。

## 最小补测设计：先回答方法分类能不能用

这是可冻结的设计草案，尚未分配费用或启动新运行；不新增通用执行框架。

**第一包：把方法选择从前置阻断中单独拿出来观察。**

- 使用已有 11 个必需非显式方法场景：L09–L12、L14–L15、L18–L22，两语言 22 个视图。
  无论原来通过还是失败全部纳入，避免只补容易成功的题。
- 复用 14 份已有效的 owner 结果；仅补 8 份原先未调用的 owner 请求。绑定相同完整
  State/Contract/runtime 才允许复用；历史两适配阶段继续分列，不冒充一次同期对照。
- 补调用是明确的诊断干预：假定已经进入 owner 选择阶段，不执行原前置层的阻断。
  不注入正确 owner，不修改事实；结果只能说明条件下的分类能力，不能替换整图结果。
- 再用 L03/L04/L23/L24 共 8 个双语视图作无方法适配的控制组，提前核实其 owner
  no-match 标签；不能把强制进入诊断节点理解为“必有一个方法适合”。这些是新增节点
  标签、复用旧开发材料，不是盲测或 holdout。
- 普通 LLM 对全部 30 个相同 State/Contract 视图作对照。若旧缓存全部满足复用条件，
  则最多新增 16 次 Jev + 30 次普通 LLM 调用；这是调用数草案，不是费用承诺。
- 先报告近邻分类、no-match、拒答/技术失败及成本，按语言和历史适配版本区分。
  第一包不修题。若两模型都在同一标准上分歧，先定位标签/合同；若 Jev 单独落后，
  再考虑模型限制。不能只凭“普通 LLM 也错”自动认定标签错。

**第二包只补适用性拒绝缺口**：固定 L27/L28 的显式 owner，按原设计读取完整合同，
双语共 4 个 J5 请求，各引擎一次，最多新增 8 次调用；用于测假适用，不重跑整图。
它不扩大成八方法全部资格认证。J2 的对象/执行反例设计是另一假设，不混入这两包。

启动前还须锁定普通 LLM 的可用模型快照、请求/语言视图哈希、语义 gold（尤其 no-match
和适用性）、费用上限与结果处置表。先核对资格可复用性；若不满足，不自动重问旧题。
可解释的新证据才支持后续一次有界合同修订；不明、超预算或无收益线索就结束该轮，
不以重命名诊断重置旧修订额度。正式 holdout 和 A/B/C 仍按原顺序，C02 不启动。
