# Mindthus 快速裁决候选与投资顺序 v0.1

通用规范：#209。状态：设计阶段排序，未实测；不是模型性能排行榜或生产部署授权。
基线：main `1527f32b99c375db9ff73f80812c644686a6576a`。WAE Loop另属研究分支 `6c84c96f3cc7cf9fe9788148439417749f6e7f2a` / #207。

## Core / 核心

**先选有业务意义、可小规模证伪的两种裁决：入口分诊，以及一个有边界产物的改进方向。用不同形态检验通用规范，保留其余候选及落后原因。**

第一批推荐：C01先做；C02作为第二个有条件试点。先后是资源排序，不是C02永远依赖C01成功；若C01只是场景不适配，完成归因后仍可判断C02是否值得启动。共性后端/恢复/成本机制失败时，先解决共性问题或停止，避免两个场景同时边跑边修。

## 评估方法与证据上限

先排除纯确定性、无业务后果、缺少必要权限、无法形成有意义边界的对象；再比较潜在节省/避错价值、复用范围、判题稳定性、可验证程度、准备/接入成本、误判后果与回退代价。

排序是人可复核的定性投资判断，不把假设频次和虚构准确率相乘成ROI分。没有真实调用量、基准延迟、图设计成本或回退率，所有“高/中/低”均为源码边界推断；经济收益尚为unknown。已存在的schema测试证明形状与机械约束，不是语义标签或收益数据。

## 逐项可复核卡片

### C01 — 入口分诊与方法选择

源码：`skills/using-mindthus/SKILL.md`；`docs/internal/issues/progressive-disclosure-runtime-exploration.md`。可复用 `scripts/router-wakeup-ab.py`、`scripts/run-judgment-benchmark-cli.py`、Judgment Trace、历史50题作回归。

输入：当前请求、有效任务约束、必要证据摘要/引用和同版本方法边界。输出：直接执行/补事实/进入方法/交回LLM，以及保留的框架与证据义务。

价值假设：新图替代一部分真实语义路由工作，而不是在完整原路径前永久再加一次调用。主要看错误加载、困难判断召回、任务最终验收与总成本。公开案例仅说明可复用工具，不提供新保留集资格。

重排条件：若宿主不能观察实际加载与最终任务结果，降级为工程诊断；若需要高频整仓摘要才能分诊，成本假设被削弱，停止或后移。

### C02 — TVG有边界改进方向与复查

源码：`skills/tvg/SKILL.md`、`skills/tvg/resources/fidelity-contract.md`、`tests/test_tvg_contract.py`。

输入：一个文本模块、独立于待改产物的expected_value/value_profile、硬约束与可用证据。LLM设计可复用的局部判题和可选改进动作；快速模型判断弱项及动作适配，既定策略选择一个已授权的改写分支；LLM生成新模块，快速复查后交给原有exit owner。

预期收益：减少盲目加深/润色，让每次改写有明确目标。不把TVG 0–5参考分变成加权终态授权，不让脚本或概率阈值写freeze；高风险独立审计要求保留。首轮只含文本、一个局部改写和一次复查，非视觉atlas、非全文件无限循环。

主要看改写后的实际可用性、证据忠实度、无用改写次数和总成本。语义保留样本/独立评价仍需准备，现有contract测试不等于已解决。

重排条件：若评价者难以形成稳定局部标准，或设计标准成本无法摊销，暂缓；若跨两个文本用途都复用同一接口且质量不降，增强通用性证据。

### C03 — 主张—证据支持关系

源码：`docs/internal/judgment-trace.md`、`skills/wae/SKILL.md`的Evidence边界及`AGENTS.md` Gate Probes。

输入是一条指定主张及授权取得的局部证据；输出supports/contradicts/insufficient/needs_domain_reasoning。程序检查引用存在性，快速模型只评价语义关系，事实真实性仍由真实来源与运行证据决定。

验证需要真实支持、反证、仅格式一致、错主体、错时间和长链因果等反例。缺少独立证据标签是当前落后原因。证据准备可复用且错误支持受控后再考虑。

### C04 — WAE交接剩余问题归属

源码：#207研究分支`skills/wae/resources/delegation-loop.md`；不得当成main已启用功能。

输入一个已识别障碍、current/downstream职责、授权与有限产物；输出current/downstream/upstream-or-external/unclear。最终handoff、Unit/Result/Absorb和TPlan责任不自动迁移。

主要防两个相反错误：下游合法自由被要求上游穷尽；真正缺口被过早交接。需真实交接结果及返工归因，不按文件长度或概率投票验收。pilot已有复杂性与未完成价值取证使其不适合首发。

### C05 — 反螺旋中的语义增益判断

源码：`AGENTS.md`、`docs/methodologies/shared-primitives.md`，并复用TPlan已有状态/Trace。

同一对象计数、身份与证据事件由程序/原runtime提供；快速模型仅辅助判断“这一轮是否仍服务原目标/提供新的有效证据”。原有第三次处理等确定性触发不被概率判断取消。

缺乏连续真实记录会让模型凭空推断，故先保证输入质量。不能将中断恢复本身作为Jev新建记忆平台的理由。

### C06 — SRA入口与模式

源码：`skills/sra/SKILL.md`；相关#185/#186/#188，既有输入准备/完成引用不重做。

快速模型可判断已提供的候选是否足够清楚、是否真实共用资源以及需要哪种深度。容量、依赖存在性、事务和权限仍由现有程序；最终必要性、bundle sufficiency、风险接受与分配不在本候选范围。

真正成本可能在输入整理而非模式选择；先测这一瓶颈，再决定升级排序。

### C07 — TPlan用户消息意图

源码：`skills/tplan/SKILL.md`；既有#134/#148/#199能力作为约束，不重开已解决问题。

仅区分当前问询、补充信息、潜在scope变化等，所有授权解析/变更提交仍走既有机制。误分类可能导致高后果事务，且许多直观情形原LLM已能处理，故首轮价值证据弱。

### C08 — 下一步算力档案

这是新增宿主结合点，不是已存在的“Jev可替换函数”。LLM/配置维护能力与预算档案，程序先筛选工具、模态和权限合格的配置，快速模型对下一动作特征分类，再给出建议。模型名称/最新排名不嵌入业务合同。

只有存在当前有效能力表和匹配质量/成本数据，才值得试自动切换；缺少这些，通用性投入可能变成平台建设。

## 首轮不做的对象

- SRA完整资源分配、SELA/EDSP/MPG总体战略或结构推演：开放式候选与重大语义耦合，保留LLM主导；未来可抽出局部判题，但不声称全部方法都能编译成DAG。
- 哈希、schema、计数、引用完整性、事务/权限、顺序与幂等：确定性现有能力，不增加模型调用。
- 全项目总分、最终发布/交接放行：独立证据与Owner边界保留，不把schema或高置信度当授权。
