# 独立复议后的合同修订：C01 v3 / C02 v2

本次修订落实三位评审确认的问题：先明确题目测什么，再修正局部决策。它是新版本的离线开发工作，不是旧实验第二次调题，也不改变旧实验未通过的结论。

## 判定标准

测试分开记录三件事：**合同是否服从、答案是否在可辩护集合内、任务是否真的做得更好**。前两项不能替代第三项。标签必须给出具体场景证据、标准条款和下游后果；“方法适用”不能推出“必须使用”。

C01 判断下一步是否存在会改变行动的未解决判断。规则和目标已定、只需普通文本合成时可直接执行；存在真实资源取舍、结构歧义、用途判断等才由对应方法介入。薄产物本身不是强制介入理由。多条路径合理的案例使用预先声明的 canonical 接受集合；合同集合另列。N01 的合同服从性仍未裁定（contract_accepted=null），不能计作合同匹配，也不能进入 live 验收集。其他场景的合同集合明确列出；不作为“漏掉必要介入”的唯一 gold。unclear 是保留的弃权出口，单独报告，不算成功匹配。方法 owner 与最终任务赢家也是不同对象。

`known_obligations` 保留原字段名，但含义明确为**仍未解决、会阻断继续的义务**。已经满足的要求写入 constraints/evidence。代码保留非空义务，模型不能将其清除；这不是让模型重新授予许可。D0、同批入口/义务、后续 owner 选择与完整 canonical contract 读取保持原路径。

C02 的 utility 只判断**是否满足已声明读者任务**。deficit 必须能指出缺失、错误或被实质阻碍的任务要素；“还可以润色”不算。新增事实不能消除两个强制目标之间的逻辑冲突；缺测量只是 source support=missing。重复或篇幅本身不能证明负担。compact_preserve 仍保留为候选，但需要事先声明的使用限制或读者取用失败证据；本轮没有这种独立依据的案例，不赋予该动作语义资格。

| 联合结果 | 运行时后果 |
|---|---|
| utility 为 outside_scope/conflict/unclear | 交还原 owner；丢弃推测动作 |
| utility 可判，support=missing | 补事实；不生成 |
| support=conflict/unclear | 交还原 owner 解决来源基础；不生成 |
| adequate + sufficient + leave_unchanged | 不重写，交还原 owner |
| adequate + sufficient + 任一重写 | 记录判断冲突，交还原 owner |
| deficit + sufficient + leave_unchanged | 记录判断冲突，交还原 owner |
| deficit + sufficient + 有匹配缺口的重写 | 仅提出一个候选；不自动执行 |
| action=abstain 或任一调用不可用 | 交还原 owner，不补猜答案 |

缺口与动作是否相配仍由语义模型及后续独立评估负责；确定性表只防止明显不相容的结果被消费，不证明模型找到了真实缺口。

## 实现变化及其限度

- `c01.py` graph=3：取消“存在有界薄产物就必须介入”的倾向，明确直接合成边界和未解决义务含义。未修改 canonical 方法或 Engine/Provider。
- `c02.py` graph=2，合同见 [c02-contract-v2.json](c02-contract-v2.json)。utility、support、action 使用同一 State，一批推测计算；action 不再读上游标签。runtime 决定消费。按原则优先合批，不声称已经证明比串行更快、更好或更便宜。
- 真正的新 State 是生成后的 artifact。重检批次为 utility + fidelity。fidelity 明确检查无来源断言、矛盾主张及关键条件/限制的遗漏；不再重复询问未变化的来源是否充分。
- fidelity 的 violation/unclear、用途未满足、服务不可用分别返回原因；全部交还原 TVG agent。`exit_state` 始终为空，最终忠实性与用途审查责任仍归原 owner，不自动 freeze/PASS。
- 原有单次 generation intent/outcome、恢复禁盲重试、模型快照锁定、权限与成本边界继续复用。

这里做等量替换：消除动作的伪 State 依赖，以真正的成品忠实性问题替换重检来源问题。没有新增通用设计器或评审平台。

## 新案例与离线反例

[cases.json](cases.json) 是公开的开发/诊断材料，不是 holdout。新场景来自标签评审独立提出的候选，由实现者整理为结构化 State；最终标签和理由可见，不冒充人类真值。C01 canonical_accepted 与 contract_accepted 分栏；C02 accepted 表示本局部合同的联合答案，N10 support=null 明确不评分。不同规则/测量版本使用不同来源及标准身份。旧 38 题、旧分数和停止记录不改。

包括：完全指定编辑／直接合成与方法介入均合理／缺制度事实／稀缺资源取舍；规则完整／仅多套话／缺分支／缺来源／缺测量／目标冲突。另在来源和目标不变时，对两段完整说明分别增加无来源效果断言、删除关键限制。

反例说明 source=sufficient 可以与 artifact fidelity=violation 同时成立。离线测试注入预期答案，只验证分批、组合、阻断、身份和恢复行为；不会证明 Jev 能发现这些错误。对多答案题应报告集合匹配与唯一子集两种口径；不可从同一集合分别取值拼出未被允许的联合结果。

## 历史保存与新实验接纳条件

旧源代码完整保存在审查基线 `26c3f5e7227479768fd1b068c8b17358c061804a`；旧冻结清单、标准、标签、运行报告、原始 journal 与会议意见逐字保留。当前源码身份变化是新版本的必要结果，旧 carrier 必须拒绝新源码，不能修改旧 freeze 的 hash 来解锁。历史 carrier 的单元测试使用临时 test-only freeze、注入 transport，不构成真实调用授权。

本任务不运行新 Jev 调用。调用前仍须完成：

1. 审阅新合同和案例的接受集合，保留争议；冻结新的协议/数据身份、完整评分分母、不可接受后果及修订上限。本文案例只到离线开发候选，不冒充已预注册的新资格集。
2. 针对明确假设绑定新官方 TypeSafe 运行的精确请求、模型快照、无重试策略和累计预算。旧 C01 修订 1/1、C02 修订 0/1 及历史支出原样保留；新协议不自动继承资格或抹去成本。
3. 真实开发稳定后才形成真正未见的 holdout，再一次验收；其后才考虑 A/B/C。任务收益和完整成本未知前不能宣称获益。

新假设是：以读者任务缺口定义修复，并只消费一致的动作判断，能减少无依据重写；对新产物直接询问忠实性能比重问来源充分性提供相关信号。这些是假设，不是本轮离线检查的结论。
