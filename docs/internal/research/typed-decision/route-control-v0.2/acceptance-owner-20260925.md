# #211 后续验收口径：整体不输纯 LLM，难题有实际增益

状态：Owner 于 2026-09-25 更新的**后续资格目标**。它不回写此前 A–F、三家族 A/B/C 的冻结协议、账本或分数；当前结果按本口径重新解释，下一批新输入才按此口径事前冻结。费用在目前比较中暂计 0，实付未知；完整任务耗时不作为当前主门槛。

## 核心判断

Jev 路由值得保留的证据是两个条件**同时**成立：

1. **整体不输纯 LLM 路由。**在同一批原始任务上，Jev 路由的有效决策覆盖不低于普通 LLM；不能靠更多弃权、回退或只统计已提交案例使“准确率”好看。事实、权限、范围或必要依赖的严重误判不能由其他题的平均收益抵销。
2. **难调整场景有明显增益。**在 Skills、4K 这类事先指明的场景里，至少一个场景家族反复出现“纯 LLM 发生了会改变任务结论的路由错误，而 Jev 纠正了它，并让原宿主交付更合适的结果”；另一家族及反向控制不得出现抵销这一收益的退化。只改方法名称、说法或解释长度不算增益。

这是**有条件的价值门槛**，不是要求 Jev 在每个场景都赢。Jev 局部调用更快可单列，但不抵消整体判断退化；现阶段不以暂计费用或完整任务耗时判输赢。

## 如何判“整体不输”

主基线 B 是**普通 LLM 在相同判断图、材料、方法合同和同一 Codex 宿主下路由**；C 只把该判断器换为冻结的 Jev，所有失败、弃权、未决、回退、后继复查都进入分母。A 是当前 Codex 原生 `using-mindthus` 路径，用于核对产品本来的最终任务表现，不把它的一次开放答复耗时伪装成独立路由调用。两个方法都可充分、不同路径可等效；不以作者偏好的单一方法名作唯一真值。

每个原始任务预先列出可接受路线集合、必须保留的事实/权限、必须处理的后继、允许直接做或具名取证的条件，以及会改变任务方向的严重错误。独立评阅原文、实际路由、宿主读取和产物，给 `有效 / 等效替代 / 错路由 / 未决或回退 / 技术失败`；只在能落到原任务结果时给有效。至少同时公布：全分母有效决策数、严重错误数、未决/回退数、已消费路由的条件正确率、最终任务结果。小批可以报告逐题差异，不能凭三题点估计宣称总体统计非劣；若要作可推广的非劣声明，差值容许界、样本来源和统计办法须在新的封存集打开前锁定。

## Skills / 4K 的增益怎样看

- **Skills：**在同一个 Skills 对象内，接受第二轮合法的讨论范围修正，同时继续独立审查“因此它只是提示词注入”的结论。充分的简单提示词解释也必须允许成立。看的是纠偏后主判断与来源边界，而非一定反对用户或多调用一次方法。
- **4K：**同一类显示器材料要区分“正在使用、是否解决眼前困扰”“购前在 4K/5K 间选择”和“某回复是否切题”。主判断随角色、时点、目标与可接受损失改变；物理限制、预算未知和原叙述者身份不能丢。不能靠固定支持 4K/5K 或两边都说来过关。

新验证须用**未进入旧开发/审计/调参材料的原始来源家族**，包含同家族的反向控制；同一帖子换词或同一案例跨轮变形不算独立来源。每家族先锁可接受的不同判断与重大失误，再运行 B/C，并由看不到臂名的评阅核对路由改变是否真的改变宿主结论。作为“明显”的最低操作化建议，至少两个独立来源家族重复出现同方向、对任务有实质影响的改善，才把单个精彩案例升级为优化候选证据；这个数量不是 Owner 指定的统计门槛，也不足以证明普遍收益。若仍是少量 AI 合成样本，只能称开发信号。实际默认采用还需更宽任务分布的复核。
