# #211 Jev 落地与测试方案全链审计

2026-09-26。审计基线 `16e374ec9f6d12b1a69a5521c279bbc1c529496b`，本地与远端一致。
作者：当前 Codex；独立复核：`independent_architecture_review`、`independent_evidence_review`。
本轮读取设计、十条原则、原始场景、实现、测试器及已存模型记录，另做确定性离线反例。
没有新增 Jev、CPA、OpenRouter 或实验 Codex CLI 调用；没有修改旧账本、冻结、样本或分数。

## 审计结论

**整体存在实质问题。原目标是纠正 Agent 在真实任务中的定框和路由偏差，当前最新实测
主要验证的却是隔离 Codex 对预置坏答案的改写。**真实 Jev 调用与数据交接成立，但这不足以
证明完整②约束式落地，也不足以检验原 Skills／4K 失效模式。

应收回两项过度解释：

1. **“2/6→6/6 证明控制链可靠性改善”不成立。**两个数字来自不同合同与不同消费终点；
   新 runner 保存纠偏和复查文件，未接入旧 Episode 的全部接受/未决规则。
2. **“K1 漏写预算未知证明 Jev 实质错误放行”证据不足。**旧清单的 5/6 保留，但原任务是
   判断现有设备是否必须换，既有材料足以支持“不必换”；没有证明预算未知会翻转该决定。

当前既不能据此确认 Jev 改善了原问题，也不能认定 Jev 对原问题无效。#211 的产品资格
仍未建立。阻止默认推广有依据；仅凭 K1 清单缺项将新来源验证一并阻断，依据不足。
代理题平手也不足以证伪原目标机制。

## 逐项发现

### F1 / P1：测试大幅简化原困难，未测自然定框与持续对话失效

原 Skills 难点是接受第二轮合法范围纠正，同时独立判断“所以只是提示词”是否充分；原显示
场景难点是从竞争的局部真相中识别当前行动者、时点和目标，并给出有用判断。原始案例明确
指出当时并不主要缺事实，而是判断对象被技术概览替代。

新来源生成提示要求短、事实足够、给定有错候选；随后将两条用户消息合在一个 S1 包内。
没有保留实际第一轮助手答复、它形成的判断及后续用户施压。v3.2 每题使用新建的
`codex exec --ephemeral` 上下文，未保留原宿主持有旧框架时的完整条件。六题仍包含范围
修正与局部真相等关系，并非完全无关，但不能代表原困难。配对各条件可以在隔离上下文
恢复同一历史快照；问题是缺少该历史，而非使用隔离上下文本身。

进一步，`build_cases.py` 的 `SPEC` 人工指定 object/goal/scope，观察 runner 又把它们直接
填成 `decision_context`，所有题统一启用 `frame_risk=True`、`execution_impact=True`。
正确识别何时检查、当前对象是什么，本身就是待验证能力，测试却先替系统做掉了。
其中 S1/S3 的 `goal` 甚至来自用户待审推论，显示“给字段”也未必等于有效目标。

**证据：**`entry-assessment/original-scenarios-design/source-packet.md:5–6,45–65`；
`hard-route-v1/source/prompt.txt:3–11`；`hard-route-v1/build_cases.py:19–60,116–121`；
`run_observation_v3.py:100–135,196–199`。

**影响与最小修正：**旧六题保留为组件测试。目标行为测试应从真实原始轮次恢复上下文，保留
助手自己的首答和用户后续范围修正；有效目标由待测路径识别，人工正确标签只用于评分。
先在已暴露历史场景检查当下 Codex 是否还会出现该失效，再预登记新来源，不把原历史弱点
直接假定为当前模型仍有的缺陷。不要为了制造差距筛选评估集中纯 LLM 失败的题。

### F2 / P1：新观察模块尚未接回产品运行时

`observation_assessment` 明确只接受已有候选的 S1；这作为组件边界本身合理。
但 `entry.run()` 仍只有旧三个模式，没有 source-direct 入口；新 runner 直接调用
`obs.assess()` 和独立 Codex CLI。旧 S0 路由仍存在，没有被删除，却没有与新消费串起来。

这与提案“挂在现有 entry/Session/CurrentAgentHost 下”的实施边界不同。默认技能不启用
实验能力是正确隔离；**实验入口也没有集成**才是本项缺口。不能将这个 S1 实验称作整个
using-mindthus 路由方案已落地，或把隔离的新 Codex 实例等同于恢复当前真实任务宿主。

**证据：**`PROPOSAL.md:92`；`observation_assessment.py:1–6,94–98`；
`entry.py:155–180`；`run_observation_v3_host_consumption.py:145–168,239–245`；
`run_observation_v3.py:196–199`。

**最小修正：**接回已有 opt-in entry、Episode 和 CurrentAgentHost，分别验 S0 选路与 S1
纠偏，再验它们在同一真实任务中的交接。沿用已有状态与预算，停止增加平行实验宿主体系。

### F3 / P1：多维发现被无条件压成一个通用标签

`correction_request()` 只要发现 `evidence_decision_fit` 命中，就只发送这一项，未判断
其他发现是否确实同源、同范围或已被覆盖。离线注入三个不同维度、被当前政策标为可处置
的命中，实际得到：

```text
actionable_hits = [explanatory_scope, scope_preservation, evidence_decision_fit]
delivered_findings = [evidence_decision_fit]
```

另外，v3.2 的 `meaning` 是类别的静态定义；例如“遗漏会改变结论的材料”，并没有标出
到底是哪段材料与哪个决定发生关系。原文仍提供给宿主，故不是完全没有信息，但具体定位
主要仍由 Codex 从头完成。这解释了为何补传标签不必然增加判断价值。

**证据：**`observation_assessment.py:239–266`；`tests/test_observation_assessment.py:79`。
当前回归验证了 premise 噪声被移除，没有验证独立 scope/whole 命中是否同时保留。

**最小修正：**保留所有相关非重复发现的处置义务，可合并文字指令，不能自动删除维度。
对已知困难，把问题绑定到具体命题/原文片段/候选关系，使答案能改变明确的后续动作。
Choice 标签本身合法，不要求 Jev 输出自由文本理由，也不恢复一整套繁重图结构。

### F4 / P1：②的约束当前主要停在提示与结果形状

新 host runner 只检查 `disposition`、非空答案和非空异议。独立审阅在实际函数的内存
替身中验证：`objection="我不同意。"`，答案原样返回，也会形成合法 host result。
没有强制异议定位来源，没有独立仲裁解除义务，也没有最终宿主接受复查结论的回执。
`summary.complete` 只由六份 host 文件和六份 recheck 文件是否存在决定。

评估原语允许再次生成 correction_request 并非自身错误。冻结 runner 已按场景强制一次
宿主调用和一次复查；缺口是尚未接入真实任务 Episode 的共同预算、处置和未决状态，
不能把这份隔离脚本的上限当作产品所有合法入口的保证。

**证据：**`run_observation_v3_host_consumption.py:151–168,229–248,274–279`；
`observation_assessment.py:226–234`。对照已有约束：
`route_control.py:336–346`、`current_host.py:99–128`。

**最小修正：**复用原宿主接口；每项必要发现终态为已接受、有据异议解除或未决。语义
正确性由任务结果验证；代码负责绑定、必经步骤、上限与未决保留。补测正确观察被忽略、
错误观察被机械服从、无依据异议、复查仍命中及中断恢复；不能只测六个诚实的 corrected。

### F5 / P1：对照设计写得比实际执行完整，现有数字不能作效果归因

计划列出自然首答、纯 Codex 复核、问题清单、同题 Codex 观察②、Jev①与 Jev②。
实际 v3.2 只跑 Jev 触发的隔离宿主改写，再引用历史纯 Codex 候选纠偏结果；清单条件、
新①/②、同题 Codex B–F 均未运行。两个“5/6”只说明旧清单总分相同，不能隔离问题设计、
多一次推理、后端和消费政策。

旧 2/6 是 relationship 合同的纠偏后继续数；新 6/6 是新观察合同判 continue，且没有旧
宿主接受环节。题组、输入表示、复查语义和终点均变了，不能归因为“控制链可靠性改善”。
哈希审计能确认请求/输出一致，不能补上这组因果对照。

**证据：**`TEST-PLAN.md:15–28,94–106`；`run_observation_v3_clean.py:184–189`；
`hard-route-v1/direct_baseline.py:21–29`；`run_observation_v3_host_consumption.py:77–88,258–280`；
审计前 `RESULT.md:80–82,119–126`。

**最小修正：**正式比较使用同一原始任务、同样方法资料、同样修正机会和一致终点；分别看
纯复核→清单、清单→具体观察、Codex观察→Jev观察、①→②。自然首答也单独保留，回答
实际产品改善多少。五项逻辑控制可分阶段调度，但比较材料和判分需提前冻结。

### F6 / P1：K1 的清单漏项被误当成实质错误

K1 原任务问：现有 4K 已经连续两周满足主要工作，是否现在必须换 5K。v3.2 答案明确说
不必换、保留 5K 锐度优势，并把未来更换条件放在截图清晰度成为门槛及预算上。
这已经回应当前决定；“当前预算未知”没单独成句，不足以证明此答案实质错误。

十条原则要求保留**会改变决定**的未知；`evidence_decision_fit` 题文也使用 material /
task-changing。旧评分却要求逐项复述预算未知。该措辞是测试作者在 `build_cases.py`
写入的操作化要求；当前来源记录没有相应用户原话定位，不能据此证明用户要求每个 4K 回答
都显式写出它，也不能反向断言用户从未提过。即使已经预登记，冻结也
只能防止事后改分，不能证明评分标准有效。

**证据：**`hard-route-v1/build_cases.py:72–73`；`observation_assessment.py:28–53`；
外部 `mindthus-source-direct-v3-host-consumption-v2/results/host/D.json`；
`acceptance-owner-20260925.md:9–12,22–26`。

**最小修正：**旧清单 5/6 和观察 11/12 保持原样，标明衡量的是清单符合。撤回“真实漏检”
和“必须修到显式预算未知才能晋级”的解释。新金标准优先判断行动、依据、条件是否正确；
必要的未知必须说明其为何会改变当前行动。此次不追认一份新的正式 6/6。

### F7 / P2：把辅助不确定变成整项未决的倾向仍在，覆盖与误报试验不足

旧 S0 consume 对任一候选的 M02 中间值/角色不明添加 reasons，主方法即使明确也可能
不提交。M05 伴随关系未知还会清空该事项的已定角色。`.8/.2` 明确是开发阈值，未校准。
三题正式开发结果中 HB 的主/支持角色差异、HC 的 SELA=0.53、HD 的后继=0.63 已显示
这条路径的有效覆盖损失。它们与接口超时、返回格式错误是不同原因。

新路径则把 premise 命中整体降为 advisory；单独命中会交回原负责人，没有静默 PASS，
但实验 runner 没有消费这个分支，也未验证真正的用户前提错误。不能因为五次候选归因误标
就认定该维度整体无用。definition/controller/competition 等旧维度的作用也未做替代验证。

**证据：**`route_control.py:252–293`；`formal-abc-v1/JUDGMENT-COMPARISON.md:9–13`；
`observation_assessment.py:70–85,186–210`；`TEST-PLAN.md:76–80`。

**最小修正：**先区分会阻止当前动作的未知与可保留的辅助不确定，再用主方法已明确、辅助
未知、真实冲突、有效用户前提/误报等对照验证。不能为追放行率直接降低阈值或统一降级发现。

### F8 / P2：将 K1 清单缺项升级后，把新来源验证与默认推广一并阻断

计划原文给 D 的职责是排除接口/消费缺陷；N 才检验自然首答与新来源的增益。完整计划
本身没有“N 必须先证明收益才能运行 N”的形式循环，本项问题在实际解释和执行。
后来 RESULT 将 K1 清单问题升级为实质错误放行，并据此不启动 N。若明确存在未修控制
缺口，暂缓 N 是合理的；K1 的争议项单独不足以支持这个决定。此外，报告中的旧题平手
不能证伪“原困难中的边际作用”；这不等于原报告明确把平手单独设成了停止门。
需要分开工程可运行、是否值得试验、是否可以推广三个决定。

此外，运行脚本硬编码个人目录、旧试验文件和 CLI 路径，v3.2 还通过修改父模块 ROOT
组合执行；整个 HEAD 绑定使新文档提交后也无法直接用当前 checkout 执行旧 report 命令。
旧账本绝对路径应保留，但新执行器不应必须依赖作者机器和所有历史试验产物。

**证据：**`TEST-PLAN.md:38,68,104–110`；审计前 `RESULT.md:21–23,145–150`；
`run_observation_v3.py:34–44`；`run_observation_v3_host_consumption_v2.py:20–55`。

**最小修正：**工程门只验目标入口、处置义务和错误路径；下一小批应能回答原目标机制，
不要求先在无差距的代理题里制造胜利。默认采用仍等待有效收益证据。可复用代码接入既有
运行时，机器配置与不可变历史记录分离；不要再复制 freeze/host/recovery 三套 runner。

## 已做的离线核对及其边界

主操作者用 FixtureProvider 在临时目录重现三项行为，零模型请求：

| 输入 | 观测 | 解释 |
| --- | --- | --- |
| scope、whole、evidence 三个可处置命中 | 宿主仅收到 evidence finding | 确认具名义务丢失；不证明真实 Jev 必定产生该组合 |
| frame_risk=False | continue_original，四题均 not_evaluated | 这是合法跳过；说明只测强制开启时不能证明激活覆盖 |
| decision_context 换成原文不存在的对象/目标/范围 | 编译正常，原样进入 State | 引用形状/hash 不证明上游定框正确；需保留上游推断身份及测试 |

架构审阅另在内存替身中重现空泛异议被保存、S0/source-direct entry 拒绝、以及方法名单
正确但产物只有“收到。”也可通过机械回执检查。最后一项是代码已经声明的证据边界，
不是要求代码能自动证明方法质量。

本轮没有运行整套工程回归：未改运行代码，现有绿色测试不回答上述实验有效性问题。
279 项通过仍是 2026-09-25 对应实现的历史事实。

## 十条原则核对

| 原则 | 当前审计 |
| --- | --- |
| 1 从实际后果倒推 | 偏离：方法与定框收益被代理成坏答改写/放行 |
| 2 足够相关 State | 有原文绑定；真实多轮与目标识别被人工预处理替代 |
| 3 连贯语义维度 | 窄维度合法；广义 evidence 一项消解多个独立发现尚无依据 |
| 4 自描述问题合同 | 题文与版本具备；激活、对象定位、消费终点测试缺失 |
| 5 定点纠偏 | 真正改写已发生；具名对象和全部处置义务仍未闭合 |
| 6 合批与依赖 | 合批及旧后继定点复查保留；不提出计费/独立性收益 |
| 7 类型与未知 | 单题隔离保留；advisory/unknown 对整个动作的影响仍需验证 |
| 8 消费与权责 | 旧 Episode 有可复用控制；新路径尚未接回，异议规则偏弱 |
| 9 边际价值 | 关键对照、自然首答、误报对实际宿主的影响未测 |
| 10 有界复用 | 单批冻结有价值；反复新 runner 的成本未转换成目标行为证据 |

## 最小纠正顺序

1. **先纠正测什么。**原历史 Skills／4K 回归用于复现失效，保持原轮次和判断压力；新来源
   用于价值评估。先记录当前纯 Codex 实际表现，不能假定旧模型的错误仍然存在。
2. **明确 Jev 到底补哪项判断。**每个问题给出观察对象、可区分关系和动作影响；保留简单
   机制确实充分、合法范围收窄及事实真不足的反例。删除没有独立作用的题，保留非重复发现。
3. **补原有运行时接线。**新观察接回 entry/Episode/CurrentAgentHost，落实处理/有据异议/
   未决三个终点和一次纠偏复查。先补相关离线错误路径，避免另造平台。
4. **做可归因的小批。**相同来源和资料对齐纯复核、清单、Codex观察②、Jev①、Jev②；
   使用实际消费后的产物评分。预先安排阶段和预算；不按获胜题临时选择后续对照。
5. **按任务决定判分。**语义误判、无谓阻断、误改和必要未知分开；清单细节单列。整体
   不劣且 Skills／4K 有重复实质改善，才讨论默认扩散；小批平手只否定该批可见增益。

本文件完成的是全链诊断与最小修正清单，未实施上述接线或宣称新测试已通过。

撤回将 K1 清单 partial 直接升级为实质错误放行的说法。
