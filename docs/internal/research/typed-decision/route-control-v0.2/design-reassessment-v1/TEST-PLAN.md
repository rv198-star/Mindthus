# #211 新方案验证计划

版本 1，2026-09-25。**只完成了 D 的原文直读最小切片；完整五条件和 N 尚未执行。**实测见 [RESULT](RESULT.md)；旧六题/v1.2 不能冒充新保留集结果。本计划冻结完整比较逻辑；N 正式调用前仍需锁定题文、源材料、逐题金标准、脚本与实际预算身份。

## 要回答的三个问题

1. 丰富而有区分力的问题，是否比“直接再看一次”更能发现遗漏？
2. 同样的问题与消费方式，Jev 相比当前 Codex 的观察是否带来任务收益？
3. 同样的 Jev 观察，②约束式是否比①建议式更少漏用，同时能处理误报？

分开检验，避免把更好的提示、更多次宿主推理、模型更换和强制流程混成一个效果。全部使用当前 Codex 宿主、官方 TypeSafe `jev-1.13.0`；不调用 CPA/OpenRouter。

## 对照条件：中文名称，不用 A/B 命名两种方式

| 条件 | 宿主输入/操作 | 隔离的差别 |
| --- | --- | --- |
| 原生首答（保留） | 原任务和相同可用方法资料，自然生成短路由/候选 | 真实发生的遗漏；不先塞给所有模型同一个故意坏答 |
| 纯 Codex 复核 | 原文＋自己的冻结首答，允许一次复核/修正 | 相同修正机会的主产品基线 |
| 问题清单 | 上述输入＋未填答案的同一问题组，允许一次复核/修正 | 仅问题设计的提醒效应 |
| Codex 观察② | 隔离 Codex 回答同一问题组；按②由同款宿主处理 | 与 Jev 观察②组成同图/同合同的判断器对照 |
| Jev 观察① | Jev 观察＋原文，宿主自由采用建议 | ①建议式 |
| Jev 观察② | 同一份 Jev 观察＋原文，按新合同处理/异议并落实路由 | ②约束式 |

Skills/4K 的 S1 切片以原生首答作为同一源的共享、不可变起点。每个后续条件以隔离的新上下文恢复相同任务，不互看其他条件产物、原始模型身份或期望答案。宿主版本、思考档位、来源材料、允许工具和输出限额一致并记录实际可观察身份；不能把配置声明当服务端证明。①/②有同样的修正次数和输出额度。所有当前宿主的实际工作与消费结果计入记录。

**仲裁机会对齐：**五个条件在首次处理后都可对有原文引用、会改变任务的未决争议请求一次隔离上下文复核，包括纯 Codex 与问题清单条件；未请求则不用槽位。它不代替外部取证，不允许无限重写。评阅同时记录“仲裁前”主比较与“仲裁后”整包效果，以及实际触发次数。①/②比较不能把多获得的一次推理所带来的改善全归因于约束政策。②的初始路由未决当前没有仲裁入口，仍记未决；对应机会未使用须注明，不假装接口已接通。此公平性约定在实验适配器实现并验证后才可进入实时 N。

“纯 Codex 复核”回答产品是否更好；“Codex 观察②”回答同图判断器是否更好；二者均需报告。原生首答不能代替同图基线，主产品对照也不再以“完成复杂 schema”代表纯 LLM 原本的能力。旧 B/C 名称只在引用历史结果时使用。

## 两个切片，先诊断后新样本

### D：已暴露开发回归，不取得资格

沿用 S1/S3/K3 的坏候选/已纠偏文本，补 S2 的简单解释充分、K1 的预算未知与 K2 的购前价格条件。覆盖：原文有事实但提案缺槽、原文真的缺事实、辅助 unknown、必要未知、观察噪声、合理异议、错误异议、源版本变化、候选已纠正但用户原话未变。

这里先做确定性消费与引用失效测试，注入观察要明确标作 fixture。两项既有根因修复直接跑相关回归，不重新实现。修复后只需解决具体剩余风险，不为文档改动重跑全仓。

开发实测最多取六个已暴露目标，对 Jev/普通 Codex 同题各做一次观测＋一次必要局部复查。每个后端每目标最多一次宿主修正、一次确需的隔离仲裁：Jev≤12；Codex 观察≤12、宿主修正≤12、仲裁≤12，共 Codex≤36。独立审阅六个目标的匿名结果最多两次整包审阅＋一次争议复评，共≤3次 Codex 审阅。目的是排除接口/消费缺陷，不将通过率当泛化证据。D 未满足正确结果能通过、错误结果仍会被处理、依赖与权限不被删等条件，先修实现，暂不开新来源。

仲裁后最多再有一次原宿主接收/执行回执，D 另封顶 12 次，N 在下表封顶 60 次。沿用已有两次 execution 尝试的上限；不能重置一次具名 correction 和一次相关 recheck 的额度。若仲裁后还需要新的纠偏循环，则以未决结束，不追绿。复查结果对相应①/②宿主同样可见；必要发现的终点只能是已按合同接受、经有据异议解除、或未决。①可不采用建议，但必须作为建议未采用及最终结果计分，不能隐去复查发现。仲裁意见存在不代表原宿主已接收：只有确有后续回执才计“仲裁后产物”。

### N：第一批新来源配对，12 个来源家族

- Skills 4 个、4K/显示任务 4 个、普通方法路由 4 个。每类至少两个支持不同正确方向的独立来源家族；有简单机制充分、无需方法/直接处理、复杂方法真实依赖的反向控制。
- 先抽取原始任务，再生成自然首答。**不能只收集纯 Codex 首答出错的题。**同一来源的改写/第二轮/多个候选只计一个来源家族。
- 收集者在结果出现前登记来源边界、场景分层、可接受路线集合及重大错误；不能用 Jev 题文倒推原文。输入作者、题目作者与独立结果评阅角色分离。
- 若只能取得 AI 合成材料，完整运行仍只算开发信号，不标天然真实场景或保留集资格。若大量原生首答均正确，报告天花板效应；不事后造更坏候选谋求差距。
- 覆盖自然正确、实质错误、条件性可用三种候选；自然分布不足部分用独立的受控噪声诊断补充，结果单列，不混入产品收益分母。

**S1（8 个 Skills/4K 来源）：**完整运行上表五个复核条件并保留原生首答；Jev ①/②共享初始观察，宿主生成不同候选后不能共享候选绑定的复查。

**S0（4 个普通方法路由来源）：**只提供原任务、原文与同样可用的方法资料，没有预先生成的框架/路由/候选。纯 Codex 直接决定处理并执行；问题清单条件另见未填写问题；其余三条件见对应观察再处理。各条件都有一次宿主处理与相同的有限争议复核机会。这里没有“共享首答后复核”；直接判断器问题从同一 S0 构造，不能用别条件产物补全输入。新产物接受若需要后继判断，最多用该条件的相关复查槽位。S0/S1 两层单列结果，不合并成一个语义准确率；覆盖任一层不足均不宣布整体资格。

| N：Jev 相关复查 | 24 | ①/②各最多一次；没变化/无需复查则不调用 |
| N：Codex 观察 | 24 | 初始 12＋修正后相关复查最多 12 |

| N：仲裁后宿主接收/执行 | 60 | 每次实际仲裁后最多一次；没有回执就不记作已消费产物 |
| N：独立匿名结果评阅 | 36 | 每来源两份独立评分，必要时第三份复评；每次同时看该来源所有匿名条件 |

因此 N 的主上限为 36 次 Jev＋248 次 Codex（含结果评阅及仲裁后宿主回执）；D 的主上限为 12 次 Jev＋51 次 Codex（同口径）。这是**预算上限，不是预定跑满数量**。审计工作不算宿主成功或免费模型工作。各阶段至多另预留 2 次 Jev 和 2 次 Codex 技术补充请求，每个失效请求最多补一次；超过上限如实结束为部分完成。D＋N 含技术预留总上限为 **52 次 Jev＋303 次 Codex**。多数无争议事项不使用仲裁及其接收额度；如果 D 已证伪新机制，N 不启动。本表是后续冻结所需的上限草案，不自动授权执行或预定跑满。

D 与 N 不共用资格；任何未知外部 intent 先审计完成情况，不换根目录重发。环境超时若已有完整终态先恢复原结果；确无完成证据且原调用不再在途时，才按预留额度做同请求的独立补充对照，不覆盖首试。不得为了模型答错使用技术重试。正式材料取得/合成若需模型调用，不包含在以上预算，必须在输入来源冻结时另列硬上限后才能执行，不能作为隐藏准备成本。

路由 API、题组准备/绑定、宿主读取观察、修正、复查、仲裁分别计调用与耗时；主要性能比较只看完整路由模块，完整任务耗时另列。费用按 Owner 暂计 0，同时保留实际未知与 token。不能由一份 State 推导服务商只收一次 State。

## 最小消融与受控误报

不跑所有题目组合。先在 D 固定一个最有理由的分组消融：**直接方法/处理选择** vs **同样直接题＋关系区分题**，两组都含必要权限和依赖检查。查看加入的关系观察是否改变了正确处理；已知依赖不得为消融去掉安全约束。

N 全量运行的“问题清单”条件本身就是必要消融。如果 D 显示某关系组值得进一步检验，N 在打开来源前固定至多一个删组条件和额外预算；不能看过哪个来源 Jev 赢后才决定删哪一题。没有额外冻结时本批不执行删组条件，不能宣称已完成因果归因。

受控误报只作工程/宿主诊断：向已正确候选注入错误的局部观察，向已有关键缺口注入过于乐观的观察，检查②是否会机械改坏、是否有依据地异议，及①是否会无声忽略正确发现。注入来源明确标记且盲于执行宿主；不记作 Jev 真实准确率。复查后错误仍在或异议未解决，报告未决，不能为了结束标通过。

## 评分与证伪

独立评阅者只看原任务、事前验收点、匿名路由与产物；不看条件名、模型名和作者评价。匿名化保留方法实际使用/回执所需内容，不隐藏会改变判断的事实。先独立评分再揭盲；评阅争议保留原分歧，由另一上下文核对，不挑有利评分。

每条件全分母报告：

1. **实际有效决定数**（可等效路线）、错路由、未决、技术失败、回退；按来源家族配对 win/tie/loss。
2. **最终结果有效数**与严重错误（目标/时点/事实/权限/必要依赖）；回退救回单列，不能算 Jev 路由成功。
3. 发现→具名处理→宿主采用→结果改善的具体变化链。合理否定误报也可改善；增加方法名、格式更齐或更啰嗦无效。
4. 对正确候选的误报、不必要改写与伤害；真实错误的漏检；因未知而不必要阻断；必要未知是否被错误放行。
5. ①遗漏正确观察的次数、②固化错误观察的次数，以及各自有效覆盖。

**事前主比较固定为 Jev 观察②**，①作为消费方式对照，不在揭盲后挑更高者作为本批主成功结论。配对差异固定如下：

| 比较 | 归因范围 |
| --- | --- |
| 问题清单 vs 纯 Codex 复核/直接处理 | 问题设计的提醒效应 |
| Jev 观察② vs Codex 观察② | 同图后端差异，包含真实未决/失败 |
| Jev 观察② vs Jev 观察① | 消费政策效果，分别公布仲裁前与整包结果 |
| Jev 观察② vs 纯 Codex 复核/直接处理 | 主产品净效果；S0/S1 分层 |
| Jev 观察② vs 问题清单 | Jev 观察相对于只给好问题的边际效果 |

**开发晋级条件：**Jev 观察②相对同图与主产品两个基线均没有观察到有效覆盖降低或新增严重错误；Skills/4K 的至少两个独立来源家族相对**纯 Codex 复核**重复出现实质 win，同时公布相对清单和同图 Codex 的差异。这两个来源可来自同一场景类别；另一场景类别（Skills 或 4K）及反向控制不得出现抵销退化。只有当 Jev 观察②还优于问题清单，才可提出 Jev 观察带来边际收益的开发信号；若与 Codex 观察②持平，只支持题组/观察路径有用，不支持 Jev 特有准确率优势。逐例公布反例，不以相加分数抵消严重错误。12 个来源只给方向性结果，不能宣称统计非劣或正式资格。

如果全为 tie，结论为“未观察到判断增益”；如果问题清单与 Jev 同幅改善或已足以解释其改善，结论为“题组设计有价值，Jev 增量未证实”；如果只有同图 Jev 更快，单列路由工程收益；若①优于②，作为修改下一版主候选的证据，不能把本批预选②追认成成功。若下一阶段要作可推广非劣声明，必须另行在未打开的更广来源上冻结样本量、差值界与统计办法。

## 停止与版本纪律

本轮设计审计完成不等于 D/N 已跑。来源/金标准/题文/政策/宿主改变后建立新版本；暴露的来源降为开发题，绝不改旧记录。最多一次按具名缺陷修订新设计再回归；没有新的收益机制就停止堆题或扩编排。默认技能采用仍等待真实增益证据。
