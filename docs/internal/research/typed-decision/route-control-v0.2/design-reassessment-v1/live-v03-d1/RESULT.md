## 匿名评阅及限制

E/F 各两个独立 Codex 上下文；分歧各补一个，最多三位，不按条件名评分。原始评分和映射保存在证据包。
评阅者型号与实验宿主相同，不是跨模型或人工裁决。多个产物同包，重复文本可被识别，不能当独立样本数。

E 三位都认可自然原答、Jev 原答及 Codex 改稿，均认为完整路由留空是不必要阻断。
其中一位认为改稿增加了不必要保留，另外两位未报此问题；保留全部意见，不把修改次数当成增益。
F 三位均认可共同候选正文。完整路由两位判不必要阻断、一位判未决；第三位部分理由引用同包已有候选，
该候选不是完整路由实际生成的，因而不能据这句话证明完整路径已经具备该产物。多数票不替代事实。

三位 F 评阅者均按“接受原候选”的意图认可清单分支，未识别实际答案版本绑定错误。
因此报告按账本核验将其列为无效，不能照抄盲评分数宣称五条件全通过。

另一个归因限制：宿主请求有完整 `loaded_methods`，S1 检查 State 的 `canonical_rules` 只有四份原语摘录，
没有收到宿主的完整 Skill 正文。Jev/Codex 初检的 State 与题文确实相同，但检查器对宿主材料的覆盖不完整。
不能将 E 的“没有定义/实现依据”自动判成 Jev 漏检，也不能将一般 Skill 文件当成用户所指全部 Skills 的事实证明。

## 技术失败、重试与计量

- d1 的两次自然候选调用因实验驱动将 JSON Schema 封成账本 envelope，被 API 拒绝；未产出答案。
  旧驱动把 error 事件误标为 invalid_tool_use，原记录保留；解释按实际 schema 错误。CLI 内部重试仍保留在本地事件流。
- d2 显式继承 d1 的预算与已运行 full-E。只补两次自然候选技术失败，不重跑 full-E 的不利 S0。
- F 纯 Codex 的一次方法名称格式错误，在同一真实 session 中仅改方法 ID；正文和其他语义字段逐字不变，耗时/用量累加。
- F 第二评阅曾因两个进程同时写匿名包而在模型调用前失败；包落盘后再启动，没有重复模型请求。
- Codex CLI 共启动 31 次：29 次完成、2 次 schema 技术失败；包括 6 次匿名评阅及一次方法 ID 格式补充。CLI 内部网络重试不虚称为独立候选，父任务两次手动组织另计。
- 本机 CLI 配置 `gpt-6-sol`、`xhigh`；服务端模型身份未另行确认。CPA/OpenRouter 调用为 0。
- 费用按用户要求暂计 0；实际金额未知。Jev 只按物理请求汇总，不能累加两个共享初检分支的逻辑账本用量。
- Jev 请求约 1.5–5.0 秒；Codex CLI 通常数十至百余秒，但含启动、上下文与服务延迟，不能据此宣布模型推理快多少倍。
  只报告路由模块调用，不外推整个场景总耗时。完整路径的父任务手动组织用量未知，账本保留保守预算占用。
