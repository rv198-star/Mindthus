## 2. 模型差异在哪些地方被测试结构遮住

### 2.1 共用的早期返回会遮住已识别的错误

**测量：**K2 的 B/C 初检都给 `alignment.F0=situation_substituted`、`local_transfer.F0.E0=local_overreach`。但都先给 `q0=material_omission`，因此只有 q0 被消费；后面的错误识别没有触发纠偏。S2/B 也给 `definition.F0=unsupported_alternative`，却先因 q0 返回。S3/B 同时识别过度外推与薄弱定义，但 `joint.F0=unresolved` 使整体返回。

**推断：**“没有最终可继续结果”不能直接译成“模型没有识别候选错误”。当前 q0 检查的是作者结构化提案，原始材料其实仍在 State；作者遗漏一个投影字段会造成两后端都失败。它可能是合理的提案质量门，也可能过度截断当前可完成的判断，须按真实消费后果单独审查。简单删除 q0 同样没有现成证据支持：错误投影也可能伤害后续判断。

精确证据：`hard-route-v1/build_cases.py:41–54,101–115`；
`experiments/typed_decision/relationship_assessment.py:311–337`；
外部 `mindthus-hard-route-v1/codex-calls/S2-B-judge-1/last-message.txt`；
K2/B、K2/C、S3/B 的原始矩阵路径列在末尾。

### 2.2 旧复查问题同时误伤普通 LLM 和 Jev

**测量：**S1 的 C 纠偏文本明确否定零遗漏保证，旧复查仍报 `local_overreach`；恢复后的 S1/B 纠偏文本同样明确否定该结论，普通 Codex 旧复查仍报同值。题目的 premise/conclusion 引用仍是 U2 中的原始推论。K3/C 已明确回答“没切中”，旧消费仍因 `conditional_decision + verdict_with_basis` 强制 `state_conditions`。

**推断：**这是题目绑定和消费后果的共同缺陷证据，不是 Jev 专属失败证据。v1.2 定点修改合理地针对了已观察错配，但同时变更了 local-transfer 问法、definition 问法和 explanation 的消费。六次新观测不能分离三处改动的边际贡献，更不能证明后端差距扩大或缩小。

精确证据：`hard-route-v1/RELATIONSHIP-V12.md:5–14`；
`hard-route-v1/TIMEOUT-RECOVERY.md:5–9`；
外部 `mindthus-hard-route-v1/timeout-recovery-v1/results/S1.json`；
`mindthus-hard-route-v12-probe/calls/{S1,S3,K3}/outcome.json`。

### 2.3 最终文案把路由失败的后果补回，但没有补回路由贡献

**测量：**正式三题 C 的完整答复全来自对原任务的独立 Codex 回退；HD/C 匿名优选文本也来自回退。`review.py:26–28` 明确选择这些文本，评分提示只评匿名文本质量。结果文档对此已有披露。

**推断：**最终文本可用是产品保护措施有效的证据，但在这种测试结构下，强宿主能把失败路由兜住，使最终质量趋同。路由贡献必须看路由实际改变了什么、实际被谁读取和消费，不能用回退后的质量抵扣有效决策覆盖损失。这是评分对象的限制，不能据此指控现有结果伪报通过；现有报告恰已判定未通过。

### 2.4 没有被遮住的实测差异仍应保留

- 正式 HB/HC 中 B 确实提交而 C 未决。HB 是 WAE 有适用性但没有主方法；HC 有适用性与关系未决；不能把这些差异统统归于过长 prompt 或 Score 错误。
- S02 Score 只作为 `guidance_only` attention 使用（`route_control.py:295–301`）；修正其合同错误不自动解除 HB/HC 的主路由未决。
- hard-route 超时恢复后 C 的继续数仍多一例，但 C/K1 的已放行文本没有满足预算未知的冻结要求。因此“多放行”自身既可能是更有用，也可能是更宽松，必须经过任务标准核对。
- Jev 请求显著短于 Codex CLI 结构化判断请求，是本批可观察结果。它同时包含后端和服务路径差异；不等于抽象模型计算速度，也不证明全任务更快、合批省费或判断更准。

## 4. 新设计比较必须保留的对照

**建议：**先锁定一次比较要回答的因果问题：是“换 Jev 是否有增益”，还是“改变合同/消费是否有增益”。两者可以同批研究，但必须有各自参照；不能同时换后端、提案和题组后，将全部变化归给 Jev。

| 对照 | 必须固定的部分 | 要回答的问题 |
| --- | --- | --- |
| B-new / C-new | 新版本同 State、同原始材料、同问题合同、同提案、同消费与宿主；只替换普通 LLM/Jev 判断后端 | 新设计下 Jev 的边际价值；这是 Owner 主基线要求 |
| A 原生当前 Agent | 同原始任务、同宿主能力、同版本原生 skill，检查实际读取；允许原生直接完成任务 | 新结构相对原本产品有没有实际增益或退化 |
| 直接候选批改 | 同 S1 候选及原始任务，仅要求普通 Agent 直接判定和修正；事前冻结 | 结构化多题的收益是否超过一次普通候选审查。若新设计只做 S0 路由，该对照不适用 |
| 旧/新合同配对 | 同一个后端、同一批新输入、同宿主；清楚标出改动部分 | 改进来自合同/消费，还是来自后端。可先用开发集定位，不必把每种消融都扩大成全面运行 |

A 和直接候选批改承担不同责任，不能以其中一个替掉另一个，也不必在不适用阶段强制两者同时运行。所有臂在新来源打开前冻结；旧失败案例保留作回归，不能充当新来源的独立重复。

### 最小消融

1. **去掉新增题组/语义检查，保留其余路径。**看有效决策、错误修正、误纠偏、阻断和调用量的变化。若整体设计只剩多问一轮，应与一次直接候选审查比较。没有明确消费用途的题无需为了消融而上线。
2. **固定同一模型观测，只改变消费规则。**对语义未变的观测可离线重放，隔离全局返回、解释/决策混用等政策影响；问题对象或问法变了就不能把旧回答当新合同答案。对 K3 类型的 explanation 消费，这比新模型重采样更能定位因果。
3. **固定问题和消费，隔离材料投影。**若新设计声称修复整理器问题，在开发集比较实际整理器产出的提案与经独立材料核验的完整提案；记录省略、错误绑定和更宽输入的代价。手工完整提案是诊断上界，不能冒充产品路径。

最小集合按新设计实际改动选择；不是要求为每题建立完整组合矩阵。若只改一个消费条件，优先做第 2 项及相邻反例；若新增整理与题组，才需要第 1、3 项。选择须在看新结果前固定。

## 5. 新验收应如何落到任务结果

**建议，沿用 Owner 已给目标，不另设未经确认的通过数字：**

- 原始任务是主分母；同一来源的多候选、改写和多轮纠偏是相关观测，不能算独立家族。失败、未决、回退、合法后继和技术失败全部留下。
- 预先列出可接受的不同主判断/行动集合、允许条件化或补证据的情况、必须保留的事实与权限、会改变任务方向的严重错误。不能把一个偏好方法名当唯一真值。
- 以相同事实构造或收集：确实错误的候选、已充分正确的候选、合法局部范围、局部机制确实充分的反例、真实缺材料、有效用户偏好。S2/K2 的反向任务语义必须保留，但要再包含候选本来就正确的版本。
- 对原生 A 与新图 B/C 先保留各自未经帮助的原输出；同一 S1 候选的后端比较则必须共享同一个候选。这样才能分别回答真实首答是否失误、检查是否发现、修正是否成功。
- 分开记录：模型原始局部判断、消费器动作、被宿主读取/接受的路由、原答与修正后质量、回退产物。`continue_original` 只有通过任务验收才计为有效决策；单纯返回原责任方也不能算正确拒绝了错误候选。
- 盲评原始任务和最终答复之外，还要有可复核的路由贡献审计；至少让评阅者看不到臂名，说明 AI/人工身份。复核分歧时不得在已打开保留集上改题、改可接受答案或只挑胜例。
- 难题增益必须出现“普通路径在关键判断上失误，新增判断改变宿主处理且结果更好”的完整证据链；同时检查正确候选被误伤和另一家族退化。多个新独立来源复现才升级为优化候选；小样本结果保持开发信号身份。
- 费用按 Owner 暂计 0、实际账单 unknown；路由请求延迟另列，报告全部合法复查/失败和样本分布。不得让速度抵消判断质量退化，也不把暂计 0 宣称节费。
- 统计非劣需另行事前确定容许差、样本来源、样本量依据和统计办法；本报告不凭 3/6 之类点估计补发非劣资格。
