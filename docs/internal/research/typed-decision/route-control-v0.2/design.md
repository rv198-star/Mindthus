# using-mindthus：轻量路由控制与定点纠偏 v0.2

状态：供实现的设计基线；尚未实现、未新增业务实测、默认不启用。父版本：`bba72569f15280e0b96353cec9f37353f9c875cb`；关联 #211。用户本轮确定方向并要求一次简短独立评审。参数可在开发实测调整，控制权边界不因一次模型输出静默改变。

## 1. 核心决议

**Jev 等可替换的快速模型提供多维观察和有边界的路由判断；薄策略层提交并落实常规路由；LLM 执行方法、形成任务结论，只对具名问题提出局部异议。**

这里的“微调”指已有框架/回答的定点修正，不是训练模型权重。Skills／4K 是通用纠偏的已暴露回归案例，不是写入生产路由的场景特判。

不同问题像不同成像角度：可以有噪声、有分歧，但不得按题数投票或把重复观察当独立证据。原生分布、同题重复、不同问题组是三种材料；首版不增加重复采样器。观察丰富不等于串行关卡多。

区分两张图：观察 DAG 按所需输入组织问题；行动 DAG 是有限方法步骤及具体产物关系。已确定关系由代码落实；关系未明时只在对应范围使用例外仲裁，不要求 LLM 每轮自由重判全部路由。

## 2. 控制权与生效范围

| 责任方 | 负责 | 不负责 |
|---|---|---|
| 原宿主/用户 | 原文、目标、权限、工具许可、任务预算和可观察执行接口 | 用模型置信度替代真实授权 |
| LLM（设计/整理） | 必要的少量事项、候选解释或产物关系提案；优先复用现有短计划 | 预先填入“正确方法”“事实真值”以冒充 Jev 判断 |
| 快速模型 | Noul/Choice/Score 观察；方法适用、职责和有需要的关系判断 | 新造证据、执行工具、签发任务完成或人类权限 |
| 薄策略层 | 现有政策下提交 route commitment、加载合同、安排就绪步骤、保存版本/回执 | 从特征组合重写方法定义、搜索任意最优业务计划 |
| LLM（执行） | 运用指定方法、保留来源边界、给出真实结论；必要时具名异议 | 无声换方法、以“更自然”或“综合看”撤销已生效路由 |

路由承诺仅约束“如何处理当前事项”，不预定事实答案。高风险行为仍走宿主已有授权；本设计不是操作系统安全沙箱。不同子问题可以各有主方法；同一结论范围才需要唯一主导。TPlan 保存状态，语义判断仍由对应方法承担。

本版本替换 v0.1 中“常规路由由原 LLM 自由组合决定”的默认消费方式；不改变八方法正式含义、原十条原则的来源/权限边界，亦不废弃19个问题模板。旧设计、失败和实测均原样保留。

## 3. 精简后的问题合同使用

完整题文/选项/刻度继承 `../mainline-composition-v0.1/questions.json`；八方法命题绑定继承 `method-bindings.json`，完整正式方法合同优先。`profile.json` 明确本次替换的激活、前提和消费，不会让旧“交 LLM 自由处理”的文字重新夺回常规路由权。运行不得同时加载两版互相冲突的政策。

| 问题 | 何时调用 | 新消费结果 |
|---|---|---|
| M02 / Noul | 需要方法且完整合同已具备；对每个必要候选分别问 | 保留可同时成立的候选；不强迫八选一 |
| M03 / Choice | 与 M02 同批，基于原任务/已有处理方式 | primary_candidate、support、constraint、support_and_constraint 进入对应职责；covered 核对已有覆盖，no_contribution 不启动 |
| S02 / Score | 多个未决事项或后果会改变关注深度；信息不足才追加 S01 | 将影响等级和分布作为 attention 提交给方法执行者，影响关注/分析深度而非方法去留；不能覆盖权限、主辅或前置依赖 |
| G03 / G05 | 当前处理模式未明／出现方法名且实际用途需判断 | direct、acquire、reuse、judge 分流；显式调用保留适用核查，审查对象不夺走当前主方法 |
| G01 / G02 | 新增会影响路由的语义提案／真正多事项清单 | 检查表示与覆盖；原始文档直接可用则不强造提案；错误候选被忠实描述不算表示错误 |
| R02 / R03 | 确有同范围主方法竞争，且正式条款没有直接解决 | R02确认范围；R03确定主导，其他保留合法支持；有前提的题可合批，前提不成立不消费 |
| R01 / R04 | 已有产物拟复用／存在具名产物依赖 | 验证同对象用途；区分开始前与承诺前依赖，不从方法名惯例造边 |
| M01 / M04 / M05 | 缺候选全文／需要解释真实开始缺口／伴随条件未确定 | 取必要材料；伴随条款触发后必须加载，不因成本或不是显式调用而省略 |
| G04 / V01–V03 | 真实义务范围争议或新方案有具体漏项、重复、越权疑点 | 只处理对应问题；不是默认的全套路由审计 |

题组是观察工具箱，不是每轮全量扫描。M03 的角色问题仍直接引用当前对象和正式方法，不退化为若干自编特征 AND/OR。相同快照下已有有效结果直接复用；新材料才产生新版本。按需省去的G03/R02/S01/M05等，其前提只可由带来源、责任人与有效版本的既有判断满足，明确标作existing_resolution而非伪造Jev答案；没有既有判断就保持未决。候选回忆不足时可用八方法来源卡发现候选，溢出/无匹配如实交回原路径，不能静默截成唯一方法。

## 4. 薄策略如何提交路由

复用现有引用、身份、模型/合同版本、来源和 episode 锁。已经明确的低风险直接工作保持原路径；语义有疑问时才用 G03。采用以下顺序，不引入自由总结型 LLM 路由节点：

1. 保留真实权限、已知义务和有效用户范围；仅使用材料/前提相容的观察。使用原文直视图或已通过来源核对的提案，不能把未审的模型摘要当原文。
2. M02 支持开始且 M03 有非重复贡献时，纳入候选职责。只有一个主候选即提交其主角色；相同范围多个主候选先用正式职责条款，再用 R03；不同事项分别提交。辅助角色不能因为没有主导结论就被删掉。
3. M03=covered 必须有可引用的有效产物或明确已覆盖的当前处理责任；复用核对没有成立时保留该项未决，不因模型口头说 covered 而取消必要判断。只有辅助角色、无主候选且无法直接完成时，维持该事项 unresolved，而非编造总主方法。
4. 伴随读取按正式条款落实；已读合同有相同版本回执可复用。读取与重新做完整方法分析不同。边以 producer、具体 artifact、consumer、begin/commit/condition 描述；无具体关系则不造先后。依赖环只交回相关分量，不随机删边。
5. 输出 route commitment。原宿主实际装载相应材料、调用执行入口，并固定版本；执行者不再被要求重新选方法。正常材料齐备时目标是一批混合判断，不保证所有复杂任务均一次调用。

### 承诺对象（使用现有 trace，不另建平台）

`route_id + revision + input/contract/engine/policy hashes + per_issue(mode, primary, supports, constraints, attention) + mandatory_reads + artifact_edges + reuse + unresolved + source_observations`。

这不是终局事实认证或执行回执。模式分别为 committed、partial、acquire、direct、delegated_unresolved。partial 可包含已提交独立事项；被交回原 LLM 的范围明确标 delegated_unresolved，不冒称 Jev 成功路由。高概率与高影响本身不能建立权限。

### 数值是试用参数，不是事实保证

沿用 v0.1 的 Noul 起始候选：p≥0.8 支持开始，p≤0.2 不据此开始，中间保持待定；完整材料和 Choice 无冲突也是条件。它们仅用于低风险、可回退的 opt-in 开发，不是经过校准的生产安全线。Choice 使用合法类别；unclear/非ok或结果相互矛盾只影响相应事项。Score保留原值/分布为注意力提示，不新增tail-mass硬门、自动深度预算或总分排名。原生分布缺失保持unknown，不造概率。该参数及需要进一步判断的比例进入首批开发观察，而非让统计证明挡住试用。

## 5. 具名异议：可纠错，不能无声覆盖

执行者遇到真实问题，提交一个最小 objection：`route_id/revision、affected_issue_or_step、kind、original_refs、claimed_conflict、requested_change`。kind 可为 source_or_scope、method_boundary、new_fact、dependency、permission。无需长论证，不要求为轻微措辞和合理深度差异提异议。

- 代码可核对的失效/缺失读取/权限变化：保护相关动作并修复，预算内正常读取不必另找模型裁判。新事实须有实际来源，不以 executor 新结论冒充事实。
- 语义异议：不能由提出者自我批准。只有出现此例外才调用一次隔离的路由仲裁上下文（现有已授权 LLM，无常驻新 agent），提供原文、被质疑的题文与观察、正式方法及异议。输出 uphold、amend、acquire、unresolved，并带具名依据和受影响部分；程序核对版本/来源/权限/范围后提交新版本。
- 仅“我更喜欢直接回答”不构成覆盖凭据；不要求执行者同意才能继续。重复无依据拒绝不进入无限争辩，标记执行不遵从并交原责任方，不伪造已执行。
- 已确定的无关事项和已完成工作保持；仍未决则交原宿主处理该范围并保留原因，常规已提交部分不重判。仲裁不是更强模型必然正确的保证；所有更改保留原路由与改动依据。

宿主实际接口是执行权成立的前提：commitment 必须以本轮有效指令而非 evidence 文段传入，原文仍标作数据；程序能控制的加载和调度必须实际完成。受控执行结果绑定 active route revision，携带完成步骤/产物引用或 objection。版本不符或无具名变更的结构性改路由不作为“已按路由执行”消费。自报完成不证明方法语义保真，语义表现由小批任务评阅和按需纠偏检验。若宿主仅能插入提示、不能提供上述装载/回执边界，只能称 advisory 集成，不能声称执行控制已交付。

## 6. 保留 Skills／4K 定点纠偏

在 before-route 或已有短候选的 before-answer，按实际风险复用已实现 `relationship_assessment/runtime/live` 的问题与一次修正能力；统一到同一个新 profile，不去掉现有禁止叠加 C01 的检查后把两套账本串跑。集成尚待实现并需回归。

结果不是给执行者“可忽略的建议”：具名命中在当前预算内触发原宿主一次目标明确的修正；也可走同一 objection 入口指出误报。修正保留原始来源，产生新候选版本；需要时复查相关关系一次，不要求所有分数一致或全部变绿。

- Skills：可以同时“接受范围更正”与“修复解释不充分”。不使用整个 Agent 系统替该 Skills 作证据；具体实现确由固定提示解释时允许保持原结论。
- 4K：区分已有设备的可用性与购前选择。已给事实可决定时交付主判断；价格/取舍不足则条件化。不把改善等同物理等价，不把“当事人”偷换成“当前用户”。
- 只改候选表述/论证且对象未变时保留路由；真实目标/事实改变只使受影响路由及后继失效。纠偏不预设选某显示器或反对提示词解释，也不为此开启另一全图复核。

这些是已暴露的开发锚点。已有 D3 成功不继承为新多方法入口资格。

## 7. 预算、容错、实施与验收

首版复用原 v0.1 容量上限而非创造新预算层：每 episode 快速批次≤4（路由、纠偏检测和复查合计）、整理≤1、例外仲裁≤1、具名修正≤1，共≤7次插件模型请求；插件请求累计≤180秒、单次≤45秒。是上限不是常规路径，实际试用限额在实测前登记。方法本体/工具执行受原任务预算并全部计入端到端成本，不隐藏为“免费LLM”。未知 intent 先核对，不换目录重发。

同一调用若同时是修正与仲裁，只计一个实际请求，角色计数按已声明用途扣相应槽位；用完例外/纠偏额度后交回原宿主，不再额外复查追绿。新版本失效不自动重置额度。无需默认重新生成题目、完整行动计划、采样投票或多轮审计。

允许不同但充分的路线、轻微关注深度差异与可恢复措辞偏差。反复漏必要判断、无据事实影响核心结论、有效目标被替换、真实权限被越过、或伪造读取/完成记录时保护相关范围并修复；不把普通噪声都变成全局停止。未批准一个固定可错百分比。

下一切片仅在 `entry.run` 增加显式新profile；复用通用provider/session与现有纠偏组件，新增最小commitment/objection接线，不另建规划平台。不能仅靠提示词宣称控制权生效。默认非Jev路径、main、旧试验保持；本轮只固化方案和评审，不启动该实现。

首批验收见 `acceptance.md`：相关工程控制后即可做低风险小批实用验证；不以前置全面校准/统计非劣阻塞。开发失败由实现者归因、等量修订/删减、回归后重新冻结，保留旧结果；不是每个细节向Owner请求决策。
