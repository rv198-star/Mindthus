# B3 当前 Codex ①／②消费对照：超时后继开发测试

## 目标与边界

这是一项新的开发测试，承接 `paired-current-codex-v1`。原①调用已有完整文本和
`turn.completed`，但外层 CLI 在 43 秒上限退出，计费及进程退出状态未确认。
本版保持原始 B3 任务、同一 Jev 初始观察、WAE 合同、①提示和已完成的②回执不变，
仅用新的隔离 Codex 会话及 120 秒外层上限取得一次明确的①进程结局。
旧请求及其失败记录保持原样；本版不把新调用写进旧 Episode。

①仍为建议式，②仍为已完成的约束式。两臂不称 A/B。本题已暴露，②答案已知，
故这里只检验当前 Codex 能否完成同材料消费及其文本性质；不作为独立保留集、
质量提升或端到端速度资格证据。

## 执行前固定

- 使用 `abc-current-codex-v2` B3-C 的同一次官方 TypeSafe `jev-1.13.0` 观察；
  本版 Jev 新调用上限为 0。
- ①模型请求为 Codex CLI `gpt-6-sol` 一次，隔离配置及只读工作区；不自动重试。
  CLI 退出状态、原生事件、最后消息、token 和耗时分开保存。服务端模型与实际金额
  无法观察时为 unknown。
- ②为原 B3-C 已消费的 `CurrentAgentHost` 回执。其内容和既有时长不重跑。
- 源提示、父绑定、父①超时结果、父②回执及本版脚本/计划均按 SHA-256 冻结。
  冻结后仓库增加结果报告不改变本版请求身份。
- CPA、OpenRouter 和其他模型调用为 0；任务为只读分析，不执行退款。

## 判读

两边都按原 B3 四项必要性质和三项严重错误检查。①即使进程完成，仍只算
已暴露开发配对；时限不同，实际调用耗时可列，但不推断公平的速度优势。
如果本版调用失败，记录失败并停止，不用第三次调用追求干净状态。
