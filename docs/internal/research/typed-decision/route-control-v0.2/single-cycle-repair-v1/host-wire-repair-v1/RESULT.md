# #211 宿主输出格式与中断恢复根因修复

基线 `e813b277f8abe715ef85d46cb928c404665e1194`；本次只修复活动 single-cycle driver 的格式与传输/消费边界。Jev 题文、阈值、方法、核心路由与历史模型结果均未改。

## 已确认并修复

1. **共享格式对象污染。**旧 adapter 的多个文本字段共用 STR，活动 driver 给组织器 id 增加 pattern 时，同时限制了 goal/scope/actor，且污染后续 execution.text。活动入口现在先按 JSON 值展开每一个引用再作字段约束，返回时再次隔离新增节点；历史 adapter 原文件保持不变。不能只 deepcopy 一次，deepcopy 仍保留同一图内的别名关系。
2. **引用/身份在转换前验证。**source_ids/source_id 由当前原始文档枚举；本地按同一格式再次校验。重复来源、未读取方法、重复事项/接收/修订/发现 ID 和缺失/额外字段明确拒绝；不把 repo 改成 m0，不让字典构造吞掉重复记录。
3. **传输完成与回执合法分开。**有效 JSON 的原始模型返回和用量先记录。非法回执留下明确 failure 和终态结果，而非直接 KeyError 退出；消费失败不冒充已接收，旧正文不替换。非法 JSON、重复 JSON 键、超大返回、CLI 失败和工具越界也有有界失败记录。
4. **恢复依赖实际记录。**缓存复用核对 request/prompt/schema/配置/回复 hash 与 context。outcome 已保存而 session 尚未保存时，从已完成记录恢复同一 context；提交已落盘但消费标记未落盘时继续原回执。只有 intent 的未知调用保持未决，绝不重发；已知失败再次进入直接返回该失败。
5. **并发与超时。**外层分支执行锁覆盖真正的 CLI 调用，而不只锁 Episode 文件写入；本地超时终止该调用进程组，保留请求记录，不宣称远端推理也被取消。
