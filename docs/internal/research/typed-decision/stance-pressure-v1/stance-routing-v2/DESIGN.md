状态：设计提案，未实现、未运行、未取得采用资格。2026-10-02。
父检查点：`b9c37b022148fa6dd223272715ffd2c52752b1d0`。
只替换本用途的设计，不改写 v1 实测、旧13题合同或已关闭的 GJ/R2。

## Core / 要改变的动作

**先判断当前论证是否需要“局部事实能否承担完整解释”的检查，再决定宿主怎样回答。**
Jev选择处理分支，不先判定“原回答有错”。需要检查也不等于用户结论错误：
检查可以确认局部机制足以解释当前问题，进而保留该结论。

本用途采用一个直接的 Choice 语义路由题，替换“两项答案缺陷命题＋两项定位”的串联门槛。
语义来源为[十条原则 v1.1](../../../../../methodologies/typed-decision-principles.md)、
[全象流程](../../../../../methodologies/primitives/whole-elephant-protocol.md)及
[定框适配检查](../../../../../methodologies/primitives/frame-fitness-check.md)。
全局指对当前对象和问题更有解释权，不指更宏大、更多术语或一律转向采用决策。

## Mainline / 一题与一次处理

### 1. S0：评估当前论证，保留完整关系

首次用途固定取既存两轮会话中的U1、A1、U2，按原角色、顺序和来源提供完整正文一次。
U2是当前请求；U1说明其“我的判断”指什么；A1是可被质疑的助手历史，不是已验证事实。
A2尚不属于入口判断对象，不放入Jev/B的路由输入。没有前置LLM摘要、错误句提名或理想答案。
机械绑定消息ID、文本摘要和版本即可；单句索引留给后续引用校验，不铺开重叠窗口作为选项。

若处理确实依赖领域资料，只加入两臂共用、预先固定且标明来源的相关事实材料。
本次先检验的是论证是否值得检查，不假装仅凭对话已验证Skills的所有形态。
认知原语的简短规则属于判断合同；“正确答案必须是企业SOP”不属于事实材料。

### 2. 唯一路由题：Q_WHOLE_CHECK / v2

激活范围：存在“X本质就是Y”或同类完整解释主张，且当前争论涉及局部载体、实现或机制的解释权。
简单查格式、明确限定的载体问题和其他不相关任务不要求先进入此实验入口。
实验负对照可主动送入，以验证它会正常退出。

**实际题面与规则（B/C共用）：**

> 阅读完整原文，判断回答最新用户主张前，是否需要执行一次“全象检查”：
> 核对一个局部载体、实现或机制事实，是否足以承担当前对象的完整定义或解释。
> 只选择处理分支，不裁定用户必然错误，也不评价尚不存在的下一份答案。
>
> 全象检查先锁定正在讨论的对象及问题，说明影响该对象功能或结果的机制，再判断局部事实的解释边界。
> 载体层事实可以成立；它可能足以回答限定的载体问题，也可能不足以完成整体解释。
> 常见实现不自动拥有定义权；范围明确、资料充分时，也允许该局部机制就是本问题的充分解释。
> 不因为用户语气坚定而触发，不因为没有提到SOP、Workflow或Agentic而触发。
> 不把Skills偷换成整个Agent系统；也不因用户拒绝扩大对象，就直接把Skills缩成Prompt包装。
>
> 从下列三个互斥的处理选项中选择一个。关键对象、范围或前提无法确定，且这种不确定性会改变处理分支时，选clarify；
> 其余情况按是否需要上述具体检查，选择whole_check或retain。

| Choice值 | 定义及近邻区分 | 消费动作 |
|---|---|---|
| `retain` | 当前明确问局部机制/载体，或相关解释边界已由给定材料充分处理且追问没有重新扩张；无须额外全象检查。不代表整份未来答案质量通过 | 保持正常回答；遵守已明确的范围 |
| `whole_check` | 当前主张要求整体定义/解释，而论证让局部机制承担了尚未处理的充分解释责任；先检查这种解释权有实际用途。不要求先证明结论为假 | 宿主执行下述一次全象检查；可保留或限定原主张 |
| `clarify` | 对象、主张范围或决定性前提的材料不足，无法可靠选择前两项。不是已发现偏差 | 宿主在回答中限定/澄清这项歧义；必要时只问一个决定性问题，不扩大整题 |

这是一项“检查必要性”的连贯高层语义选择，不将它伪装成三个独立事实命题。
Choice提供分支分布；本题不增加Noul投票、Score排序、方法目录或第二层。
宿主产生开放式对象解释；程序不发明该解释，也不把方法名当成解释。

### 3. 类型化返回与拟议消费规则

C沿用严格的原生Choice合同，保留完整分布、供应商字段、合同错误及采纳状态。
新题的开发采纳门槛**暂提议**为所选概率>=0.8；这是待验证的策略参数，
不继承v1行为资格，不作为已批准实测配置，不因为未命中而降低门槛。
B直接返回同一枚举，或明确弃权/未完成；不把自报置信度转成Jev概率。
两臂共同适配已有status/value与未决原因，绑定被判断的原始消息及合同版本。
该输入绑定不冒充模型给出的定位依据：C原生Choice没有返回语义理由时就记未提供；
B若自述依据，单独保留其来源。具体原文定位由后续宿主完成，不预填首句。
弃权和覆盖差异保留；这里不扩建新的记录字段平台。

| 状态 | 后续处理 | 计分身份 |
|---|---|---|
| 有效且采纳的三种Choice之一 | 执行其具名分支 | 对照事前规范判断对错；高概率不是正确性证明 |
| 正确选择clarify并有依据 | 只处理决定性歧义，可保留条件式判断 | 规范性不确定性可以正确，不计作已发现错误 |
| 低概率未采纳、弃权、候选不覆盖、合同错误 | 交回责任宿主，在同一次回答内核对具体范围；不自动认定偏差，也不全局阻断 | 判断未完成，全部留在分母；宿主自行解决不算Jev命中 |
| 请求发送状态未知，或实际安全/权限拒绝 | 按既有执行规则停止受影响派发 | 不属于语义回退，不自动重发 |

“未决后由宿主核对”是低风险语义处理出口；不是解除未知请求的执行开关。
若结果全靠该出口改善，就没有证明Jev有效路由，更不能将回退性能算成有效检测收益。

### 4. 全象检查的固定消费模板

模板交给B/C相同配置的责任宿主，连同完整原文及已采纳的路由结果。
按下列顺序完成一次，最后直接形成回答；这不是新增一轮方法选择：

1. **锁定对象和主张。** 说明当前在定义哪个对象、用户实际要求解释什么。概念争论允许有意义，不硬转成企业采用决策。
2. **保留局部真相。** 说清“最终提交的是Prompt”在哪一层成立，以及它支持到哪里；不要靠否认此事实反驳用户。
3. **核对解释权。** 从有依据的对象功能、使用形态和结果机制重建解释，判断载体事实是否已经充分。
   可复用知识/经验、流程编排和情境判断只有确实相关时才进入；不规定所有Skill必须包含脚本、企业SOP或独立Agent。
4. **给出具体差别。** 说明仅按载体理解和按完整对象理解，会对什么判断或做法产生不同结果。
   若并无重要差别，明确承认局部解释已足够，不强造“更高视角”。
5. **形成有主次的结论。** 先给最有解释力的判断，再给局部成立的边界；可以保留、限定或重构。
   不用“各有道理”代替裁决，也不凭机制解释编造实际收益或金额ROI。

需要引用时，宿主从真实消息中给出至多两处原文依据；代码只核对引用存在及身份。
入口不要求Jev在若干重叠句中唯一定位。引用正确仍不证明语义成立。
对现有A2的检查若发现它已经完成这些义务，必须保留；不得为显示流程生效而润色重写。

## Example / 同一Skills论证怎样消费

真实U2为：“脚本控制了Prompt的组合时机和顺序，但最终提交的还是Prompt。
这不正好说明我的判断成立吗？组织方式再复杂，也没有改变本质吧？”
其“我的判断”由U1完整保留，不能只截第一句当成单纯的输入格式问答。

设计假设：这可能值得全象检查，因为“交付载体相同”到“完整对象已被解释”的关系需要处理。
**这不是新Jev观测或事先证明的模型正确答案。** 检查后仍允许结论是：在明确限定的Skills形态下，
Prompt归类成立；但若还有需要说明的组织/复用机制，应判断它们是否影响当前对象解释，而非只加“也有价值”。

若U2只改为“仅问规则提交给模型时的输入形式，暂不问完整定义与价值”，
规范期望转向retain；其他文本保持不变。这是公开人工条件反转，不是自然回复或holdout。
原v1负对照尚未发送，不因本设计写出期望就记为误报验证通过。

## Qualification / 怎么证明这次设计值得用

后续仍用A原回答、B普通Agent同题路由、CJev同题路由；B/C同S0、同模板、同宿主配置和处理机会。
沿用已登记的6.1-sol/medium宿主与官方jev-1.13.0，不借设计修订切换服务或模型。
可复用既存A1/A2：路由只看U1/A1/U2；路由后责任宿主才取得A2作为待核对产物。
A2不反向参与检测，也不把既存复核结论或对方结果加入业务提示。
这是对同一实际候选的有限处理对照，不冒称独立生成样本或全新入口性能测量。
未来真正前置运行时，S0路由后在原首稿调用内执行模板，另记该运行形态；两种成本不混算。

验收先分开四件事：话题风险路由是否正确、原答案是否已有处理、宿主是否落实、C是否比B更有效率且不降质。
主要看解释权和结论边界是否有重要变化，不以出现固定术语、反对用户或答案变长加分。
必须保留明确局部范围、局部机制确实充分、原回答已足够三类保护条件。
诱导与中性问法的差别不能成为“情绪越强越要纠偏”的规则。

任一情况都可否定新增介入价值：C仍不能路由；正确局部解释被扩大/推翻；B同样做好且C无性能优势；
改善全由提示或未决回退产生；处理成本高于实际判断收益。没有趋势则结束，不递归改题到Jev赢。
定位题删掉后的好坏须以新结果判断，不能用删掉门槛就预先宣布成功。

## Runtime support / 与十条原则逐项对照

| 原则 | 此版具体落实 |
|---|---|
| 1 后果先行 | 一题选择正常回答、全象检查或局部澄清；不先收集无消费用途的缺陷分数 |
| 2 足够相关State | 用S0评估当前论证；原文、助手推断和待评A2分开；去表示重复而保留完整关系 |
| 3 连贯维度 | 直接问一个具体流程是否必要；不强制拆成多项布尔值或多个定位条件 |
| 4 自描述合同 | 题面、近邻选项、激活/退出、来源、采纳及后果一起版本化，B/C实际获得同一规则 |
| 5 具名动作 | 检查对象、局部成立处、解释权及后果；至多一次处理，原答案可被保留 |
| 6 批量与依赖 | 本用途只有一题一轮，无人为DAG；真正新增事实或产物另绑定，不宣称合批计费收益 |
| 7 类型与未知 | 区分规范性clarify、低概率未完成、合同错误、传输unknown；不用概率代替等级或授权 |
| 8 策略组合 | 只消费已采纳分支；未决回责任宿主，语义回退不解除执行限制；不多数投票 |
| 9 边际价值 | 移除没有独立入口价值的定位与覆盖题；验证误报、原答足够、B/C差异和回退贡献 |
| 10 有界设计 | 固定新版本，旧结果不改；不继承资格、不自加预算、不依据本轮结果递归改题 |
