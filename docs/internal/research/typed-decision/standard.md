# 通用类型化裁决范式使用规范 v0.1

> Normative Decision Contract design principles: `docs/methodologies/typed-decision-principles.md`.
> 本文件负责实验治理、接入、验证与价值账；若涉及 State / Question / Choice-Noul-Score / batching / policy / dynamic design 的设计规则，以该规范资产为准。

状态：设计草案 / 待试点验证；不是已上线能力或已通过模型资格认证。登记日期：2026-09-21。
本轮授权：制定规范、比较候选、登记最多两个试点；运行时代码、真实推理预算和发布不在本轮执行范围。

## Core / 核心

**由人或 LLM 把问题设计成有边界的裁决程序；快速模型执行其中局部的语义判断；确定性运行时组合结果、执行受授权动作并保留证据。Jev 是第一个后端，不是标准的所有者。**

规范适用于可重复、有明确问题与上下文、可观察后果的判断。架构的通用性来自稳定合同，不来自预先建设覆盖所有场景的平台。

## Mainline / 主路径

### 1. 选择值得转化的判断

先回答四个问题：要改变哪一个行动；正确判断依赖哪些材料；能否形成稳定且有意义的候选或评价标准；重复使用节约的代价是否可能覆盖设计、取数、验证与维护成本。

确定性计算继续用代码；开放式问题定义、候选创造、因果推演和文本生成保留给 LLM。小问题可只有一个节点，复杂问题可成为树或 DAG；节点数量按真实语义依赖决定。

### 2. 分离设计、数据和执行责任

| 角色 | 负责什么 | 交付什么 |
| --- | --- | --- |
| 设计者：人或 LLM | 目标、判断边界、候选、标准、节点依赖、结果后果与例外出口 | 版本化 DecisionSpec / GraphSpec |
| 上下文提供者 | 按合同取得本次所需事实，保留来源、时效、缺失和访问范围 | 有身份的 ContextSnapshot |
| DecisionProvider | 在指定上下文上执行指定局部问题 | 类型化判断及其模型/配置身份 |
| 确定性运行时 | 能力检查、调度、合并、预算、已授权动作与恢复 | 执行轨迹、动作结果、异常出口 |
| 评估者 | 用独立参照检验局部判断与最终任务收益 | 有来源标签的评估，不代写观测事实 |

设计时规定“需要哪些上下文及怎么取得”；运行时绑定本次真实数据。长期事实、用户目标、当前证据和上游模型推断分别标注，摘要不能提高证据等级。

### 3. 最小供应商无关接口

概念接口：`evaluate(decision_spec, context_snapshot, execution_options) -> decision_result`。这不是已实现 SDK，也不要求所有方法采用同一种物理部署。

最小节点合同包含：`id/version`、`question`、`result_type`、`criteria`、`required_context`、`policy_ref`、`fallback_ref`。图在此之外定义依赖、分支、汇合、终点、权限范围及总预算。字段能继承图级默认值，避免每个节点重复大段配置。

通用能力：
- `select`：从声明的候选中选择，候选覆盖与冲突处理明确。
- `assess_proposition`：评价一个清楚的命题。肯定、否定、材料不足的语义由合同区分。
- `rate`：依据显式有序等级评价，保留等级口径；序数或加权等级不是跨任务可直接比较的价值金额。

结果分为两部分：执行状态 `ok / abstain / missing_context / unsupported / provider_error`，以及适用时的类型化值。输入缺失、候选不覆盖、语义难判、服务失败各有独立出口，不折叠成否定、0分或通过。

不确定性是可选且带类型的元数据：分布、供应商置信统计、校准引用，未提供则 unknown。适配器保留来源和数值含义；普通 LLM 自报置信度不冒充原生概率；后端不支持所需能力时显式拒绝该配置。

Jev 首个映射为 Choice→select、Noul→assess_proposition、Score→rate。Jev 的 Score 是等级概率加权值，不能静默当成一个离散等级；Noul 的概率输出不自动拥有 missing_context 状态，该状态由输入检查或独立适用性判断处理。供应商名称、端点、限额和原生字段留在适配器。

### 4. 裁决图的组合语义

节点可以是确定性规则、快速语义裁决、工具取证、LLM 生成/设计或终点。所有语义决定有命名责任人/模型节点；合并规则来源于已批准合同，不能由下游脚本临时创造。

没有数据依赖且访问范围相容的节点可以并行；仅结果消费有条件的节点可以预算内推测执行；必须依赖上游结果构造输入的节点分阶段执行。批次是传输优化，不改变逻辑依赖；同批独立评估不等于统计独立，不默认相乘概率。

分支覆盖所有合法状态；汇合明确 all/any、必要前驱、跳过、缺失和冲突的处理。优先级、否决与补偿条件分别表达；有序评分不自动相加成授权。合并后仍存在语义歧义时，转给命名裁决节点或 LLM，而不是用随意权重掩盖。

一轮图有明确终点；迭代是外层有预算、带新输入/版本的运行。未经变化的同一输入，不反复重问直到得到想要的答案。批量、投机和并行的额外成本全部计入。

### 5. 运行时动态设计

**默认复用已有合格裁决图；运行时动态设计是补齐明确覆盖缺口的例外路径。**优先级为：直接复用→已有资格模板内的参数绑定或合规组合→确有必要时由 LLM 设计局部新题/子图。场景参数变化不自动成为重新设计；简单一次性问题由 LLM 直接处理，不为使用快速模型额外造图。

启用前说明：旧图具体不能解决什么、为什么补事实或常规 LLM 回退仍不足，以及设计成本可能换来什么收益（批量/重复裁决节省，或可观察的判断质量收益）。这是一项简短、可核对的理由，不新增一轮专门的元评审。低置信度、事实缺失或服务失败本身不触发重设计，先走对应的补证据/回退出口；新证据确实揭示未覆盖结构时才重新考虑设计。

顺序为：识别具名未覆盖问题→生成声明式局部新版本→验证结构、引用、权限和成本边界→按其资格在授权范围启用→固定该次执行版本并保存结果。新设计保持原目标、判定标准来源、责任、权限和验收底线；针对候选或任务实例补充问题时，标准来源仍是用户目标和有效合同，而不是待评产物自身。不能依据本次答案是否合意反复改题或降低标准。

结构验证只证明可执行；新设计的语义正确性仍需样例/领域证据。已有资格模板内的参数绑定与新的语义设计分开处理：后者不继承旧版本置信阈值或高风险自动执行资格。Jev 对答案的高置信度不能证明 LLM 设计的问题正确。低风险、可恢复且处于已有权限内的临时设计可按预设策略试用，不把人类审批设成每个节点的常规成本；资格不足时保留建议或 LLM 处理路径。

每次启用前为该覆盖缺口限定作用域、设计/验证/执行总预算和语义修订上限；子图在同一预算内执行，不递归启动新的设计链或自行加预算。达到上限或没有新增有效证据时，转回 LLM 直接解决、既定回退或停止，不继续自动造图。动态设计使用已允许节点与工具引用，不执行模型任意生成的宿主代码。目标、验收标准、责任和授权变更走独立变更入口。

当前运行使用固定版本；新版本另起运行并显式关联前驱，只重算受变化影响的节点。临时图默认仅用于声明的任务作用域，一次成功不自动升级为全局模板；复用范围扩大前另行验证，并保留设计、取数、验证、裁决和回退的完整成本。本补充明确可选能力与使用纪律，不增加 #211/#212 的必做范围，也不使两个试点以“自动设计器开发”为前置。

### 6. 采纳和回退

`shadow` 用于取证，`advisory` 用于有限提示，`bounded_execution` 允许合格节点直接驱动已授权分支。前两者是验证阶段，不是架构上限；正常路径不要求 LLM 每次完整重判快速模型结果。

自动采纳资格绑定任务类型、语言、输入分布、节点/图版本、后端版本、校准与动作后果。未知或变化条件进入既定回退；高分本身不授予权限。补事实、LLM处理、请求责任人决定、停止，依照各自原因路由。

服务超时与有限重试有总预算，回退到明确路径；缺遥测为 unknown。回退时保留原目标、权限、约束和已有证据，而不是用一份裸提示词重开任务。

### 7. 恢复和观察

保存图版本、节点版本、输入快照/引用、模型实际版本/配置、已完成结果、未完成依赖、动作凭据及成本覆盖。复用键包含影响结果的上述身份与时效；策略/图变化同时影响结果采纳资格。

相同且仍有效的已完成节点直接复用；变化只使受影响节点及其依赖后继失效。历史记录保持不变，新运行建立 lineage。未完成的外部动作先查询原操作结果，再依赖宿主幂等机制恢复，不宣称网络调用天然 exactly-once。

“保存并复用原结果”与“重新调用模型重算”分别记录；重算不是同一次观测。模型意见、实际选择、实际执行和结果证据分别标注。

### 8. 验证与价值账

每个试点先冻结目标、数据划分、错误类型、主指标、非劣边界、成本目标、调用预算、排除项和停止规则。公开历史案例只用于回归；开发集和保留集隔离，相关任务/模板的近重复不跨组泄漏。

对照至少包括：A 原有路径；B 同一新图采用普通 LLM 裁决；C 同一新图采用 Jev。B/C保持问题、上下文、候选、非模型控制和执行预算可比；生成/最终评估使用相同配置。原版不是“新图换成LLM”这一臂。模型资格比较与加载策略比较分开，主线及现有冻结/HOLD试验保持原状态。

既测节点错误，也测整条路径、实际任务产物、误路由/误放行、返工、无必要阻断和中断恢复。主评估不由被测后端独占；人工/LLM标签与可执行证据分开。报告 abstention/覆盖率与错误率，不能只展示被接受样本的准确率。

完整成本账：一次性设计/验证/维护，以及每次上下文取得、所有模型/工具调用、等待、重试、回退和返工。分别报告单次冷启动与重复使用的摊销结果，按实际使用次数判断是否划算；不把付费成本、时间、风险随意压成一个综合分。

中文单独分层；供应商/图/题目/语言/分布显著变化触发相应范围复核。有限样本中零严重错误不是零风险证明。允许结果是保留原版、缩小场景、停止试点或证据不足。

## Guardrails / 从属保护

- 保护“最小充分上下文”：原始材料中的指令保持数据地位；访问/出站数据范围由宿主控制，公共issue只登记设计和脱敏引用，不上传生产内容或密钥。
- 保护“可执行即合格”的误用：schema、图有效、代码测试绿灯只证明对应机械属性，不证明语义正确和实用收益。
- 保护“通用性变平台扩建”：通用的是语义合同。第一批最多两个试点，只实现它们共同需要的薄支撑；已有任务、证据、权限与恢复机制继续复用。
- 保护“快速裁决变无限加题”：图和动态设计有预算及明确收益假设；依赖按语义必要性展开，不按展示复杂度扩张。

## Boundary / 使用边界

确定性校验不交给模型；开放式总体战略、未经授权的资源配置和高后果放行不因模型置信度自动变成快速路径。文档或日志只是呈现资料时，模型不能把它当成已实际运行的证明。
