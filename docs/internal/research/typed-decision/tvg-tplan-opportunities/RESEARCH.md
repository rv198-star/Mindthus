# Jev 在 TVG / TVG Profile / TPlan 中的潜在价值

日期：2026-10-02。仓库阅读基线：`f0c88a9c588c28d4b58d5852254050f16e8977f3`。
状态：源码、方法合同与既有真实证据调研；下文的新用法是建议，未实现、未实测。
本轮真实模型调用 **0**，没有启动 TVG 生产循环或 TPlan Mission。

## 结论与优先顺序

**先研究 TVG Profile 的具体成品检查，再研究 TPlan 的目标与证据增量检查。**
值得检验的对象是已经存在的产物、修订或下一动作，而不是再做一轮八方法入口路由。
Jev 判断某项关系是否成立，已有宿主负责创造解释、修改产物和承担最终决定。

| 候选 | 可能产生的实际收益 | 优先级与限制 |
| --- | --- | --- |
| 固定 Profile 下的文本成品检查 | 找到未落实的具体标准，少做整篇重写；足够好的稿子直接保留 | 第一优先；判断要能落到原文和修改位置 |
| TVG 修改前后的局部增量与忠实性检查 | 发现“加长但没补上缺口”、删除关键限制、编造效果；避免无效下一轮 | 同一切片的必要观察，不能代替整个退出审查 |
| TPlan 下一动作与目标、验收差距、证据增量的关系 | 识别局部返修取代主任务，或无意义复核；也保留必要的长路径 | 第二优先；语境和动作后果更复杂，先只给已有 Gate 提供判断 |
| 通用 TVG 质量总分、全 Mission ROI 预测、所有检查点常驻扫描 | 价值含糊，容易重造治理和评分平台 | 暂不做 |
| 直接评生成图的构图/审美、权限裁定、脚本计数/哈希/状态校验 | 当前服务不支持图像；后几项由权威规则与脚本处理 | 不作为本轮 Jev 接入目标 |

这不是“TVG/TPlan 已证明比路由更适合 Jev”。它们提供了更具体、可证伪的收益机会。
最强的假设不是“再加一个聪明裁判”，而是：**在固定标准的重复工作中，用较快判断
减少昂贵且无效的修改/复核，并准确保留本来已足够的产物或执行路径。**

## 1. 仓库当前已有的能力和职责

### TVG：改产物，Profile 定义何为好

[TVG 主合同](../../../../../skills/tvg/SKILL.md)要求先确定有界产物、实际用途和证据边界，
再判断厚度、洞见和密度，选择具体改进动作。默认不是无条件加长；没有值得改的对象就不启动。
[方法正文](../../../../../skills/tvg/resources/methodology.md)中的常规资源压力 2 通常是
核心改进加退出判断；状态循环默认是一份结构稿加最多三轮有理由的改进。
这些是方法指导，不等于当前每次使用均有独立 API 审稿调用。

[Profile 构建合同](../../../../../skills/tvg/resources/value-profiles/profile-construction.md)
已有三个有用层次：

- `value_semantics`：什么算好/坏，优先保护什么。
- `realization_surface`：价值落在哪些可检查单位上，例如一句简介、一个镜头、人物知识状态。
- `gain_policy`：缺口成立后优先怎么改，什么时候做减法而不是加内容。

Profile 是价值与消费规则的来源，不是独立退出权威。
**直接使用固定 Profile 生成的一次结果**与**反复修补后的生产结果**必须分开。
[现有单次 Profile 记录](../../../../../skills/tvg/resources/value-profiles/cinematic-colossal-realism/examples/single-pass-profile-power.md)
自己标为 partial；[循环研究日志](../../../../../skills/tvg/resources/value-profiles/cinematic-colossal-realism/examples/loop-assisted-research-log.md)
是特定会话观察，不能用来证明 Jev 的价值或 Profile 普遍成熟。

[trace 校验器](../../../../../skills/tvg/scripts/trace/validate.py)只检查字段、枚举和记录形状。
[影像提示 lint](../../../../../skills/tvg/resources/value-profiles/cinematic-visual-direction/scripts/lint_prompt_packet.py)
能发现词表/字段层面的缺项，但“出现镜头、光影、前景”不能证明存在有意义的空间关系。
这是可以研究语义判断的缝隙，不是需要再造一个格式检查器。

[TVG 退出审查合同](../../../../../skills/tvg/resources/exit-audit-template.md)仍要求人或 LLM
负责实际用途、证据边界和是否诚实退出；高影响、不确定或关键交接需要分离审查者。
**本建议不让 Jev 自动写 freeze/PASS，不取消必须的独立审查。**

### TPlan：已有状态机，缺口在语义是否真实成立

[TPlan 主合同](../../../../../skills/tplan/SKILL.md)已采用薄状态机、按需展开和稀疏证据。
[hooks 合同](../../../../../skills/tplan/resources/hooks.md)明确分工：脚本观察，Pulse 分流，
Gate 决定；普通父子任务对齐可以内联处理，不必每步完整审查。

实际 [build_mission_pulse](../../../../../skills/tplan/scripts/tplan_runtime.py#L5849)
收集活动节点、事件、风险、日志及机械候选，按既定优先级仲裁。
无候选时返回 continue，同时明确 `agentic_judgment_required=true`；这不是已确认 Mission 健康。
第三次触碰、失败或验收变化不足是触发信号，不是语义结论。
现有 Quiet no-op 已用确定性变化比较减少无意义状态播报，Jev 不必再判断一次。

[build_decision_packet](../../../../../skills/tplan/scripts/tplan_runtime.py#L6028)
提供目标、验收、活动任务、父链、共享风险和最近事件；
`path_assessment` 与 `continuation_authorization` 的枚举校验只保证形状。
任务是否仍值得做、缺陷是否阻断验收、下一步是否产生新证据，仍由负责的 Agent/Gate 判断。
packet 的最近事件窗口不保证包含所有关键证据；研究用快照须按真实引用补齐相关依据，
不能把“窗口里没看见”当成“此前从未验证”。

在阅读的 `skills/tvg` / `skills/tplan` 源码中，没有发现默认路径直接调用 Jev。
现成实验 [c02.py](../../../../../experiments/typed_decision/c02.py)有局部判断、一次改稿意向和
成品复查支撑；[当前宿主交接](../route-control-v0.2/implementation/current-host.md)也能复用原 Agent。
这些是可复用接缝，不能因此宣称新的 Profile/TPlan 接入已经完成。

## 2. 必须使用已有实测，而不是假设 TVG 没试过

[第一次 C02 实测处置](../c02-disposition.md)：官方 Jev 完成 12 个公开开发例、18 次调用；
route 10/12、utility 9/12，未满足当时冻结门槛，没有进入实际生成。
其中“足够可用但还能压缩”的标签依据有争议；adequate 文本被选 make_actionable，
则暴露了“可做这种改进”和“必须改”的混淆。这是合同/标准问题与模型表现的混合结果。

[复议后实测](../review-remediation/live-disposition.md)：C02 联合 6/8、route 7/8、utility 7/8、
action 6/8、support 7/7（另一个样例预定不评分），仍未进入实际改稿。
两个有实际后果的观察不能略过：

- 来源缺规则时提出 make_actionable，但运行时根据 support=missing 丢弃了动作；没有编造规则的真实产物。
- 文本漏掉目标明确要求的选择理由，utility 与 action 一致地认为已足够。
  **多个判断一致不保证检查到了真实缺口。**

固定成品 fidelity 的 6/6 来自两个母场景的原文/虚构/删限制变体，提供窄范围正向信号；
不是实际改稿成功、独立六任务覆盖或最终质量收益。

所以，下一步不应恢复旧 C02 标签/批次或用“合同工程已通过”当作语义资格。
可借鉴的资产是用途与来源分离、同 State 合批、只消费相容结果、原 owner 保留退出责任。
可复用的失败材料只作公开开发反例，保持旧分数和停止结论。

## 3. TVG Profile：最小且具体的研究切片

### 先选哪个 Profile

| Profile | 能问到的具体关系 | 用途与局限 |
| --- | --- | --- |
| [Plain sharp 简介](../../../../../skills/tvg/resources/value-profiles/plain-sharp-skill-intro.md) | 简介是否交代真实用途；例子是否说明实际选择；是否把方法夸成结论机器 | 短、材料完整，适合先看误报和少返工；“朗朗上口”仍交给人/宿主 |
| [King Hu 分镜](../../../../../skills/tvg/resources/value-profiles/king-hu-wuxia-cinema.md) | 人物如何获得信息；行动前是否建立空间关系；新增镜头是否带来新知识/叙事作用 | 更能暴露“风格词齐全但关系缺失”的价值问题；先只检查文字分镜 |
| [Cinematic visual direction](../../../../../skills/tvg/resources/value-profiles/cinematic-visual-direction/profile.md) | 次要动作是否服务主画面，或竞争第一阅读重点；是否真的落实减法 | 有自然消费动作，但实际图像是否实现仍须视觉审查 |

若目标是最快看到有无实际价值，先用**一个固定文本 Profile**。
若只在简介里发现措辞差异，不能据此声称判断能力有收益；可选分镜中的信息关系作为更有力对象。
不要把所有 Profile 的全部 axes 编成永久题库。

### 一次检查应拿到什么

State：原始目标与允许范围、已固定 Profile 的相关标准、有界全文及单元编号、来源/假设、
明确未知；复查时再加旧版本和本次具名修复目标。正文不先经过 LLM 提名疑句。
结构切分、编号、字段绑定可以确定性完成；语义候选及新因果解释不让程序发明。

候选问题按实际用途选取，以下只是消费示例，不是已冻结新题组：

| 判断 | 类型与答案含义 | 消费 |
| --- | --- | --- |
| 指定用途关系是否真正落实在成品中 | Choice：已落实 / 具体未落实 / 材料不足；说明何谓落实及可接受的简单实现 | 已落实保留；未落实才提出局部修复；不足回到缺失的输入 |
| 某句确定事实是否超出提供的证据 | Noul：给定资料下是否存在该越界命题 | 高度支持越界时限缩该句；未检测到不等于外部事实认证 |
| 指定改稿目标相比旧稿是否解决且保留关键限制 | 分开评目标落实与限制保留，同批用同一前后材料 | 修复成立保留；删限制/未解决交回原 owner，不能靠长度变化过关 |
| 哪个原文单元承载这项已定义关系 | Choice：全部合法单元及 none/unclear | 绑定原文；定位未完成不伪造发现，不删除其他独立有效结果 |

不需要为了形式同时用三种原语。Score 只在真的有可描述的有序等级时辅助比较，
不把“厚度 4.2 + 密度 4.6”算成退出决定。Noul 不是程度；Choice 原生 confidence 和
所选概率是不同字段；普通宿主自报 confidence 不冒充 Jev 分布。
新后果的采纳规则须另行明确，不能照搬旧问题的 0.8 当作通用资格。

**发现必须具体：**“P3 已让屋内人物知道屋外刺客位置，但 S1–S2 没有视觉/听觉或此前信息来源；
请补足获知关系或取消确定知晓，保留后续合理行动。”
而不是“注意提升空间智能”。Jev 只选关系/位置/分支；说明和改稿仍由宿主完成，
不要求 Jev 自由生成论证，也不把宿主事后解释写成 Jev 原始发现。

### 必须保留的反向结果

- 增加一个合理的声音线索后，人物获知位置应可成立，不因“没有看见”强制判错。
- 简短稿已足够说明用途及边界时，不要求所有 Profile 维度齐全、不为了更好听而强制重写。
- 允许有意隐瞒观众的信息；未知可以是悬念设计，不等于遗漏。
- 来源缺少效果测量时，应保留未知；改写不负责凭空补出证明。

这些例子说明什么能证伪检查，尚未写成新业务样本，也没有运行。

## 4. TPlan：看“下一步会带来什么”，不接管权限和总控

TPlan 的潜在收益可能更大：如果早识别无效路径，能省下一串宿主动作。
但判断难度也更高，因为目标、依赖、时点、风险和历史证据都可能决定同一局部动作是否必要。
**运行时间长或第三次返修，单独都不是浪费证据。**

建议只在已有触发点检查本次快照与拟议动作，给原 Gate 有界输入：

| 问题对象 | 合理的有限输出 | 实际用途 |
| --- | --- | --- |
| 拟议动作与当前已授权验收差距 | 直接推进 / 必要支撑依赖 / 仅附带改善 / 未决 | 让原 owner 解释必要性，或把附带改善批量处理 |
| 声称“验证”的动作与已有证据 | 预期可区分尚未解决的判断 / 重复已有观察 / 材料不足 | 不让复述、换日志或无关绿色测试冒充新的任务证据 |
| 新缺陷与本次交付 | 阻断验收 / 可批量细节 / 范围外 / 未决 | 支持既有 defect_classification，不自动允许发布或删除义务 |
| 已发布共享风险与当前节点 | 适用 / 不适用 / 未决 | 避免局部风险泛化成所有独立路径暂停，也避免漏掉真实共同依赖 |

同一完整相关快照上的独立问题可以合批；若需要新证据或新动作候选，再由负责的 Agent
取得或提出。Jev 不从最近几条日志猜整条 Mission 的历史，不自己发现所有备选路径。
纯脚本可以查的权限、引用、预算、版本、未知请求阻止派发等继续原样执行。

三个最有辨识力的对照方向：

1. **无效勤奋**：目标是交付真实答案，缺口却只被更多离线结构测试覆盖；
   下一动作若仍不产生目标证据，就不能把绿色测试作为任务已完成。
2. **必要深挖**：同样经历多次处理，但新动作检验已定位的核心阻断且有新证据来源；
   应保留这条长路径，不能为少调用而催促结束。
3. **合法改目标**：用户明确改成先做离线接线，此时离线测试就在服务新目标；
   不能死守旧目标把用户授权的阶段划分判为漂移。

这是未来回放研究的方向，不是对旧任务/R2的重新审计。
输出通过现有 source_ref/decision packet 交给 `continuation_authorization`、Mission Review 等 owner。
Jev 不能自行写 `authorized_action`、关闭 Mission、证明 unknown 已结束、复用一次性风险例外，
也不能因为“未发现问题”跳过规定的 Gate。先不改变任何 TPlan 生产合同。

## 5. 性能收益怎样比较才不造假

[上一轮路由结果](../stance-pressure-v1/stance-routing-coverage-v1/FINAL-RESULT.md)
显示几次 Jev 路由约 1 秒，比单独宿主路由快；但 5.6 完整处理路径反而更慢。
这不证明普通 Agent 的整体路径更慢：普通 Agent 可以在一次调用中识别、转向并生成。

TVG/TPlan 同样要区分以下结构，不能为了让 Jev 好看，把对照强行拆开：

| 真实原路径 | 加入 Jev 后可能发生什么 | 允许的收益主张 |
| --- | --- | --- |
| 宿主一次检查并修改 | Jev 检查 + 宿主修改，多了一次前置 | 必须证明少返工/质量改善/宿主推理负担下降；不能先宣称少调用 |
| 已经自然存在独立的低风险局部检查，再由宿主修改 | 用 Jev 替换该局部检查 | 可以测局部及完整处理时间；必须如实说明被替换调用原本存在 |
| 必须的独立退出/权限审查 | Jev 加入，原审查仍须完成 | 检查只能提供具体发现，不能把省掉必须审查当收益 |
| 外部触发的重复语义检查，目前需唤起完整宿主复核 | Jev 判断后，仅必要时唤起原 owner | 可以看减少了哪些真实唤起；不能新造每步检查再计算节省 |

金额暂按用户重视的低 Jev 成本处理，仍记录未知；**零近似金额不等于零延迟或零复杂度**。
State 准备、文字提取、全部 Jev 往返、误报处理、宿主修改、必要复核和维护都要计入。
当前实验的单发送者/60 秒冷却约束没有变化；若之后继续实验，多出来的真实调用与等待
同样进入完整墙钟，不用单次推理耗时替代总体速度。产品节奏与实验节奏分开解释。

## 6. 建议的下一小步：先看现成成品，不再造三轮前置

先选一个固定文本 Profile，整理 **3 对有界成品**：关系缺失/成立、无依据强化/诚实限定、
无效加长/真正补齐用途。标准先写清楚，正负两侧只改决定性关系，保留公开开发身份。
Profile 本身先保持不变；不能看了 Jev 结果再补规则使其赢。

分两种不同问题观察，不能混成一个成绩：

- **判断替换**：同一固定产物及同一 Profile 检查合同，普通宿主与 Jev 分别给出原始判断；
  核对漏检、误伤、未决、定位和可消费性。这能隔离判题差异，不证明生产路径收益。
- **完整产物**：保留正常 Agent 直接按 Profile 工作的路径；精细问题宿主与 Jev 路径用相同
  材料、宿主、允许的修改次数和最终标准。Agent 可一次检查并改，不强制独立路由调用。
  Jev 只触发具名局部修复；足够好的结果应可不改。保留全部首稿、判定和最终稿。

主要看四件事：有没有补上读者/下游真正缺的内容；有没有删除正确内容或引入无依据主张；
有没有减少不必要的宿主往返；完整处理/等待是否值得。
“Profile 题问得更具体就有效”与“Jev 比同题宿主额外有用”分别报告。

若只产生无用评分、漏掉关键关系、误伤合理简单稿，或省下局部审稿时间却增加更多返工，
就结束该切片。局部正向信号可支持限定使用，不需要普遍非劣、精确金额 ROI 或默认采用资格。

TPlan 接着选上述三种**既存或明确合成快照**做只读回放，先查能否准确区分；

## 7. 官方接口核对与本次边界

2026-10-02 阅读 TypeSafe 官方文档，未调用鉴权/模型接口：

- [State](https://docs.typesafe.ai/concepts/state)：当前 Jev 只收文本/文本 JSON。
  可以查文字分镜、提示包和已有文字观察，不能直接审图；另调视觉模型先描述的成本与错误必须单列。
- [Choice](https://docs.typesafe.ai/primitives/choice)、[Noul](https://docs.typesafe.ai/primitives/noul)、
  [Score](https://docs.typesafe.ai/primitives/score)：分别处理有限选择、命题概率、可描述有序等级。
  不从概率造整体正确率，不从 Score 造现实 ROI。
- [同批推测判断](https://docs.typesafe.ai/patterns/fan-out)：独立问题可合批，
  条件未成立的推测答案不消费；供应商延迟说明不是本项目新题组的实测保证。
- [Jev 1.13 限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13)：间接推理、无关大上下文、
  数值精确性和诱导内容有明确局限；这支持小而直接的关系检查，不支持交给它整个战略/审美总控。
- [模型说明](https://docs.typesafe.ai/models)：英文为主要训练语言，中文需按实际工作验证；
  不能把旧英语/中文结果或概率门槛自动转移到新 Profile/TPlan。
