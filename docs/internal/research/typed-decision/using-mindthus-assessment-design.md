## Core / 要解决的事

> 在选方法之前，识别会改变实际处理方向的定框、证据或范围偏离；在已有候选主判断时，针对已知失效模式执行检查，让结果触发一次明确纠偏。方法选择是评估结果的一个用途，而不是唯一产物。

验证目标仍是改善任务结果、减少误加载/返工或总成本。不是增加题量、追求“全息完整性”，
也不是建设新的 Cognitive Control Plane。原语不是独立总入口，using-mindthus 仍按最小充分镜头工作。

## Canonical map / 复用原有认知规则

以下均为现有语义来源；新增检查只是其候选执行方式，不拥有重新定义原语的权力。

| 来源 | 已有判断与拟消费用途 |
| --- | --- |
| [using-mindthus](../../../../skills/using-mindthus/SKILL.md) 与 [Entry Triage](../../../methodologies/primitives/entry-triage.md) | 直接/补信息/介入；显式调用不证明适用性；形状而非关键词触发 |
| [Frame Fitness](../../../methodologies/primitives/frame-fitness-check.md) | 定框风险且影响后果才检查；保留/限定/重构/因证据阻断 |
| [Whole Elephant](../../../methodologies/primitives/whole-elephant-protocol.md) | 局部真相不自动获得整体解释权；先锁 canonical object、result controller 与偏离后果 |
| [Decision Context](../../../methodologies/primitives/decision-context-calibration.md) | 用户角色、时点、目标、可接受损耗约束判断；全局不等于更抽象 |
| [Aspect Ownership](../../../methodologies/primitives/aspect-ownership.md) | 只仲裁同一范围的主判断竞争；其他切面保留为约束/支持，不平均成无主结论 |
| [Shared Primitives](../../../methodologies/shared-primitives.md) | 结论不越过证据；重复局部修补需回查收益与新增证据；原语不接管主流程 |
| [Expression / Pressure](../../../methodologies/primitives/expression-pressure-and-gates.md) | 有实际后果的压力检查与表达纪律；假设数字不是推理证据 |
| [Fidelity contract](../../../../skills/using-mindthus/resources/fidelity-contract.md) | 已触发审计的内部产物/校验与失败出口；校验形状不代表语义已证实 |

不得因为存在证据问题就直接路由 WAE；先判断真正的对象。也不得以存在依赖、跨日或一个
artifact 的特征自动推导 TPlan/TVG。相关性、方法适用性和必须采用是不同问题。

## Mainline / 输入、问题组与结果

### 1. 输入按对象与阶段绑定

**S0 入口快照**包含原始请求、有效目标/范围/权限、引用事实、当前时点、已知义务及其来源。
保留原句与有关事实，不仅提供主模型已经接受某框架后的摘要。结构化抽取若由 LLM 完成，
需留原文引用和推断身份；这项投影的成本也计入，不能免费假设。

**S1 候选审视快照**在 S0 上追加既有的候选框架、短计划、主判断或答案及其版本。
候选是待评对象，不是新增事实。没有候选时只做 S0 适用的检查，不为路由强制生成完整回答。
用户问法本身也可作为一个框架对象进行 S0 检查，但不能称为“检查了尚未生成的回答”。

**S2** 是补证据/修正后产生的新快照；保留前驱，失效相关结果，不改旧 State 或在新图内
静默复用旧语义结果。无需输出或保存私有思维过程；公开的短计划、主张或产物引用即可。

每行评估绑定 `target_ref + relation/scope + state_version + question_version`。
例如区分“校验器的证据认证有问题”和“当前助手缺乏分析该问题所需事实”；二者可以前者为真、后者为假。

### 2. 题组是可组合视角，不是固定全量流水线

| 题组 | 可问的关系 | 触发与消费 |
| --- | --- | --- |
| 入口处理 | 缺的是事实还是未决判断；当前处理是否受已知义务阻断 | 使用原入口合同，保持 direct/acquire/intervene/unknown 出口 |
| 定框与范围 | 当前解释是否越过局部适用范围；用户目标是否被扩大或替换 | frame-risk + execution impact；决定保留、限定、重构或补证据 |
| 证据与前提 | 指定前提是声明过的假设还是被当成事实；候选结论是否超出来源 | 影响当前主张时才检查，避免把分析对象的缺陷误作当前阻断 |
| 方法与关系 | 直接 owner 候选、多个方法适用性、资源/控制/路径等关系 | 按需求组合；同 State 可并发，适用不等于必须调用 |
| 候选主判断纠偏 | 既有主判断是否局部替代整体、盲目采纳前提或越过用户范围 | S1 中有明确对象；输出具名修正请求而不是“再想全面些” |
| 过程动态（预留） | 同对象重复修改、新增证据与收益是否改变 | 需要跨轮来源；本切片不扩展到所有过程诊断 |

题组激活来自已有 Entry Triage/原语事件和真实任务信号。可以消费现有语义判断，不能仅
按关键词白名单激活，也不能宣称“未被激活 = 已检查无风险”。显式要求或 canonical 必需
审计继续执行；初筛不确定时保留原责任 LLM 路径，不假装已取得豁免。

同 State 上已知输入足够的关系判断可与方法候选同批推测执行；无关答案不消费。
只有新合同、证据、候选或上游输出实质改变输入时再分批。题组数不等于请求数。
八种方法可以分别评估，也可以直接选择；维度上限按成本/效果确定，不先定为 8、20 或 40。

### 3. 评估矩阵与路由结果分离

矩阵保留各问题的对象、原生值、状态、不确定性、来源与消费记录。它可同时供路由、
证据要求、纠偏和 trace 使用。示意（非模型实测）：

| 对象/关系 | 维度 | 评估 | 后果 |
| --- | --- | --- | --- |
| 用户提出的局部机制 → 整个待定义对象 | 解释权 | 局部贡献被扩大为整体定义 | 先处理 Whole Elephant，不先强选 WAE |
| 候选主判断 → 用户本轮有效范围 | 范围匹配 | 不应扩大到其上位系统 | 纠偏必须仍围绕同一对象 |
| 某未证实前提 → 当前结论 | 证据支持 | 尚不足 | 不把另一套解释自动宣布为真 |
| WAE → 当前任务 | 方法适用 | 未判断 | 不能把未问项记为“不适用” |

代码可解释“哪个信号按哪条规则导致哪次动作”，不能声称看见 Jev 的内部思维或把模型
解释伪装成事实观测。外部回答保留简明主判断与依据，不倾倒矩阵/trace 字段。

## First slice / 首个落点：局部正确与定框偏离的有界纠偏

后继设计可表达很多维度，但首个实现验证只围绕一种已知失效模式及其反向控制展开。
使用下列三个可并行问题合同，形成第一份小矩阵；它们是起始候选，不是永久必问清单。

| ID / 对象 | 问题主旨 | 答案语义与后果 |
| --- | --- | --- |
| P1 `explanatory_scope` / 指定框架或候选主判断 | 相对当前对象与目标，是否把某个局部机制、阶段或实现描述扩大成整个问题的主结论，并遗漏改变结论/行动的因素？ | `scope_fit` 继续；`local_overreach` 交回 LLM 重建主判断；`insufficient_context` 补具名材料；`not_applicable` 不消费 |
| P2 `premise_treatment` / 指定前提与候选结论 | 该解释是否将未经支持的用户事实前提当成了事实？明确声明的假设推演、有效偏好和范围限制不属于这种错误。 | `treatment_fit` 继续；`unsupported_as_fact` 改为假设/限定或取证；`insufficient_context` 保留未知；`not_applicable` 不消费 |
| P3 `scope_preservation` / 候选处理与用户约束 | 候选处理是否擅自扩大或替换用户的有效对象、角色、时点、目标或范围？纠正错误事实本身不算越界。 | `within_scope` 继续；`scope_overridden` 收回原目标；`insufficient_context` 定位缺口；`not_applicable` 不消费 |

题面全文须自解释，引用实际 State 路径；关键前提/对象未提供时不由检查器暗自发明。
P1/P3 部分相关但消费不同：P1 防局部夺取整体解释权，P3 防“升维”夺取用户目标。
要用删减对照检验其边际价值，不因三个问题都显得合理就永久保留。

这些标签是候选检查语义，**不直接改写 canonical `frame_status` 或授予审计通过**。
命中后 LLM 按已有 Frame Fitness / Whole Elephant / Decision Context 合同作明确判断；
其产物和验证仍遵守原 Fidelity contract。无证据不声称有更高明的整体框架。

### 命中以后做什么

P1 命中：在同一 canonical object 上说明结果由什么控制，保留局部真实作用，重写主判断
及行动后果。需要开放式整体重构时由 LLM 完成，Jev 不能从未提供的候选中选出“正确全局”。

P2 命中：区分事实与假设，纠正对应前提或取得指定证据；不泛化为“用户带偏”或推测讨好动机。

P3 命中：恢复用户合法范围和判断约束；更高抽象、更长回答或更多方法不是预设优化方向。

P1 与 P3 同时命中不必冲突：可以既把对象误缩成局部机制，又逃到其上位系统。纠偏顺序是
锁定有效对象和目标，再重建其整体解释；无需二选一投票。若仍有同范围语义冲突，按
Aspect Ownership 命名主判断者，其他结果留作约束/支持，不平均成“各有道理”。

### 执行位置与预算边界

```text
已有入口 / D0 身份、时效、权限和缺字段检查
  → S0：按需并发入口/相关框架问题
  → 若有框架偏离，先按原合同纠偏，再选择方法
  → 直接处理 / 补信息 / 适用方法 / 原责任 LLM
  → 已有候选主判断时，在 before-answer 按需执行 P1–P3
  → 命中则一次具名纠偏；候选变化形成 S2
  → 可在原预算内复查受影响维度一次
  → 交付 / 保留未决项并转回原责任方，不循环追绿
```

这是逻辑顺序，不要求每轮扫描两次。同一目标的相同 State/题义/规则结果直接复用。
S0 不消费回答检查；S1 不自动重复已有效完成的全部入口判断。检测位置优先选择已有短
主判断或计划可用处，而非为检查额外生成一整篇答案。

初版实现预算以每个触发对象**一次检查、至多一次纠偏、至多一次相关复查**为设计上限。
不同入口/回答对象的共同调用总额、token/时间与费用准入必须在实现协议中固定，当前
不授予付费批次预算。自动调整只能在已验证的低风险范围内；其他情况使用原 LLM 路径。

## Qualification / 怎样验证不是更多自审而是真正改善

先核对对象锁、有效用户范围、假设与事实、当前任务与被分析对象的区分，以及所有出口。
开发反例应包括：局部真相越权；局部机制确实控制结果；明确只问底层实现；用户有效偏好；
公开假设推演；错误前提；候选尚不存在；旧摘要；合理局部修复；因“升维”反而跑偏。
中性问法与诱导问法使用同事实和目标，相关模板按家族分组，不能以换词证明独立样本。

先比较**相同任务/宿主，有无具名检查与动作消费**，判断纠偏率、误伤率、无必要升级、
最终质量、全部成本。再按需要比较同合同 LLM 与 Jev，以区分问题设计收益和引擎收益。
保留路由准确率为一项指标，不把更换 owner 当唯一进步；未通过题目不能从分母消失。
新增/删减问题只在开发集有界进行。后继冻结后另行准备独立保留集，不重新命名旧题充数。

计费核查是独立的工程事实问题：仅当布局/预算决策依赖同 State 共享计费时，先做有
独立准入的批量/拆分对照。当前没有这一实测；不据想象的免费扫描承诺净收益。
