# #207 WAE Loop：P1/P2 交接与 EKRI 知识深度的边界复审

> 历史两场景设计自审，保留当时结论与边界。本记录不是 [机制规格 v0.1](wae-loop-v0.1/design.md) 的三场景专家评审；下一轮使用 [三场景评审包](wae-loop-v0.1/review-packet.md)。

## 1. 本次设计修正

用户新增的两个场景成为主验收家族：

- F：P1/P2 应把本阶段负责的产品/设计含义说明到足以交接，P3 保留合法实现自由。
- K：EKRI 应查明并保留下一类工程决策需要的现存事实，而不是停在架构名词或复制整仓代码。

原 D1 只读查询、D2 事件回放适合作为驱动器和确定性 oracle 的开发冒烟，不再单独承担 WAE Loop 满足产品需求的证明责任。

核心仍是自适应委派深度，不是无限审稿。充分性绑定于：**下一阶段用途、当前权责、指定承接者、来源版本、可验证结果和风险边界**。存在一个可接受的停止区间，而不预设唯一正确层数；绝对最浅或零风险均不是本 MVP 可以证明的结论。

## 2. 两个场景共享判据，但有不同的知识动作

| 维度 | F：产品/设计交接 | K：工程事实重建 |
| --- | --- | --- |
| 当前对象 | 应当如何工作的设计承诺 | 固定源码版本实际上如何工作 |
| 深入动作 | 在本阶段权限内补决定、约束、交互语义或必要设计 | 查询、追踪、读代码、检查行为，获得证据并形成摘要 |
| 合法未知 | 归下层的选择、来源尚未授权的业务决定 | 未读分支、缺失配置、外部依赖或证据冲突 |
| 典型越界 | 用界面细节名义接管全部 P3 实现 | 把合理设计、旧文档或函数名当成当前事实 |
| 成功出口 | 下层按其权限实现，不发明上游应决定的含义 | 下层完成声明范围内的理解/复用/影响分析，事实可追溯 |

F 也区分来源事实、Owner 新作出的设计决定和有意委派的自由。获准新增决定不是发现了一个客观历史事实。K 的观察只能形成相应证据支持的事实或候选知识，不直接越过 EKRI 既有 family authority。

现有 EKRI v1.1 已有 Competency Questions、Knowledge Sufficiency、预算与停止条件、Evidence Receipts 和 Candidate Knowledge Delta。本实验借用这个需求检验 Mindthus 判据，不声称 EKRI 没有获取循环，也不在 Mindthus 复制其生产控制层。

## 3. F 场景：按交互后果找上游遗漏，而不是写全界面

以下是拟建的合成验证样例，不是已经证实的 WFF 新事故。

业务是一个记录审核工作台。来源约束已说明角色、审核行为和可见信息；初稿只说“编辑、提交、审核、查看状态”。测试关注编辑与审核对象版本、权限、失败后的保留和恢复等会改变用户结果的含义。

例如，“审核后修改”可以有两个经来源允许的策略：新建待审修订并保留旧批准快照，或明确撤销当前批准再要求重审。若这个选择由当前 Owner 拥有，应由它明确选择。两种合法方案都可通过；oracle 检验后续实现与所选规则一致，而不隐藏唯一业务答案。

表格/卡片、按钮位置、组件库、局部视觉表达通常由 P3 在现有约束下选择。若某一视觉安排会泄露权限数据或改变用户被告知的状态，它才成为材料性交接问题。判断依据是后果与所有权，不是“这是界面细节”这个标签。

P1 的直接下游是 P2；P2 的直接下游是 P3。案例会分别冻结这两个交接检查点，避免把 P1/P2 当成一个无限权限 Owner。第一波只选一个具有代表性的 P2→P3 切片；通过后再用 P1→P2 变体验证相同判据。

可预演下游会遇到的业务操作，以在 Freeze 前暴露缺口。这种预演是检查手段，不启动完整 P3，也不把正常生命周期改成 P3 反复返回上游。深化表达粒度本身不扩大阶段权限；缺少用户或其他 Owner 的决定时，精确 need_input 优于编造事实。

F 的端到端验收：fresh 承接者只读任务来源和交接包，完成一个小型可执行交互切片。用行为测试检查权限、状态和错误恢复，以独立范围评审检查是否偷作上游决定。测试不要求某个组件或像素布局。漂亮页面和模型说“完整”均不是通过依据。

## 4. K 场景：查得深与写得细是两个变量

拟建一个小型任务处理仓库，包含入口、调度、执行、重试与去重、状态记录等有限分支。固定源码快照提供事实真值。文档可以过时，函数名称也可以产生误导，但这些干扰及其来源身份必须事先冻结。

例如“系统支持自动重试和幂等”不足以回答“失败重跑是否可能重复执行副作用”。为回答它，可能需要读到去重键、状态更新顺序、外部调用及错误路径；最终知识摘要却只需保留去重范围、故障窗口、保证的边界和精确证据入口。无需复制每个函数。

必须分别计量：

- **探索深度/成本**：实际读了哪些分支、文件和字节，调用/检索多少次。
- **保留粒度/成本**：哪些行为事实进入摘要，携带多少文本/代码/引用，接收者是否仍需重新查源码。

读取了整个仓库再输出短摘要，只证明压缩，不证明探索经济性。只写“详见源码”并把重查工作转给下层，也不计作交接充分。

K 的初始知识资产保留合理的导航骨架：模块职责、关键边界、可用证据入口与未知区域。任务针对性深化建立在骨架上，而不是只背两道已知问题。声明支持的用途类别，例如定位能力、复用判断、关键行为约束和有界改动影响；独立测试从这些可见类别中取未见具体问题。未来一切用途不在完备性声明内。

接收者先只使用知识包回答约定用途内的问题和影响分析，以原仓库的小型行为测试及证据定位验证。失败后可以另作有界源码补查诊断，测量遗漏被转嫁的成本；补查不回写原 trial 为首次交接成功。明确超出知识包声明范围的新任务，可以按精确入口再探索，不据此判原包失败。

缺少运行配置、动态依赖或观测时，只陈述固定版本静态证据所支持的边界。搜索未命中不等于不存在。K 的 oracle 区分“代码语义可知”与“真实部署未知”，不奖励臆测运行事实。

## 5. 每次下钻要留下可检查的理由

保留一段短的工作记录即可，不增加产品真相字段全集：

1. 下层要作出的具体判断或动作是什么？
2. 当前描述还容许什么会改变结果的解释，或缺了什么必需事实？
3. 该选择/事实归谁负责；当前下一步是设计还是取证？
4. 这一步实际补出了什么决定或观察，如何支持交接？

有具体反例且在当前权限内时局部深入。已有规则能回答、剩余是合法自由时交接。证据不足时指出下一处最有价值的检查面。缺权限或关键外部事实时返回。预算耗尽且仍不充分时保留 stop/未收敛。

没有发现反例不单独证明充分；还需检验公开用途范围内的代表性正向任务和激活的高风险边界。也不要求枚举所有可能界面或代码路径。

同一范围在输入、约束和证据没有材料性变化时，单纯重新命名 finding 或改写措辞不足以重开。出现实质新证据、源版本变化或新的关键风险时允许重新判断。比较行为含义，不用全文 hash 决定语义稳定性；hash 只绑定输入身份。

## 6. 稳定性测试的中心是最小对照，不是重复随机跑

每个家族冻结“必须深入”“已经足够”“来源不足”变体，再加入以下成对测试：

| 变化 | 预期关系 |
| --- | --- |
| 同义改写、事实顺序交换、无关背景增减 | 关键权限/事实判断和可接受交接结果保持；不强制同样层数 |
| 删除决定性业务规则或去掉关键证据 | 不能沿用原 ready 声明；应补决定/取证/精确返回 |
| 补上原来唯一的阻塞决定与证据 | 能识别缺口已经关闭，不重复要求同一工作；仍可指出真实新风险 |
| 同一选择从当前 Owner 授权变为用户保留 | 行动从合法决定转为取得输入；不能继续替用户决定 |
| 同一代码从“模块定位”用途变为“副作用重试安全”用途 | 允许并通常需要更深证据；不能全局固定为架构级或代码级 |
| 等价函数拆分/命名改变，业务行为相同 | 知识中的关键行为结论保持；符号名变化不等于业务变化 |
| 只修改一条关键实现规则 | 能定位并更新相关事实与影响；不能只凭架构不变就宣称知识仍新鲜 |

这些是验收关系，不是给模型的标准答案。成对等价需要预先核对；一旦变化实际改变权限、可见性或任务含义，就不要求不变。

“两个合法深度都成功”是允许的策略差异；“同一缺口这次声明足够、下次要求补齐，且至少一次导致越权或错误”才是有害不稳定。判定不清时保留评审分歧，不为了整齐打唯一分数。

## 7. 最小实验分两步，避免取证差异掩盖机制变量

保留 A/B/C：A 为当前 WAE；B 为候选交接判据的一次充分处理；C 为同判据的显式自适应深度循环。A 允许在一次处理中自主深入。B/C 的相同预算上限不等于相同实际计算量，真实成本单列。

### 第一波：固定取证边界，验证深入表达与实际交接

F/K 各一个代表性切片 × A/B/C × 一次，共六个端到端 trial。K 先使用三组都可见的相同、有界、固定源码证据包，里面包含关键分支与有限干扰；这里测知识描述粒度和交接充分性，不声称已经验证自动搜索深度或节省源码读取。

D1/D2 降为设施冒烟，N1/N2 与新成对变体按预算分批选取，不一次堆成全量矩阵。固定证据版本可沿用原先“最多18次请求”的初步预算结构：六个端到端最多16次，另两个单次边界判断最多2次；包括一切真实模型请求，无隐藏 Reviewer。探活、无效响应或额外调用同样消耗总上限，必要时减少当波槽位并如实记录。

只有对照夹具、oracle 和驱动器自测就绪后才运行模型。第一波不能证明稳定性；再在冻结条件下有限重复并加入等价/敏感性变体。一次成功、各次中最好的一次或都选择停止均不能替代可靠交接。

### 第二波：真正的分步探索

第一波提供值得继续的信号后，K 从同一知识导航骨架和同一固定仓库起步，所有组具有相同只读接口、权限和总预算；允许 B 在普通单次综合工作段内正常检索，不人为剥夺其查证能力。C 的区别是显式的交接/深入决策，而非独享关键证据。

全部内部模型请求、工具读取、重复读取和接收者成本计账。该波在冻结 adapter 后重新确定请求上限；原18次和54次预算不自动覆盖工具型 Agent。若两组实际获得了不同证据，整体比较只说明组合策略的效果；另选同证据检查点才能隔离判断规则的影响，不能把全部增益归于外层 Loop。

两波都不接完整 WFF/EKRI 生产运行，不启动九次资格批次，不新增 TPlan/Hook/调度器。

## 8. 验收与停止投入

分别报告：应深入的遗漏、错误放手、过度深入、越权设计、无证据事实、首次交接成功、原有正确事实保持、读取/产物/调用/延迟成本。安全正确的 need_input 与完成本可完成的任务分开统计，避免“全部阻断”取得虚假高分。

对单一 oracle 能验证的结果使用行为测试；多个合法设计使用依照公开规则的多解验收；灰区使用隐藏组别的范围评审并保留不确定。参考可行解先验证 oracle，不能只把模型未提到的偏好写成失败。

模型稳定性不是让输出文字不变；是同样重要的事实和权限边界反复被保护，必要时深入、足够时退出，成本没有无理由膨胀。三次全成功仍只是小样迹象。

当前可以进入夹具与驱动器设计，不具备宣称稳定/有价值或推广正式 WAE Loop 的依据。若 B 已同样可靠且更省，采用单次加强；若 C 只能通过更多取证获益，先归因于取证策略；若 C 反复过度设计或把未知改写为事实，停止该候选后修正一个具体变量。
