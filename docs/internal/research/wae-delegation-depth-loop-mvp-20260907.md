## 1. 目标纠偏

用户定义的 Loop 是：当前负责人判断能否把下一层设计或实现可靠交给具体承接者；可以就交接退出，不可以就在必要的局部继续深入，再判断。

它不是通用的生成—评审—修稿循环，也不是要求 Reviewer 不断找新问题。核心变量是“负责人应亲自做到哪一层”，不是“同一份答案应该再改几轮”。

核心：**当前负责人把必要工作推进到足以可靠交给指定承接者的最浅层；只为尚未解除的实质性交接障碍继续深入。**

复杂度是检查信号，不是自动下钻指令。负责人可以补接口约束、详细设计、伪代码、核心实现或可执行示例，具体形式由缺口决定。它不固定为架构→详细设计→算法→代码的四级流程，也不要求上层包办全部模块。

## 2. 与当前 WAE 的关系

`skills/wae/resources/ownership-closure.md` 和已关闭 #149 已具备沿委派边界追踪语义选择、在 Mechanical Boundary 停止的思想。因此不是从零发明理论；待验证的是把这些判断变为真正驱动工作深度与交接的循环。

本候选扩展两点：

1. 交给机械执行器时，剩余语义选择必须确定；交给另一个 Agentic Owner 时，可以留下已明确授权、符合全局约束的合法选择。
2. 语义已经完整而承接者暂时不会可靠实现，属于能力/可验证性缺口，不冒称 Semantic Ownership Leakage。上层可补算法或参考实现，也可选择获准的更合适承接者。

这两点需通过实验再决定是否进入正式 Skill。当前机械停止条件仍然适用于机械委派。

## 3. 进入条件和输入

只有发生真实委派边界，而且误解/能力不匹配可能改变结果时才启动。低风险、已清楚且可直接执行的工作可直接退出。

最小上下文：目标与验收、不可变事实和约束、当前产物、拟委派范围、下层预期用途、承接者的能力/权限/可见上下文，以及本次资源上限。

充分性相对于这些条件成立，不是“完整理解一切”的认证。设计工作区分来源事实、Owner 在权限内作出的新决定、有意留给下层的自由；事实重建只依据被观察的固定来源形成事实或明确未知。探索深度与交接产物的保留粒度分别控制：可以读到代码验证，只保留必要行为事实与证据入口。

接收者按实际配置描述。模型显示名、角色名称和自信陈述不能单独证明能力；可使用相关历史表现、小型能力检查或有界实际接手证据。能力未知要保持未知；本试验不为了评估能力先跑一套大基准。

## 4. 唯一核心判断：能否可靠交接

每轮检查四件事：

- **语义**：是否还留有本层应决定、下层不得擅自决定且会改变用户结果的选择？
- **能力与权限**：指定承接者是否在允许范围内，且有合理依据认为其可以完成剩余工作？
- **可验证性**：完成与失败能否观察，关键错误能否被已有测试、反例或验收条件发现？
- **剩余风险**：交接后的残余风险是否处于本次已批准的范围内？

一个有效的下钻理由必须给出具体后果，例如：同一个输入，下层可能采用两种均符合当前模糊描述的解释，其中一种会违反上游目标；或者承接者在相关核心算法上已有可复现失败。

“还能更详细”“模块很大”“Reviewer 又想到了建议”不单独构成下钻理由。不同数据结构、函数分解或表现形式只要都满足合同，就不算必须由上层消除的歧义。

可靠交接不是零风险证明。结论绑定指定范围、承接者和证据；条件改变时可以重开。交接也不等于整个任务已经验收完成。

## 5. 主循环及权责

```text
当前产物 + 具体承接者 + 约束
  → Owner 判断交接缺口
    → 可以交接：输出交接包，退出当前 Owner 的深化循环
    → 本层可解决：选择最小充分局部工作，产生新产物，再检查边界
    → 缺事实/权限：请求具体输入或返回正确上游
    → 无有效下一步/预算耗尽：停止，保留未收敛结论
```

Workflow 管理次数、预算、版本、合法动作与结果记录；Agentic Owner 判断缺口、决定深化范围并实际完成设计/实现；Evidence 检验依据和实际交接结果，不替 Owner 发明业务选择。

Reviewer 可以提出候选反例，但不是每层固定角色，更没有“必须接受全部建议”或“必须零 finding”规则。默认不增加 Full Review、terminal Review 和多套评分。

四个决定足够：`handoff`、`refine`、`need_input`、`stop`。观察/小测试是取得证据的动作，不能偷偷变成无上限的重试分支。

`refine` 必须通过本层有权进行的设计或取证，产生与指定缺口有关的新决定、有效观察及工作产物，而不只是多一张表。知识探索不能靠改写摘要制造新事实，设计下钻也不自动扩大阶段权限。语义选择已完整后的普通拼写/语法错误留在相应实现修复流程；仅在新证据表明边界错误时重开 Owner 判断。

每次 refinement 后按实际依赖影响重新检查；不是只读被改的一行，也不重开全部已交接模块。负责人可以回到上层纠正错误抽象，而不是只能无限向下；实质回退仍消耗同一份预算。

## 6. 两种正常出口

### 机械交接

明确的结构化输入能够确定应有行为；未知输入有明确拒绝或降级路径。执行器可以是代码工具，不一定是 Agent。

### Agentic 交接

本层必须决定的约束已经封闭；允许下层选择的部分有明确范围，承接者具备相应权限和能力，结果可验收。剩余设计自由是有意委派，不是泄漏。

因此完整设计可以长成一棵不均匀的树：普通读接口停在架构/接口层；回放核心继续到状态规则、算法或参考实现；其他模块保持原交接状态。不是全项目一起多走一层。

## 7. 交接包

最终只携带下层实际需要的内容：

1. 目标、范围和已确定的关键选择；
2. 留给承接者的合法自由与权限边界；
3. 必要设计、算法或代码；
4. 验收、关键反例、失败/返回条件；
5. 仍未确认的事项及其对执行的影响。

不用把 Owner 的完整思考历史、前轮分数和所有审计记录塞给下层。最小性指不携带无关内容，不是强行追求最短字数。

MVP 的小型控制记录只记当前范围、选择的动作、具体缺口、工作产物引用、证据引用和累计成本。它是实验运行记录，不是正式 WAE Mission/账本/持久化协议。

## 8. 最小实验真正检验什么

假设 H1：在简单边界上，Loop 能及时交接，不迫使上层写完全部实现。
假设 H2：在含重要未决选择/困难核心的边界上，Loop 能局部深入，改善实际下层产物。
假设 H3：外部显式循环的增益超过仅增加指导和思考预算；否则采用更简单的一次判断。
假设 H4：缺事实、越权、无进展和预算耗尽时，不会靠继续深入伪造交接资格。

这些是假设，不是已证明事实。源码里包含规则、控制测试通过或本会话角色模拟都不能证实 H1–H4 的模型行为与价值。

## 9. 主验收家族：用户提出的两个真实需求

### F：P1/P2 的设计交接充分性

从小型审核工作台构造 P1→P2、P2→P3 的分别冻结检查点，不合并阶段权限。第一波选一个 P2→P3 切片：上游决定中涉及审核后修改、状态/权限和失败恢复的含义是否足够，使 fresh P3 能产出可运行的交互切片而不发明上游事实。

来源允许的多种策略都可接受，但必须由有权 Owner 明确选择；oracle 检查实现与选择一致。布局、组件等合法实现自由留给 P3。下层操作预演用于发现本阶段缺口，不启动完整 WFF/P3，也不把经常向上游返回当成正常主线。

### K：EKRI 的工程事实保真与保留粒度

固定一个含入口、调度、执行、去重与重试的小仓库。高层“支持重试与幂等”不足以回答副作用故障窗口时，应查明关键分支并保留必要行为规则、适用范围和准确证据，不把整段代码复制为知识。

第一波各组看到同一有界源码证据包，测描述深度和 fresh 接收者实际理解/影响分析；这是固定取证实验，不声称节省源代码探索。第二波再用同一只读仓库和相同获取预算测真正的自适应探索。

知识骨架保留模块职责、关键边界、证据入口和未知区域；声明支持的用途类别，独立测试从这些类别取未见具体问题。不能只背公开问题，也不能承诺覆盖所有未来任务。接收者先只用知识包；后续补查源码另计为缺口诊断和转嫁成本，不回写原 trial 为首次成功。

### 必须同时保护的边界

F/K 均准备“已足够”和“必须深入”的成对变体。N1 保留缺用户权限/事实时的准确返回，N2 保留完整合同上的普通机械修复。对称检查同义改写/顺序变化的稳定性，以及移除关键事实、改变授权、改变使用目的时的必要敏感性。

原 D1 只读查询、D2 事件回放降为驱动器/确定性 oracle 的开发冒烟。八个现有 Ownership Closure 案例也是开发素材，不当成新的独立泛化证据。以上都是待构建夹具，不是声称 WFF/EKRI 已复现这些具体样例。

## 10. 三组对照：隔离指导、额外预算和显式 Loop

同一用例、同一初始产物、同一来源和接收者配置：

- **A 现有 WAE 单次交接**：当前发布方法做一次 Owner 判断/必要工作后交接。允许它在单次内自主深化，不人为强迫错误的浅交接。
- **B 新交接判据，单次加强**：与 C 相同的判据、权限、可见材料和总 Owner 输出预算，一次调用完成最有帮助的设计/实现援助后交接。
- **C 同判据，显式自适应循环**：每次基于当前实际产物决定交接或局部深入，最多 3 次 Owner 调用，通常最多 2 次有成果的 refinement，再交给同样的接收者。

A 对照现有产品；B 对照“只是指令更好或多花了思考预算”；C−B 才涉及显式循环本身。三组均由一个 fresh 接收者实际执行对应下游任务，只收到该阶段允许的来源和最终交接包，不收到 Owner 轨迹、组标签和参考答案。K 的接收者首轮不读取原源码证据包，只读取知识包及公开任务，以免额外源码掩盖摘要遗漏。B/C 使用相同候选判据和参考材料，A 使用发布版指导；各组对应角色的可见输入、输出协议和可用工具条件一致。

固定证据第一波只返回文本/代码产物，不启用内部自动工具循环；公开样例或语法检查由驱动器执行，隐藏验收不反馈给 Owner。F 的接收者实现交互切片，K 的接收者使用知识包作有界理解/影响分析，二者不强行使用同一种输出。对需要上游输入的返回保持诚实，但 F/K 的来源已足够且本轮有权处理时，返回仍记为未完成交接，不能靠全部阻断取得高正确率。

真正检索的第二波给所有组相同只读接口和总预算；B 可以在普通综合工作段内正常检索。所有内部模型请求实际计数，不能把含十几次请求的会话算一次。如果取到的证据不同，整体差异只能归因于组合策略；同证据检查点对照才用于隔离边界判断规则。

第一轮固定 Owner/接收者的精确 provider、model、effort 与工具权限；不同时试多个智力组合。角色可以用同一模型的隔离上下文。更弱接收者或更强 Owner 是下一阶段单独变量；第一轮不预设更贵模型就是原因。

若 B 与 C 同样好而更便宜，就采用一次加强的 WAE 指导，不为保留 Loop 强行选 C。

## 11. 次数、预算与停止

先完成不调用模型的路由/预算/隔离支撑自测。它只验证实验设施，不证明方法有效。

固定证据第一波：F/K × A/B/C × 1 次 = 6 个端到端 trial；另选两个单次边界判断。A 最多 1 Owner + 1接收者，B 相同，C 最多3 Owner +1接收者，因此总上限18次真实模型请求。探活/无效响应/额外调用也消耗这个上限，必要时减少当波槽位并记录；没有隐藏 Reviewer 或不计费的补跑。

仅当第一波没有基础设施混淆且值得继续时，冻结同一协议再增加两次重复：F/K 获得每组3次，所选边界判断也各3次。固定证据版本累计18个端到端 trial +6个边界判断，上限54次请求；未见等价/敏感性变体另行有界排入下一小批，不自动扩成全矩阵。

动态检索第二波在 adapter 冻结后重新确定调用与文件/字节预算，原18/54次上限不自动适用于工具型 Agent。两波结果分开报告。

建议第一波累计墙钟上限30分钟、单调用180秒；这些是待实模启动时确认的实验资源上限，不是预估耗时，也不是 WAE 的产品级语义深度上限。具体 token 参数按所选 provider 的实际语义冻结：B 与 C 的 Owner 总上限相同，接收者上限相同；报告实际使用，不能用相同上限冒充相同花费。

基础设施探活也计数；确认调用不可用即在模型试验前阻断。超时和无效输出保留为相应类别，不以成功样本替换，不修改预算刷通过；配置或提示发生变化就产生新实验版本。预算耗尽输出未收敛，不能改写为可交接。

先不运行额外的 downstream→Owner 回流修复。首次交接是否真的够用是主指标；发现不够的轨迹成为下一版研究材料，不能在原 trial 内无限返工后报成功。

## 12. 评价与进阶条件

### 价值

主要评价下层的实际结果，而不是 Owner 的自评：关键合同正确率、源事实保持、越权选择、需要上层重新决定的事项、最终隐藏测试、总调用/Token/时长、局部下钻范围。上层写出的核心代码也必须执行测试，不能因为作者是上层就自动可信。

若 Owner 已经包办全部任务，结果单独标记为“Owner完成”，不能把空的接收者工作计入成功交接率。最终交付可仍然成功，但需完整计入上层成本和接管范围。模型正确返回与任务交付成功、代码通过与方法净收益分别报告。

允许不同实现满足同一语义合同。评测使用独立冻结的可执行 oracle 与人工范围审阅，不用另一个模型的大而全评分当唯一判断。oracle 的要求全部来自可见来源或被允许的明确选择；预先提供至少一个可通过的参考实现验证测试公平性。

### 稳定性

按同一用例多次运行和成对变体报告：错误放手、无依据深入、越权决定/事实、原有正确内容保持和实际成本范围。探索深度与产物保留粒度分别计量。方法可以选择不同合法深度，不要求全文hash、措辞、设计或轨迹一致。

同义/结构等价变化应保持关键语义结果；关键事实、用途或权限改变应引起必要的重新判断。只允许已声明范围内的结论；无法判唯一最浅点的灰区按可接受行为区间验收，并保留评审分歧。

三次全成功只是小样 repeatability 迹象，不是高可靠认证，不估算一个没有样本支持的百分比。初始反例不能作为对所有项目/模型的普遍判决。

### 是否进入下一波

- 出现越权、误冻结、伪造缺失事实或评测泄漏：停止当前候选并归因。
- 正确性不足但能精确定位：改一个机制变量，用新版本与未见变体验证，旧失败保留。
- F/K 的充分变体明显过度深入，或缺口变体的实际改善不足以抵消成本：不推广。
- B 与 C 等效：优先 B，结束没有增量价值的 Loop 路线。
- C 在复杂核心上反复有实质净增益、简单例不退化：进入第二个领域与接收者能力变化测试。
- 单个领域的小样通过后仍不直接发布通用 WAE Loop；正式 Skill promotion 单独评审。

## 13. 最小交付及当前完成范围

实施只需要：用例及oracle、一个小型实验驱动器、A/B/C提示、结果与成本文件。无通用agent平台、无多专家矩阵、无新Mission运行时、无WFF耦合。

推荐顺序：

1. 冻结用户定义、交接判据、两种正常出口和边界对照；
2. 写用例/oracle和最小驱动器，先做零调用自测；
3. F/K 固定证据第一波最多18次真实请求；
4. 根据明确失败决定单变量修订或小样重复；
5. 有净收益后才研究正式WAE入口与TPlan承载。

本轮完成的是设计和实验协议草案；驱动器、oracle、实模结果尚未完成。没有把两篇文档或未来测试计划算成可行性证据。
