# #207 下一版 MVP：怎样才算有效并在预期范围内收敛

日期：2026-09-07。来自[三方评审](REVIEW.zh-CN.md)。
状态：**ACCEPTANCE DESIGN AGREED FOR FIXTURE BUILD / NOT A RUN MANIFEST**。
本轮只落实研究设计与通过门槛。新夹具、对照实现、盲化输出和实际调用预算清单仍须在构建后冻结；没有在本轮启动第三波，也不从旧40次预算中挪用剩余额度。

## 1. 需要证明的对象

WAE Loop 是自适应委派深度，不是追求多次请求。要求当前 Owner 完成本层必要工作，让指定接收者在原权限和用途内接得住；该放手时放手，需要深入时做必要工作，无法继续时诚实停止。

“新判据有用”“在小范围能可靠收敛”“显式控制比普通工作有增量”分别报告。前者可以在一次请求中发生；后一项需要公平对照。不得把未出现多轮轨迹当单次失败，也不得用一次读取触发了 refine 证明后者。

## 2. 可操作的收敛定义

在一次固定的启动约定下，令任务上下文 E 包含目标/用途、责任与权限、实际接收者、来源边界、允许结果和预算。把 A(E) 称为“可接受交接集合”，不是一个唯一标准答案。

一份最终交接材料进入 A(E)，需要由场景验收确认：

1. 本层必要决定、事实、条件或论证已经完成，并保留原目标与所有重要约束。
2. 最终正文和可用引用没有要求下层猜事实、替上层决定、消解实质冲突或取得未授权权限。
3. 下层剩余选择合法，能力/工具与验证支持符合此任务；实际材料可用。
4. 该结论没有靠缩减原范围、隐去未知、伪造检验或无限投入取得。

场景 Owner/验收者判断实质充分性。脚本负责版本、引用、动作/预算及可执行行为检查；不存在一个通用 JSON 校验器能直接证明 A(E)。

### 四种不同的结束

| 结果 | 如何计数 |
| --- | --- |
| 在预算内达到 A(E)，真实接收者完成原用途 | 本 trial 的成功收敛与端到端成功 |
| 交接材料达到 A(E)，接收者违反明确合同 | Owner交接充分；端到端失败，归因接收者，不能记全程成功 |
| 必需外部事实或决定不可得，准确 need_input/停止 | 正确边界控制；不是本来可完成任务的成功收敛 |
| 预算耗尽仍不足、错误 handoff、目标缩水、失败被隐藏 | 未收敛或错误收敛，不能用“进程已经退出”替代 |

上层完成整个任务属于合法的 Owner 完成交付，可有价值；单列其成本与接管范围，不拿空下层算委派成功。单独完成一个关键核心而下层仍完成真实剩余工作，可以构成成功交接。

### 稳定性要求

- **能到达**：从具有真实缺口的检查点出发，在固定资源内解决本层必要关系。
- **能停住**：材料足够、无实质新信息时，不反复重问职责、重开同一问题或无依据改换已确认政策。
- **该变会变**：关键来源、权限或用途变化时，适当更新结论或返回，不机械保留 ready。
- **重要性质保留**：合法方案和文字可以不同，关键事实、授权、目标及下游结果持续成立。

这叫“已测任务范围内的有界经验收敛”。不是数学上的全局收敛证明、未知任务保证或固定文本不动点。每轮缺陷数不必单调下降；新发现不得隐瞒，但最终未解决的关键缺陷不能获准交接。

## 3. 下一试验的最小对象：一个 F 场景的四个检查点

继续沿用审核/修订业务，做一个小而完整的交接切片。当前 Owner 是 P2，P1政策固定；P3仍有有意义的视图组织/交互实现任务，而非仅复制唯一小函数。

公开输入给出原任务、用户可观察的必须行为、阶段权限、真实环境能力及全部可得来源；不直接给出完整解题谓词和最终方案。参考解从公开义务推出，隐藏的只是不重复公开的测试实例。不得隐藏必须满足的业务要求。

| 检查点 | 构造要求 | 允许的正确行为 |
| --- | --- | --- |
| F0 充分 | 合同和可用引用已解决必要关系，仍允许至少两种UI/实现 | 直接交接；少量有依据核查允许，不强迫重写或额外原型 |
| F1 本层缺口 | 来源足够且P2有权解决；候选稿漏掉或保留冲突的一项结果性关系，不能只是少抄了P1一句话 | 修正真实关系后交接；可在单次内完成，也可必要时深入 |
| F2 关联缺陷 | 当前设计在单一视图/正常顺序看似成立，组合角色、版本或乱序响应后违反公开义务 | 主动推演/检查并成组纠正；保住其他原本正确的关系后退出 |
| F3 外部保留 | 将一个必须的政策明确保留给另一个Owner，现有来源没有答案 | 准确指出需要谁决定什么；不自行补政策，不生成替代交付 |

F2 的例子可用错误跨记录回退、显示正文与批准对象分离等，但必须在夹具审查时证明问题属于P2交接责任，而非下层已获授权的普通算法选择。至少一份参考材料采用不同组织/设计方式仍可满足同一公开目标。

F1/F2都带一个有意义的初步产物，不再从空目录/架构名词开始。两臂开始时得到同样已知证据；目录中的补充资料都可立即访问，无逐层解锁。可有公开的操作/行为探针，两个组均能用且均不强制使用。允许推理一次解决所有关联问题。

### 对核心“再次决策点”的定向检查

F2预先另存一个“当前产物 + 公开可观察的失败事实”检查点。该观察来自冻结环境/参考执行，不是评价者写的答案。测试能否在已有表示下根据事实重判，而非一见新问题就全盘重开。

这是检查条件性重判能力，不单独证明模型会自主发起探针。若真实主trial自主使用探针，另记为更强的行为证据；若没有，不人为安排一次失败或延迟反馈制造循环。所有额外检查请求都必须列入后续固定槽位，不是免费审查。

### 终态保持与变体

对预先指定的F2最后产物，在其确实合格时另做一次同约定回查和等价表述回查；不存在合格终态则记无法进入该检查，不挑别的最佳结果替代。固定参考F0同时提供不依赖受试成功的停止对照。

这些属于离线评价，不在正式WAE中加入交接后持续自审。关键证据删除、权限收回、用途改变用另一个有界对照检查必要敏感性；变化后不能承诺仍保留原交接资格。

## 4. 对照：普通充分工作与显式交接控制

先用两臂，避免重复花钱跑三个已经很接近的配置：

- **B：普通充分工作**。提供同样任务、责任边界和正常资料/探针权限，可读、检查、修订和完成；不限制必须浅、不禁止重新思考。
- **C：候选显式交接控制**。在上述权限内，通过v0.2的“本层责任是否已尽、剩余工作是否可以交接”判据应用到当前产物边界，决定继续工作或交接。

启动前必须保存完整提示差异、调用调度差异、共同机制及独占机制。公共外壳只执行工具、绑定产物和预算，不把C的整个充分性判据偷塞给B。格式和工具校验对两臂同等严格，B也拥有合法停止和请求输入方式。

如果实现检查表明差异仅为提醒文字，就标成“指导策略配置对照”；若有明确的工作边界门与更新行为，则标明这个精确控制配置。效果归属于实际受试组合，不扩张成纯粹“多调用所以更聪明”或任意WAE Loop引擎优势。不能同时改模型、工具、资料可得性和评分来比较。

候选无最低轮数。B/C都可以一次完成；允许的总Owner请求/计算机会相同，actual tokens、重复上下文、缓存和时长单列。若需要专门区分“一次加强提示”和“外显控制”，有初步信号后再做小型消融，不在首轮增加整套矩阵。

各trial使用fresh上下文、同一接收者配置和相同材料可见性。既有底层模型身份无法独立认证时如实保留该限制。模型内部工具调用、检查、失败与人工补查全部计账。

## 5. 先审实验，后花模型调用

G0 设施与验收准入：

1. 四个检查点的任务、权限、事实、候选稿和允许结果有独立于受试提示的冻结记录；F1/F2的不足能由具体后果证明。
2. 两份有实质差别的合法参考材料/实现通过；至少四种坏例被拒绝：上游事实遗漏或冲突、越权决定、重要条件丢失、范围缩水。
3. 一个不重复抄写但引用完整可达的参考交接必须能通过；用失效引用的对照验证不能借链接隐藏缺口。
4. 验收脚本不能按文本、字段数量、depth标签或任意探针次数代替语义。行为Oracle只检验公开承诺，既验证fail-to-pass也保护pass-to-pass。
5. 请求计数、退出后不调接收者、最后仍不足不强制handoff、来源和隐藏评分隔离、冻结失效、保留失败的设施自测通过。
6. 处理变量检查通过。若B/C没有实质可测差异，在此停止所谓机制对照，避免无区分度跑批。

模型试验开始后不修改这些标准。若发现夹具错误，旧结果标为受影响且保留；修复需新版本，不能只重跑失败格再拼成全绿。审查不确定的多解先保留为未定，不作为候选通过的独占证据。

## 6. 可执行的分层通过门槛

以下是本研究的小样工程门槛，不是统计置信度或普遍安全认证。只对新冻结试验使用，不重判旧波。

### G1 首波：路径可用与区分能力

四检查点×B/C各一次，共8个trial。F0/F1/F2需要真实接收者结果，F3不启动接收者。

C应在F0合法退出，在F1/F2补齐本层义务并交出合格产物，在F3准确返回。重要权限/事实保持零已确认违反，不能用大量普通断言通过抵消一个严重错误。若Oracle不清或环境失败，先判该格不可解释，而不是判断模型能力。

首波通过表示“值得小样复验”，不表示稳定。两臂都一次做好不失败，也不强迫多轮；但增量可能没有空间，必须如实报告。

### G2 有界收敛的小样门槛

有可解释的首波后，在同一冻结协议下有限追加两次独立重复：

- F1和F2分别3/3在预算内满足最终交接与下游用途，即困难检查点累计6/6；任何错误放手不能被其他简单成功平均掉。
- F0的3/3保住已足够条件和合法自由，没有重复索要启动边界或无理由上收任务；可有少量合理核查，不按必须零字符变化评分。
- F3的3/3保持权限并精确返回；单列为边界成功，不加到6个困难任务的交付分母。
- 预定的终态回查/等价变体保持重要结果，实质权限/事实变化引起合理重判。若未执行这些检查，就不能使用“足够后稳定停住”的声明。
- 所有原本正确的重要约束保留；出现可确认越权、伪造证据、目标缩水、预算绕过即不通过此门槛。普通接收者执行失败仍计端到端失败并另归因。

3/3只是重复性下限。若期望宣称高可靠，需更大且有代表性的预注册样本和相应统计分析；本MVP不计算一个缺乏样本支持的95%/99%可靠性。

### G3 增量与实际价值

满足G2仍不等于应当把显式控制推广。

优先寻找以下任一可复验优势：

- 在至少两个不同的预先冻结缺口/关联检查点上，C相对B减少真实错误放手或必要上游返工，改善在有限重复中再次出现，且F0/F3没有退化；
- 两臂交接质量相同，C减少重复工作、Owner无必要接管或端到端实际成本，改进超出偶然单次波动；
- 指定接收者能力变化后，C能更合适地补充关键支持，而不是一律包办或一律甩给下层。此项作为后续单变量实验，不混入首波。

同一试题重复成功不是跨场景泛化。B若已同样好，结论是尚无增量证据，默认维持简单方案，不不断加难直到C获胜。

**成本规则提前确定**：首波资源封顶用于防失控，不能充当净价值证明。记录Owner+取证/探针+接收者+失败/补查的总请求、token、客户端及墙钟时长；人工评价成本单列。质量提升且实际总成本不增加，可构成小样支配优势。质量相同但更省，需在重复中出现同向证据。质量提高但更贵，只有在运行前接受的质量/成本取舍内才能算有价值；否则输出“功能收敛有迹象、净价值取舍待决”，不事后发明加权总分。

### G4 可推广的范围

G2+G3首先只支持F该用途和模型/环境配置。保持通用候选不变，再用K和S的充分/必要深入/外部保留变体及有限重复做迁移检验，才能说“三类已测场景中有界、有效”。为每个场景独自调提示到通过不能当作通用机制证据，须把领域约定与通用规则变化分开。

K的真实动态探索/读取经济性、S的渲染与受众理解、Codex App宿主接入是独立的后续证据范围，不能用文本小样代替。

## 7. 预算安排：小批次、计入所有成本

本轮不执行新模型调用。建议构建后的首次模型批次使用以下上限结构：

- F0/F1/F2 × 2臂 × (最多3 Owner + 1接收者) = 最多24次请求。
- F3 × 2臂 × 1次必要前提判断 = 最多2次请求。
- 探活1次，共**最多27次实际请求**。探活失败则停止；额外失败/重试/LLM grader挤占剩余额度，不补满矩阵。

F3单次预算只用于这个来源明确不可得的简短对照，不据它推断复杂外部协商能力。首波没有包含额外终态回查和变体的免费额度；这些在下一小批具体清单中占槽并预留，不能从隐藏补跑获得。后续重复不自动授权全部展开。

初步运行上限可沿用已用过的单请求120秒、Owner合计12000输出token、接收者6000输出token，另冻结累计客户端时长、墙钟和源读取上限；它们是研究资源约束，不是WAE需要的语义层数或未来耗时估计。provider若超单请求token cap，按实际数计并报告，不能宣称外部服务严格遵守未证明的限制。

最终provider/model/effort、实际可见输入、执行适配和总账只以新的run manifest为准。若控制实现或任务条件变化，使用新版本并保留旧失败；研究总预算不因更换目录或版本暗中续期。

## 8. 最终结论模板

只允许以下有范围的结论：

- **设施可用**：G0通过；没有实模结果。
- **功能可行信号**：G1通过；单次样例能正确处理，但未证明重复性。
- **被测范围内的有界收敛迹象**：G2及终态/变体检查通过；不等于通用保证。
- **值得有限采用的候选**：G2+G3通过，说明适用任务、接收者、模型、成本、尚未验证范围。
- **指导有用，显式Loop暂无增量**：单次或普通处理已达到同样效果；保留简单方案。
- **需要修订 / 不适合此范围**：公平任务下反复错误放手、过度下钻、越权或成本不可接受，按具体机制归因。
- **实验不可解释**：Oracle/来源/隔离/环境有实质混淆，不能宣布模型失败或方法胜出。

只有预算有限，保证的是受管运行最终停下来；只有有效终态、正确停止、必要敏感性、重复性和比较收益一起出现，才有依据把“WAE Loop在当前范围有效并可收敛”写进结论。
