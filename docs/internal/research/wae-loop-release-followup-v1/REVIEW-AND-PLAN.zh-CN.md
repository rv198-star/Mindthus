## 1. 核心裁定

G1 的实际交接结果保留；G2 的重复性、终态保持和变化重判尚待检验；G3 的显式策略增量尚未建立。纯合成环境仍适合做合同、回归和边界复验，但继续制造更复杂题目对“真实使用价值”的证明边际收益已经明显降低。

用户随后明确首版形态：**不是让 Agent 按需想起 WAE Loop，而是 Loop 默认关闭；一旦用户、项目或授权宿主对 bounded scope 显式启用，该 scope 内所有相关 responsibility handoff 都必须经过 WAE checkpoint。** 是否启用是显式控制事实；启用后是否执行交接检查不是 Agent 的自由选择。

因此下一阶段从“继续大规模合成 G2”调整为 **Explicitly Activated WAE Loop real-project pilot**：用 WFF / EKRI / Slidethus 三种真实交接验证深度判断、下游结果和实际成本，合成测试退回协议/回归角色。真实项目必须默认留下 project-local trace，方便后续取回做 G2/G3 裁定。

**计划应当能够走向发布，也能够依据证据结束而不发布。** 真实 Pilot 不能用 opt-in 名称绕过价值验收；如果普通工作已经同样可靠而 Loop 只增加负担，应结束 Stable 推广，而不是继续加难直到候选获胜。

当前第一实现形态已经收敛为现有 WAE 内的**显式启用委派深度模式**：启动时确认一次职责/自由/保留决定/用途；Active scope 中每次交接检查 `handoff / refine / need_input / stop`；外围任务系统继续管理调度、预算和恢复。首版不交付研究跑批器，不新增通用 Agent 框架，也不要求固定 Reviewer 或最少轮数。

真实 Pilot 日志固定写入 `.mindthus/wae-loop/`，每个 Run 生成可单文件取回的 `wae-loop-run.json`。Trace 只记录 observable activation/checkpoint/work/outcome、artifact ref/hash、可得成本与 telemetry coverage，不保存私有思维链或整份 artifact 正文。宿主级 Stop/SubAgent 物理拦截需按实际 host 单独验证，当前不提前造通用 hook 大系统。

## 3. 第一方：实验可信度与统计归因

### 质询 A：两组都通过，为什么还值得继续？

方法方主张：C 在 F1/F2 修正必要义务，F3 正确保留他方权限，是实际功能证据。

实验方反驳：B 也做到了，本波四格的 C 耗时和报告 Token 全高于 B。不能把绝对成功当成采用 C 的理由，也不能因为没取得增量就继续换更难的题。

裁定：G1 功能信号保留，不扩大成独有能力。G2 可以回答可重复性；只有预先冻结的实际质量、成本或适配改善才能支持 G3。当前数据既不支持 C 更优，也不证明普遍等效或普遍劣势。

### 质询 B：现在测的是方法、指导，还是 Loop 引擎？

`run.py` 的 `init()` 将 scheduler_difference 记录为 none。B 使用普通专业工作指导，C 加载候选 v0.2；共同控制器、工具、预算、接收者一致。八个 Owner 都只用一次调用，公开探针为 0。

裁定：准确对象是同一有界控制器上的指导策略配置。合法一次深入可以成功；但不能用此证明实模多步反馈路径、持续会话中的重判或宿主强制控制。下一步用已约定的终态和变化检查补这一证据，不要求人工制造最低轮数。

### 质询 C：F0 扩写是不是接口强制的，因而不能算成本问题？

核对 COMMON：明确允许原稿不变，也允许对当前稿给出可用引用。F0 从1326 bytes变为B3177/C3290，并非接口强制必须改写。但两组都扩写，所以不能独归因C；合理的澄清也不能仅凭长度判错。

裁定：保留“重复表达成本待解释”的观察。终态检查记录新增内容解决了什么任务问题、是否只是重排和复述；以行为和实际用量为主，不引入通用字数硬阈值。若以后做简化提示实验，另定版本，不把旧C的证据直接移植到新候选。

### 质询 D：三次全通过就可以说稳定吗？

裁定：原G2门槛是小样工程准入，不是概率保证。旧G1 v2可作为同条件第一次；停止的v1不能混入。新增两次必须保留所有结果。实质协议/源内容改变后使用新版本，不能挑三份成功凑3/3。

## 4. 第二方：方法价值、发布对象与用户预期

### 质询 A：为了更稳，是否需要让 Owner 先提交，再由另一个 Reviewer 放行？

工程方认为这样能观察真实重判；方法方指出这会把原来的委派深度变成常设审批流程，与用户“一次定界、该放手就放手”的目标冲突。

裁定：保留 Agent 的语义决定权。控制器只应用决定和资源约束，必要时接收真实检查结果；不为了研究区分而新建默认 Reviewer、终审、分数门槛或逐层解锁。一个明确反例可促使深入，一次修正足够也可直接退出。

### 质询 B：什么应当成为正式产品？

候选核心可以形成现有WAE的条件模式，而不是公开一个绑定实验网关和合成题库的run.py。首版产品应包含简短主路径、可复用的启动约定、合法Agentic交接出口、几个正反例和与外围执行的清楚边界。

尤其需要处理现有公开规则与候选的关系：原 `SKILL.md` 和 `ownership-closure.md` 的停止描述集中在 Mechanical Boundary；候选同时允许有权且能接手的 Agentic 下层。用户批准研究实现后，当前 #207 工作树已按同一 canonical rule 统一 Mechanical / Agentic 两种出口；Stable main 尚未包含这项改动，是否发布仍由真实 Pilot 证据决定。

### 质询 C：没有G3能不能换名成“指导增强”先发？

裁定：原候选的Stable推广仍需要G3。若有限收口后C没有增量，结束这一推广路线，研究结果保留。可以另提更小的文档澄清或指导精简，但要明确新范围和对应验收，不把它记成原Loop通过，也不把当前普通B的成功宣称为某个新Skill已验证。

研究材料可合并与功能可发布是两件事。显式opt-in降低触发范围，不证明净价值；Experimental资格也不是Stable资格。

## 5. 第三方：工程、维护与发版

### 质询 A：能否直接用现有命令跑两次G2？

不能直接重新初始化旧命令。当前 `run.py.CONFIG` 固定历史 campaign_started_epoch、停止前版的调用和扣费数据；运行身份与实验内容耦合。照搬会沿用旧墙钟/预算，或者诱发手工篡改冻结文件。

裁定：给复验增加最薄的启动适配，分离不变的任务/指导/评分/角色可见性与本批次新批准的时间、预算、输出根。旧文件与旧结果不改写；新适配有新代码身份，逐项说明允许变化。重新自测数据、提示、调用机会和接收者一致，不把适配差异隐藏为精确同一执行实现。

同一复验campaign内失败/版本纠正继续累计，不因新目录清零；新批次只有在明确冻结批准预算后才有自己的起点。provider报告、实际用量、未知底层模型身份继续记录。

### 质询 B：研究脚本是不是已经等于将来的运行时？

不是。它们包含固定题库、评测oracle、研究输出、单一provider/effort配置与历史时钟，是实验设施。公共包按allowlist排除 `docs/internal/`、原始响应、私有端点与本地路径。G1成功不支持把这些脚本直接搬到 `skills/wae/scripts/`。

研究分支已增加最薄的公共确定性支撑：显式 activation、project-local trace、`guard-handoff` 和 trace validation；它们只执行状态/绑定/日志合同，不判断 semantic sufficiency。正式发布前仍需在真实宿主确认 handoff carrier 的接入价值。TPlan继续管理Mission，#200/#146继续负责各自的外部续投/宿主问题。

### 质询 C：ROI Beta 是否适合先承载尚未验证的WAE？

不是默认实验桶。项目默认规则要求ROI Beta从精确Stable shared core继承；overlay只包含已资格验证的delta。不能用ROI Beta名称绕过当前WAE资格。受控候选体验先使用明确研究分支/隔离安装；如要新增独立预发行轨道，应另提明确范围，而不是本轮自动创建。

### P1 有限G2收口：先明确清单，再运行

1. 冻结复验启动适配；仅外层执行身份变化，v0.2候选、G1修正版任务/评分、角色资料和对照指导保持不变。补引用缺失与坏例检查，旧G0逻辑继续通过。

3. 另预注册一个小批次，最多27次，检验首次G1修正版F2终态：同约定保持、等价材料保持、真实权限变化、F2既有稿加公开行为事实后的重判。每类在B/C上检查；必要的接收者复核和LLM评估从同一上限扣除。检查不到的项记未执行，不能免费补跑或缩窄门槛。
4. 首个C/F2不是合格终态时按旧协议记不可进入对应终态回查，不挑后续最好样本替换。等价变化先核对真的等价；权限/必要证据变化需要一致地更新来源和启动约定。删除一条非必要证据而剩余材料仍充分时，不强制撤销交接。

P1的81是三个小批次的合计硬上限提案，不是应花满目标、当前授权或时间估算。任一已确认阻断缺陷先停受影响试验并保留成本；不按计划机械跑完矩阵。三个批次的先后可让最有区分能力的终态/变化检查优先，G2最终必须满足原全部条件。

复验只证明这些检查点和配置的重复性。收到公开事实后会重判，与自主发起探针，是两个声明；自主探针未出现就继续保持未证明。

### P2 G3净价值裁定：以观察结果决定继续或结束

对同条件B/C复验，按公开义务与实际产物盲化配对复核。这里盲化需要未见组别的新上下文或另一真实评审者；本会话已见结果，不能声称自己现在变盲。记录评审者身份、共享模型偏差及分歧。确定性行为仍用oracle，争议不由多数票或单一美学分决定。

不新增事后总分。原G3的两类缺口改善、同质量实际节省、或预注册的承接能力适配优势保持。指导篇幅/缓存/网关开销都计入，但不凭它们将质量差异自动归因。

若B继续同样正确且更省，输出“候选功能可行/可能可重复，原显式策略暂无采用依据”，结束当前Stable推广。一个更轻的候选或新真实失效场景只能作为新假设登记，不能不停改题直到C胜出。

### P3 保持方法不变的K/S迁移与实际试用

仅在P1/P2支持继续时投入。K/S沿用同一通用候选，仅替换领域启动约定、材料和验收；各保留充分/必要深入/外部保留，以及有限重复。事先定义迁移门槛与预算；修改通用指导视为新候选，不把场景专用调参拼成泛化证据。

K首版可宣称的范围限于有界源码事实交接；若宣称自主搜索经济性，就必须再测真实按需读取与接收者补查成本。S页面表示只支持语义保真；若宣称实际幻灯片表达，需要渲染结果和与目的相关的审阅。能力声明匹配证据，不要求为了首版把所有可能能力都做完。

选择一个代表性真实使用环境做前瞻性隔离安装试用，例如Codex App中显式调用。记录实际版本、加载路径、模型/推理配置和输出，验证一次启动复用、必要深入与停止、资料可达、无新权限/预算。这是部署适配证据，不是统计价值样本，不要求重跑完整16小时事故。

### P4 最小产品化和最终发版

通过相应门槛才启动正式修改。预期触点为现有 `skills/wae/SKILL.md`、`resources/ownership-closure.md` 和一个按需详细资源；只在必要时更新共享引用/fidelity说明。以同一canonical规则处理机械/Agentic交接，Minimal WAE默认入口继续轻量；不默认加载全部研究文档。

逐项对照已测 `candidate.md` 与实际安装后的指令，确认没有丢条件或多一套相反的退出规则。打包后的角色上下文若比研究中更长、更复杂，也视为可能影响行为的处理差异，运行小范围行为回归，不能仅凭文件存在判等价。

在干净工作树、声明支持的Python下运行完整unittest、Test Lifecycle、WAE定向、打包与引用检查；当前CI使用3.11，已知下限3.10需保持或明确调整。所有五布局包括必要资源且可独立解析，不包含研究脚本/原始案例/私有配置。新增测试围绕不变量，登记生命周期，不扩张无效逐字匹配测试。

版本面、CHANGELOG、能力/证据矩阵必须写清支持场景和未验证边界；新增兼容能力按minor评估，而不将其包装成bugfix。最终版本号按届时main确定，本轮不预定标签。

Stable发布默认同步同版本ROI Beta，精确shared-core继承、namespace隔离、三份归档与SHA256SUMS、可复现构建和发布后下载/源码验证沿用现有规则。研究合并、功能合并和发布分别有明确状态。

## 8. 结束条件，避免研究本身螺旋

有限收口后只能选择：

- G2/G3和宣称范围迁移成立：进入最小产品化，输出受限而准确的能力说明。
- 功能成立而增量未建立：保留证据，暂停原显式策略推广；不继续同型加压。
- 公平试题下出现实质失败：定位Owner缺口、交接表达丢失、接收者偏移或机制误用；只改成立根因，版本隔离后复验受影响范围。
- 夹具/环境混淆：标为不可解释，保留全部成本，不归因模型失败。
