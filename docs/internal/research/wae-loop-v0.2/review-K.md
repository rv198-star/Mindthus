# 第二场评审：EKRI——知识什么时候够用，什么时候只是被压缩得很短

日期：2026-09-07。关联：#207 / Draft PR #208。
输入固定为 `59d8cbfc81531978a59fc0d63638d593b6499dba` 的 WAE Loop v0.1 设计与评审包。
方式：本会话 ChatGPT 分别采用程序分析、知识使用者、知识建模与成本三种立场交叉质询。不是隔离模型实验，不是 EKRI 生产审计；全部小代码轨迹和反例为合成设计推演。

## 1. 三个立场为何冲突

**程序分析立场**：没有追到实际控制流、状态和失败分支，就不能说支持幂等。应深入到可证明相关行为的实现。

**维护使用者立场**：我需要能作决定的结论，不是十个文件链接和一句“存在风险”。但知识包若取代源码成为未经约束的第二份真相，也不能信任。

**检索与成本反方**：看完整个仓库再压缩成三句话，证明不了自适应探索。所有未知都要求继续查，也会把事实系统变成没有退出条件的扫描器。

共同初判：原方案分开探索深度和保留粒度是对的，但必须进一步区分“有证据身份”“证据支持这个结论”和“这个结论足以服务用途”。

## 2. 争议 K-01：读到本地重复调用路径，可以断言实际副作用会重复吗

定位：v0.1 §4–§5、评审包 K-gap/K-unknown。

### 合成最小轨迹

固定来源描述：

```text
若本地状态 done 则返回
调用外部 deliver(key, payload)
写入本地 done
```

任务说明允许失败后重试。外部 deliver 成功后，本地写入可能失败；外部服务的幂等合同不可见。

可支持结论：在已描述条件下，下次执行可能再次调用外部 deliver。
不能直接支持结论：重复外部副作用一定发生；或者绝不发生。

程序分析立场若坚持追完外部实现，会在无访问权时耗尽预算；使用者若接受“肯定重复”，会把条件性风险当成既成故障。

裁定 R4：充分性针对任务要求的结论强度。若任务是识别本地故障窗口，明确条件、调用次序和外部未知后可以交接；若任务是批准“生产绝不重复”的承诺，则外部合同是阻塞输入。相同来源、不同用途允许不同退出，未知不是统一 need_input 信号。

这不是降低原目标：初始请求保证时，不得临时改成“仅识别可能性”并报完成。

## 3. 争议 K-02：证据引用完整，知识结论就可信吗

定位：v0.1 §8。

反例：摘要写“幂等保证已验证”，引用确实存在的 retry.py 及准确哈希，但文件只证明本地完成标记去重。文件引用正确，结论仍超出证据。

反例二：知识构建过程已经理解“外部成功—本地标记失败”的窗口；输出压缩时只保留“支持重试与幂等”。内部理解正确、最终交接却重新变得错误。

裁定 R5：对**实际交接文本**检查结论、条件、来源与未知是否一起保留。摘要的关键条件不能只藏在作者上下文或不可达引用中。引用闭合只保证能找到材料，不保证逻辑蕴含；后者仍需语义判断或可执行行为证据。

保留最小行为关系通常比复制函数更有用：去重范围、外部调用时点、完成标记时点、失败后路径、部署未知、准确证据入口。它们是该用例激活的事实，不是所有模块必填的六列 schema。

## 4. 争议 K-03：短摘要的字数能否当作“最小充分”

反例：系统读完一万行后交付“具体见源码”；接收者被迫重读。另一系统只保留三个行为事实和两段必要摘录，稍长，却足以支持任务。

裁定：总体成本包括作者取得事实、保留产物、接收者重新理解、失败与返工。短文字不是独立收益指标；不能把成本转移到另一个角色后宣称更省。

R6：第一波固定同样证据，只能评价表示和交接，不宣称扫描经济。第二波才让各组从同一知识骨架自主查证，记录所有模型请求、读取与重复读取。若证据集不同，先报告策略总体差异；同证据条件下的补充比较才用于归因边界判据。

正常 query-first 知识产品允许按入口再取证。是否允许接收者补查必须在用途和实验可见性中预先确定；本 MVP 的固定证据包测试不能偷换为“所有未来 EKRI 任务都不得查源码”。

## 5. 争议 K-04：任务定向知识会不会退化成背一道题

反例：作者看到唯一问题“是否重复调用”，只记录一句答案；接收者被问到同一行为范围内的“修改完成标记顺序影响哪类失败”，又无法作答。若隐藏测试转而要求整个数据库迁移方案，也是不公平扩题。

裁定：启动用途应是一个有边界的任务家族，保留最小导航骨架和与该家族有关的行为关系。隐藏的是具体输入与问题表述，不隐藏要求涉及的业务边界。未知未来用途不在当前充分性保证内。

R6 的评测修正：至少两个公开可行表示通过，不要求唯一段落；关键条件删去的坏例必须失败。若只会复述公开答案，不能称可用知识资产。

## 6. 争议 K-05：代码、文档、运行配置冲突时谁更权威

“代码永远比文档权威”也不充分。固定源码可证明这个版本的静态路径；部署配置可能关闭该路径，外部服务可能改变可观察效果；政策文档可能描述应当保证的义务，而不是实然行为。

裁定：按声明对象区分“源码表现”“预期合同”“实际部署”。证据冲突暴露为冲突，不能自动靠来源名称定胜负；缺运行观测时限制部署声明。查无结果不证明不存在。

来源版本变化时检查受影响的事实，不重复确认四个职责问题。等价重构允许保留行为判断但更新引用；关键时序改变需要重建相关事实。hash 用于身份，不裁决语义等价。

## 7. 最强反对意见：越查越深无法证明没有未知未知

反方指出：正向任务和关键失败窗口只是有界样本，不可能证明任意未来问题的完备性。Owner 若总能再构造一个新问题，预算会成为唯一实际退出条件。

裁定：约定用途之外的新问题不自动扩张责任；本用途内的实质新反例可以重开受影响结论。退出是有范围的合理交接，不是全知证明。不能要求模型每轮证明“再也不存在风险”，也不能用一个主观置信分数替代现有事实。

保留待实测风险：模型能否稳定识别任务内/外，能否保住压缩后的关键条件，三轮是否有增量。纸面规则不解决这些能力问题。

## 8. 本场结论

接受：R4 用途所需结论强度和条件性退出；R5 实际交接文本的事实—条件—证据对应；R6 分开探索、表示、消费成本与公平用途覆盖。

拒绝：必须消灭全部未知；全部外部依赖追到实现；所有代码逐行录入；字数最短获胜；链接正确就算事实正确；用答案列表替代工程知识；把静态源码直接认证成生产保证。

回查结果：定位入口→允许浅停；识别本地重复窗口→深查关键分支后可条件性交接；要求外部绝不重复→缺合同则 need_input；准确链接但夸大保证→refine；只缩短文字而丢条件→退化。

本场结论：**修正后适合固定证据 MVP；自主探索效果必须单独实测。** 未新增真实用户案例，未修改 EKRI。
