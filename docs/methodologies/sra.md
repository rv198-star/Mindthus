# SRA / Scarce Resource Allocation / 稀缺资源优先分配

## 这是什么

SRA 用来解决一个很直接的问题：

> 时间、人力、资金和注意力都有限，当前到底先把资源投到哪里？

它适用于多个事项都值得做，但无法同时获得同一批稀缺资源的情况。SRA 不只生成一个
`A > B > C` 的排序，还会判断：

- 哪些事项共同构成达标所需的最小组合；
- 哪些小事项会改变方向、解除瓶颈或避免不可逆损失；
- 哪些工作只需要维持最低维护线；
- 哪些正确的事现在必须延后或停止；
- 是否应该保留一部分资源作为机动量；
- 资源、证据、风险或时间窗口变化后，何时重新判断。

一句话：

> **先保证目标能成立，再把下一份资源投给最能改变结果的地方。**

项目地址：<https://github.com/rv198-star/Mindthus>

## 解决什么问题

很多资源浪费并不是因为正在做的事情完全没价值，而是因为它仍然“可以继续变好”。

例如一个页面已经达到上线门槛，动画还能继续优化；但支付链路尚未验证。继续做动画并不错误，
只是它已经不再决定本轮目标能否成立。如果没有一次明确的资源判断，当前任务会因为已经打开、
已经投入、继续起来最顺手，而不断获得更多时间。

SRA 处理的就是这种竞争：

- 当前任务继续做，还是切到更关键的任务；
- 新发现的问题现在修，还是记入后续；
- 多个产品问题谁进入当前 Sprint；
- 故障、合规、技术债和新功能怎样争夺团队资源；
- 现金有限时，完整建设和方向验证之间如何取舍；
- 一个人同时承担多个长期项目时，哪些主攻、保底或停止。

SRA 的判断中心不是“哪个任务听起来更重要”，而是：

> 哪些候选真正竞争同一种有限资源，它们如何影响同一个目标门槛，当前下一批资源投到哪里最合理。

## 核心判断

SRA 使用以下顺序：

1. **硬底线**：安全、合规、权限、伦理、不可逆伤害等先作为 Gate。
2. **可行组合**：先找出哪些行动组合能在时间窗和风险底线内达到目标。
3. **达标必要项**：保护删掉后就无法支持本轮达标的部分。
4. **方向、瓶颈和窗口**：优先处理能改向、解锁后续或保护机会窗口的小事项。
5. **组合价值**：在剩余可行组合之间比较风险、收益、证据和机会成本。
6. **下一投入批次**：决定下一份能够产生可观察结果的资源投向。
7. **机动资源**：必要时保留资源，而不是把所有容量立即填满。

压缩表达是：

> 先排除不可行，再保护达标必要项；方向、依赖、瓶颈和窗口决定先后；组合价值决定本轮投哪套；边际价值决定下一份资源投哪里。

## 两档使用方式

SRA 默认轻量运行。只有错误分配可能造成较大损失时，才展开完整分析。两档共享同一个
“收缩—回补”核心：Lite 只做一次微型收缩和一次微型回补，Full 才把它展开到多个组合、
多种资源和相邻压力场景。

### Lite：快速优先级决策

Lite 用于普通执行过程中的下一步判断。

它只回答：

> 下一份有意义的资源，是继续投在当前任务，还是切换、保底、延后、停止或保留？

Lite 通常只比较：

- 当前路径；
- 最强的可信替代项；
- 维护、延后、停止和保留资源。

它先做一次**微型收缩**：当前投入可以删减、封顶或降到什么程度，仍然守住目标门槛和风险底线；
再做一次**微型回补**：从这个当前底座出发，下一批资源投给当前路径、最强替代项还是保留，哪一个最能改变结果。

输出可以很短：

```text
当前决定：切换到支付验证
为什么现在：支付仍阻塞上线，动画只提高完成度
当前底座：页面只维持上线阻断缺陷修复
下一投入批次：一个工程师日，产出可复现的支付验证结果
当前投入上限：到本次验证检查点为止
延后或停止：动画优化延后，页面仅修上线阻断缺陷
重排触发：支付验证通过、出现新阻塞，或页面发生上线阻断问题
```

Lite 只授权一个动作、一个资源批次，或到一个明确检查点。它不会因为一次快速判断，自动批准当前路径长期持续投入。

### Full：完整资源分配

Full 用于项目、Mission、产品组合或重大执行调整，例如：

- 多个可行组合争夺同一周期；
- 多种资源同时受限；
- 投入有固定门槛，少量投入不会产生价值；
- 方向性未知可能使大量后续工作失效；
- 决策金额大、影响广、难以回退；
- 需要形成主攻、支撑、维护、延后、停止和机动资源的完整方案。

Full 会完成：

1. 锁定目标、门槛、时间窗、风险底线和决策责任人；
2. 找出真正竞争的资源和当前主导约束；
3. 让候选达到最低可比程度；
4. 处理可能改变方向的关键未知；
5. 构造一个或多个当前最小充分组合；
6. 淘汰不可行和被其他组合全面支配的方案；
7. 运行资源收缩，找到不可删项和失败边界；
8. 运行资源回补，判断下一批资源加在哪里；
9. 形成当前分配和机动资源；
10. 设置决策有效期与重新排序条件。

## 相对独立的混合运行

SRA 不应让“生成、维护或辩护当前任务的同一段上下文”直接拥有资源分配权。它会先把当前
目标、约束、候选、证据和假设整理成一个密封分配包，再让 Agentic 判断在这个包内完成。

稳定部分交给脚本：

- 建立上下文准入账本；
- 保留当前指令、用户约束、证据、权限、显式假设和相关历史；
- 默认隔离既有结论、候选宣传和环境推断；
- 把候选整理成同样结构的卡片；
- 生成与输入顺序无关的匿名候选；
- 锁定包、盲评结果和状态复核的哈希；
- 检查证据、假设和状态引用；
- 渲染最终决策。

真正的判断仍然交给 Agent：哪些事项必要、哪个组合可行、收缩到哪里会失效、下一批资源
投向哪里，以及真实切换成本是否足以改变盲评结果。

SRA 支持三种隔离强度：

- `packet_bound`：当前 Agent 只能引用密封包；这是逻辑隔离，不能声称已经忘记原上下文；
- `fresh_context`：新子 Agent 或临时 CLI 只读取分配包，且保持只读；
- `blind_then_state`：先匿名判断候选，再单独加入当前路径、切换成本、可复用资产、剩余成本和
  已有承诺进行复核。历史投入只能作为沉没成本被识别，不能成为继续理由。

普通 Lite 使用最小的包内判断；污染风险高或重大 Full 决策优先使用新上下文的两阶段判断。
这能降低上下文污染，但不能证明候选已经穷尽，也不能证明最终优先级一定正确。

## Candidate Horizon Probe / 候选视野探针

SRA 在决定优先级前，会短暂检查当前视野是否被正在做的任务占据。

至少扫过：

1. 当前路径；
2. 硬 Gate、阻塞项或达标前置项；
3. 会改变方向的未知、不可逆风险或正在关闭的机会窗口；
4. 对同一目标最强的可行替代项；
5. 保底、保留、延后和停止选项。

这不是要求全面盘点所有任务。它只防止 Agent 在 A 和随手想到的 B 之间认真比较，却漏掉真正关键的 C。

## Current Minimum Sufficient Bundle / 当前最小充分组合

SRA 寻找的不是“最小任务”，而是当前证据下能够使目标成立的一组行动。

一个组合在以下条件下可以称为当前充分：

- 在明确的时间窗和风险底线内，足以支持达到目标门槛；
- 删除其中任一不可替代部分后，达标判断不再受到充分支持；
- 不包含只改善观感或形式完整性、却不影响目标、风险、证据或必要可选性的投入。

“最小”不等于脆弱。备份、回滚、复核和冗余在风险底线要求时，也可能是必要项。

如果当前资源下没有任何组合能够达到目标，正确输出是：

```text
当前无可行组合
```

然后说明缺少什么资源、哪个门槛造成不可行，以及什么变化能够恢复可行。不能为了给出答案而偷偷降低目标。

## 资源收缩—回补循环

Lite 用一次微型收缩和一次微型回补完成下一批资源判断；Full 对多个可信组合反复施加现实压力，
直到找到当前底座、失败边界和下一批投入。轻量模式减少分析宽度，不省略方法核心。

### 收缩

在保持目标门槛和风险底线不变的前提下，逐步收紧真实的受限资源：

- 哪些行动仍然不能删；
- 哪些可以替换、合并、并行或降级；
- 删除什么会改变方向或阻塞多项后续；
- 哪些投入只是在达标之后继续提高完成度；
- 哪种资源最先使组合失效。

### 回补

从最低可行组合开始，逐步加回下一份能够产生结果的资源：

- 哪一批投入解除当前瓶颈；
- 哪一批投入打开最多后续选项；
- 哪一批投入提供最高的信息价值；
- 哪一批投入保护最重要的时间窗口；
- 哪一批投入最能提高目标相关结果。

一句话：

> 收缩找出不能删的；回补决定下一份值得加的。

如果收缩和回补顺序冲突，通常存在依赖、组合效应、固定投入门槛、切换成本或未解决的不确定性。此时保留条件式或局部顺序，不强行生成虚假排名。

## 不同资源不能简单相加

时间、资金、工程师、法务、管理注意力、风险额度和机会窗口并不总能互换。

SRA 会先判断：

- 当前真正受限的是哪一类资源；
- 哪些候选确实竞争同一资源池；
- 哪些工作可以使用不同资源并行推进；
- 哪些任务需要不可分割的投入门槛。

因此，它不要求把所有因素压成一个统一分数。

## 切换成本与沉没成本

执行中的重排需要区分：

- **沉没成本**：已经花掉且无法收回，不能成为继续投入的理由；
- **切换成本**：从当前状态转向另一条路径需要新增的真实成本；
- **可复用资产**：已经完成、未来仍然有价值的工作；
- **剩余成本**：从现在开始完成当前路径还需要多少资源。

判断比较的是从当前状态开始的未来后果，而不是两条路径历史累计投入谁更多。

## 什么时候不用

以下情况直接处理更好：

- 只有一个明确阻塞项；
- 没有真实的共同资源竞争；
- 不同任务使用独立资源，可以并行；
- 选择低风险、可逆，尝试成本低于分析成本；
- 只是按既定顺序执行的简单清单。

SRA 的目标是降低错误分配成本，不是给每个待办增加一套仪式。

## 与其他方法的关系

| 方法 | 拥有的判断 | 与 SRA 的关系 |
|---|---|---|
| `3L5S` | 问题发现、定义和拆解 | 让候选达到最低可判断程度；SRA 决定哪些获得资源 |
| `EDSP` | 命题结构、伪二选一和判断坐标 | 为可能改变分配的结构未知提供约束 |
| `SELA` | 系统效率与局部优势的长期方向 | 提供方向约束；SRA 决定当前资源配置 |
| `MPG` | 一个已选主线的载体、暴露和路径承载 | SRA 选跨候选资源；MPG 设计单一主线如何穿越路径 |
| `WAE` | Agentic system 的 Workflow / Agentic / Evidence 控制边界 | 只在 SRA 运行方式存在控制者错配时介入 |
| `TVG` | 单个有界产物的下一轮价值增益 | 产物内部由 TVG 判断；产物与外部任务争资源时由 SRA 判断 |
| `Anti-Spiral` | 发现局部修补正在替代目标推进 | Anti-Spiral 刹车，SRA 决定释放的资源去哪里 |
| `TPlan` | Mission 状态、证据、权限、恢复和任务变更 | TPlan 记录和执行；SRA 只提供真实资源竞争下的语义判断 |

尤其要区分：

```text
多个问题、任务或行动组合争夺公共资源 → SRA
一个已选主线需要选择载体、暴露和穿越路径 → MPG
```

TPlan 的 Pulse 仲裁、Mission 重入、同路径继续授权和任务变更权仍然属于 TPlan，不由 SRA 接管。

## 证据边界

SRA 可以让资源分配变得：

- 更显式；
- 更容易审查；
- 更不容易被当前细节绑架；
- 能明确产生延后和停止清单；
- 能设置资源上限与重排条件。

它不能仅凭一套完整结构证明：

- 这一定是正确优先级；
- 这个方案一定最大化 ROI；
- 当前组合是数学最优解；
- 压力测试通过就等于真实业务价值已经被证明。

脚本可以管理上下文准入、候选对称化、包与判断哈希、阶段顺序、引用检查和结果渲染；
它不能替人或 Agent 判断真实必要性、组合充分性、语义 ROI 或正确优先级。
