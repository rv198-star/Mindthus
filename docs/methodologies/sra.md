# SRA / 稀缺资源分配

## 这是什么

SRA 用来处理一种常见但经常被普通优先级表掩盖的判断：

> 多个正确且有价值的事项竞争同一批稀缺资源时，当前投哪一组，哪些只保底，哪些延后或停止？

它的核心是 `资源收缩—回补循环`。

- **收缩**：在目标和风险底线不变的前提下，对可能达标的行动组合持续做减法，直到再减一步就无法合理支撑目标。
- **回补**：从这个最低可行底座开始，一份一份地加回资源，判断下一份资源放在哪里最改变结果。

一句话：

> 收缩找底座，回补定增量。

## 解决什么问题

普通排序经常把底线、依赖、必要项、瓶颈、增强项和可选项混成一个分数。它还容易：

- 排单个任务，却忽略必须一起成立的组合；
- 因为一项工作已经开始，就让它继续占用资源；
- 在资源不足时偷偷降低目标；
- 把不同资源池错误地换算成一个总分；
- 把沉没成本当成继续投入的理由；
- 没有明确的保底、储备、延后和停止项；
- 在证据、约束或机会窗口变化后仍沿用旧排序。

SRA 不追求一个永久正确的总排名。它只给出当前证据下的有限分配和重排条件。

## 核心判断

> 在目标、风险底线和资源约束不变的前提下，先收缩到刚好还能达标，再从这个底座回补下一份最值得投入的资源。

这里的“最小”是当前证据下的最低可行组合，不是数学最优，也不是把方案削到最脆弱。

## 什么时候使用

同时满足以下两点时使用：

1. 至少两个有效行动、行动组合、继续/切换/维持/储备姿态竞争同一稀缺资源；
2. 判断会改变下一次投入、投入上限、保底线、储备、延后/停止项或重排触发器。

以下情况直接执行：

- 只有一个明确必做动作；
- 任务使用不冲突的资源，可以并行；
- 选择可逆，试一下比分析便宜；
- 候选问题还没定义清楚，此时先补事实或使用 3L5S。

## 怎么用

### 1. 锁定分配框架

写清本轮目标、达标门槛、时间窗口、风险底线、决策权限、真正争用的资源池和证据上限。

资源减少不等于目标自动下降。改目标必须成为新的授权决策。

### 2. 扩展候选视野

至少看见：当前路径、硬阻塞或必要前置、会改变方向的未知、最强替代组合，以及维持、储备、延后和停止姿态。

候选要保持可比粒度。把一个事项拆成更多行，不能增加它获得资源的权重。

### 3. 形成可能达标的组合

互相补足才能产生价值的动作先组成 bundle。此时只叫“可能达标的组合假设”，不能提前称为最小组合。

### 4. 做资源收缩

尝试删除、降级、替换、延后、并行，或把完整工作改成足以支持当前决策的最小验证。

每次都问：

- 目标不变时还能达标吗？
- 风险底线仍满足吗？
- 是否暴露隐藏依赖或固定门槛？
- 这项现在不可缺，还是只是做了更好？

当再减一步会使目标不再得到充分支持时，得到 `当前最低可行底座`。

若没有任何组合能成立，结论是“不可行”，不是擅自降低目标。

### 5. 分开处理资格、依赖和组合选择

- 安全、合规、伦理、权限和目标门槛负责资格过滤；
- 前置关系和固定门槛负责执行顺序；
- 候选角色只描述它在当前窗口里的作用；
- 组合比较负责选择；
- 回补负责下一份资源投向。

不要把它们压成一个固定优先序或总分。

### 6. 做资源回补

从最低可行底座开始，比较下一份有意义资源。它可以是一轮实验、一个工程师日、一次评审、一个工作包，或跨过固定门槛的最小团队/预算块。

优先考虑能：

- 移除瓶颈；
- 改变或验证方向；
- 解锁后续选项；
- 保护机会窗口或避免不可逆损失；
- 产生高价值决策信息；
- 提升达标概率、韧性、质量或选择权。

默认使用定性比较、支配关系和条件判断。只有真实数据支持共同单位时才使用数字 ROI。

### 7. 输出六条资源通道

- `主投入`：本轮主要资源去向；
- `必要支撑`：主投入成立所需资源；
- `最低维持`：保持运行或可逆性的保底线；
- `储备`：暂不投入，并写明释放条件；
- `延后`：有价值，但本轮不增长；
- `停止`：当前目标和证据下不再继续。

同时给出下一份资源、投入上限、授权范围、证据上限、判断有效期和重排触发器。

## 自适应深度

SRA 只有一条主路径。简单场景可以只做一次真实收缩和一次回补比较，但不能省略核心。

当出现多个组合、多种受限资源、固定门槛、切换成本、方向性未知、不可逆性或高影响投入时，扩展候选、证据和压力情景，仍然沿同一循环判断。

## 默认输出

```text
决定：直接执行 / 分配 / 条件分配 / 不可行 / 阻断
为什么是现在：与目标直接相关的原因
当前底座：目前证据下不能再删的组合
下一份资源：明确、有限的投入
投入上限：本轮最多投到哪里
保底 / 储备：最低维持或预留
延后 / 停止：本轮被挤出的事项
重排触发：哪些变化后重新分配
```

普通回答先给结论，不展示完整方法结构。结构化 trace 只服务审计、回放、验证和交接。

## 常见误用

第一种误用，是轻量场景只比较“当前 vs 替代”，没有真正做收缩和回补。这只是普通优先级判断。

第二种误用，是先宣布最小组合，再让收缩为它找理由。正确顺序是先提出可能达标的组合，再通过收缩发现最低可行底座。

第三种误用，是把底线、依赖、角色、价值和边际收益混成一条固定序列。它们属于不同逻辑层。

第四种误用，是用任务数量、文档完整度或形状验证器证明资源分配正确。结构完整不等于判断正确。

## 边界

- 问题或候选还不清楚时，先用 3L5S。
- 命题结构不稳时，用 EDSP。
- 长期系统效率与局部优势的方向判断，用 SELA。
- 已选主线的承载者、暴露、时机和可选性，用 MPG。
- Agentic / Workflow / Evidence 控制权错位，用 WAE。
- 单个成型产物内部是否继续强化，用 TVG。
- TPlan 负责 Mission 状态、权限、证据和任务变更；SRA 只负责语义分配。

不建立固定调用链。只有某个未知真正控制当前分配时，才交给对应方法处理。
