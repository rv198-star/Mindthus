## 减负目标与真实观测

目标是**在保留任务质量的前提下，减少不必要的token消耗**。不要求精简后的答案一定更聪明。

已完成16个公开场景的Sol 6.1当前/精简32条、Astra抽检8条、无Mindthus Sol对照4条，共44条真实交付。执行端依事前固定判据知晓分组核对：42份可用、P01两臂2份部分可用。这不是独立盲测、未见样本认证或普遍质量优势证明。

Sol 6.1的15组同CLI可比较路径：

|指标|当前版|RC01被测实现|
|---|---:|---:|
|输入token|472459|434320（少8.1%）|
|逻辑调用|24|23|
|宿主会话秒|550.931|482.025|

L02跨CLI版本只比较内容，不纳入上述匹配性能统计。主要局部节省来自迁移两例少一次伴随方法读取。Astra的4组配对则从4次变为5次，输入从74489变为91774：Skills一例的额外读取抵消了正文缩减，不隐藏这项结果。输入token含共同系统上下文，缓存影响金额，不把8.1%直接称作费用节省率。

四条无Mindthus对照也都可用，说明这些场景里模型自身已足够；不能由此断言全部Mindthus方法无价值，也不能将这些正确回答算作方法独有增益。无Mindthus仍是同一Codex系统环境，不是无系统提示裸API。

全部执行累计98次，包含34次因项目上下文污染而剔除的调用，以及一次旧unknown与经指定授权的补试；后者远端状态继续未知。保留全部原始产物和损失，不以补试成功追认干净首发。真实金额与底层HTTP次数保持unknown。
