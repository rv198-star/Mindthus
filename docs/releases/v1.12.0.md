# Mindthus v1.12.0 — Explain 人向交付与 TPlan 进展视图

发布日期：2026-10-06。

这是 1.x Stable 线的功能 minor release。新增 `Explain / 解释与表达`，并把正式 Explain Skill 设为 Mindthus 有意义人向结果的默认交付层；同时补齐 TPlan 的来源约束进展/剩余工作视图和 ChatGPT 对话内交互展示。

## Explain / 解释与表达

- 默认 clarity：各 Mindthus 方法形成判断后，由当前 Agent 使用 Explain 完成人向交付；已清楚的结果允许原样通过。
- 支持 `--brief`、`--eli5`、`--audience`、`--html`，模式只改变理解与呈现，不接管上游判断、证据、状态、验收或执行权限。
- 精确 JSON、代码、命令、逐字引用、机器记录与固定格式继续遵守上游合同；短确认和心跳不会被扩写成报告。
- 普通运行仍是轻量 `Input → Explain → Output`，不新增独立 Agent、第二模型调用、先写完整答案再重写的固定流水线或 runtime AI-review loop。
- 3L5S、SELA、MPG、SRA、EDSP、WAE、TVG、TPlan 和 `using-mindthus` 都接入正式 Explain 入口；Explain 不进入 judgment owner。

## TPlan 进展与剩余工作

- 新增可选 `work_plan`，记录剩余估计、已声明前置和并行条件；unknown 与 zero 分开，估计更新不冒充执行推进。
- 文字/JSON/HTML/Visualizations 视图都从同一只读 `tplan.progress_view.v1` 来源构建。整体百分比只有上游提供有意义口径时才显示，不从任务数量、历史耗时或 token 使用量倒算。
- 同单位剩余工作可以透明计算构成占比；区间保持区间，不取中值。依赖、逻辑独立和实际并行资源条件分别表达。
- 风险、阻塞、证据、依赖图和估算依据进入下钻层；首屏优先回答整体状态、剩余工作和剩余构成。

## HTML 与 ChatGPT Visualizations

- ChatGPT 上 `--html` 优先使用已现场验收的 **Visualizations / app_block**；HTML fragment 由宿主 sandbox/iframe-like surface 呈现，不用 Code/Preview 冒充交互。
- `render_user_update.py --visualization` 与 `render_progress_view.py --format app-block` 提供 TPlan 的结构化适配；点击、展开、dependency-edge 高亮等交互只改变视图，不产生 Mission authority。
- 其他真实 HTML renderer 可继续使用完整 self-contained HTML；只有用户明确要求保存/下载/导出时才持久化 `.html` 文件。

## 验证范围与证据边界

当前 release candidate 已通过 Explain/TPlan/packaging 聚焦回归、完整 unittest、Test Lifecycle、五种发行布局、可移植性 lint 和 GitHub Python validation。ChatGPT Visualizations 已在当前会话现场确认可交互；发行前也复核了 renderer 对 Mission/evidence/trace 的只读边界。

开发期 A–D 样例覆盖 brief、ELI5 + audience、普通 Explain 和组合 HTML；默认 Explain 另有六个同源固定用例覆盖短结果、关键限定判断、TPlan 进展、精确 JSON、精确命令和短确认。这些是有限开发证据，不是跨模型生产 A/B 或金额 ROI 证明；本版不承诺固定质量提升、token 节省或延迟收益。

## 发行范围

Stable 发布不再要求同步 ROI Beta。**v1.12.0 不发布 ROI Beta**；既有 Beta 标签、资产和源码保留，后续只有明确需要时才单独安排。TPlan runtime generation 保持 `1.5.4`。
