# Mindthus v1.14.0 — TPlan 多会话目标保持

发布日期：2026-11-18。发行性质：**Stable / v1.14.0**。

## 多会话协作时，A 持续负责自己的目标

设计会话 A 可以把开发交给 B、审计交给 C，同时用 TPlan 保持用户交给自己的目标、职责和验收标准。B/C 使用普通工作说明与自然语言回复，只有 A 需要 TPlan。用户说明目标、分工和通信授权后，A 在实际委派时按需启用协同，无需指定模式口令。

每次反馈先关联任务、轮次和成果版本，再由 A 判断是采用、补证据、返修、延后还是调整路径。实现排错由 B 自主处理；A 继续设计、证据判断和最终验收。明确的用户目标变更写入当前目标与验收。

## 可靠反馈、当前验收与有效续接

- 非当前焦点任务的反馈仍会进入 Pulse，处理后保留 A 的当前职责和下一动作依据。
- 稳定发送意图记录已发送、未知和执行状态；发送结果未知时查询原会话对账，同一回报重复导入只产生一次业务效果。
- 当前采用和必需审查绑定任务、轮次、合同、成果摘要及审查范围；旧版本 PASS 保留历史，当前版本按自己的证据验收。
- 连续返修逐项承接验收责任。Task 完成、Mission 收口与恢复视图共用当前责任投影，覆盖分支、最新失败和缺失审查。
- 外部等待保存恢复条件；事务锁、Guard、运行时指纹、证据资格和关闭检查继续生效。

## 同批收录的 TPlan 接口

本版也包含 v1.13.0 后已经合并的接口工作：

- Q1：固定构建身份下的一致只读查询。
- Q2：可选原子命令、持久结果、幂等与恢复。
- H1：可选的按任务范围人工控制、候选成果和完成内核，以及绑定固定 Mission、身份和权限范围的 Host writer 入口。候选存储使用目录描述符约束文件操作。

普通 TPlan 使用不依赖 H1。H1 普通入口保持 `host_disabled`；启用它的宿主负责可信身份、签发密钥、存储和写入权限隔离。真实人工业务闭环按该宿主单独验收。

## 验证

Issue [#246](https://github.com/rv198-star/Mindthus/issues/246) 的工程独立审计、源 Agent 受控目标保持场景和普通本地 A/B/C 真实闭环均通过。真实闭环经历交付、独立 FAIL、完整返修、当前成果独立 PASS，再由 A 正常收口；原目标和验收保留，未决反馈与当前差距为零。

工程回归覆盖重复/乱序回报、旧版本 PASS、Guard、未知发送、崩溃恢复、等待续接和角色/权限。发布检查覆盖版本一致性、五种干净解包布局、当前运行时指纹及仓库 CI。

当前 Codex MCP 工具面提供发送、唤醒、回传和查询；发送幂等键及 stop/interrupt 未暴露，取消需有实际宿主能力才可确认。普通同账户会话采用协作记录与代次校验；物理写入者隔离由宿主权限提供。

## 升级与历史任务

- TPlan runtime generation 为 `1.6.0`，source ID 为 `mindthus-tplan-v1.6.0`；产品包版本为 `1.14.0`。
- 已固定旧运行时的 Mission 继续用原运行时完成。升级前保留旧版本，避免替换在途任务的 writer。新 Mission 使用新版。
- 历史无指纹 Mission 沿既有兼容规则处理；已有指纹保持不可变。需要排查选择时使用 `runtime_doctor.py`。
- 回退可使用 [v1.13.0](https://github.com/rv198-star/Mindthus/releases/tag/v1.13.0)；本版创建的 Mission 应继续使用其固定的 1.6.0 运行时。
- **ROI Beta 已停止维护及后续发布**。历史标签和资产保留。
