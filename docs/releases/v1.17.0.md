# Mindthus v1.17.0：人类插话规则与会话接管

发布日期：2026-11-24。Stable 小版本。上个版本打通了交付的登记和催办；这个版本解决另一半问题——你在主会话或任何子会话里直接输入时，会话怎么处理被打断的工作。

## 实际发生过什么

此前没有规则区分"人在说话"还是"会话在说话"：会话要么凭消息开头的格式猜，要么停下来问，容易出现不必要的中断。用户级 Stop Hook 启用后，它的拦截提示会作为一条新输入出现在会话里，需要能和人说的话区分开。

## 这个版本怎么处理

- **识别靠宿主标注**：输入框消息的 `turn_trigger` 是 `composer`，会话消息带 `<codex_delegation>` 和 `source_thread_id`，Stop Hook 的拦截提示以 `[dispatch-hook]` 开头。不靠消息格式判断说话者。
- **优先级**：人类消息到达后立即处理，不进收件箱排队，排在待处理交付之前，效力高于派工单。
- **默认继续**：提问回答后继续，范围内纠正照改继续，改目标按新目标重排继续，另起一件事做完回原工作，意思不明确按最保守的理解继续并说明；暂停、停止、接管照做停下。回复第一行用一句话说明处理方式。
- **只在两种情况确认**：与硬边界冲突或继续做会花钱、对外发内容、无法撤回；两种理解差别大且选错难改。确认用一次异步提问，只停受影响部分。
- **主/子会话区别**：子会话里你的话直接生效，改目标、范围、接口或停止接管时通知主会话一次，范围内纠正写进交付偏差清单；主会话在交接点传达，只有紧急停止才插入子会话。
- **人类接管状态**：你在某个子会话里持续操作时，用 `dispatch_inbox.py takeover` 登记，Stop Hook 和心跳都不提醒、不拦截它；`release` 解除后恢复。接管只暂停提醒，不处理事件也不销义务。
- **随附修复**：Hook 生效检测只认带真实 `session_id` 且 `hook_event_name` 为 Stop 的运行记录，测试不再写真实仓库；非收件会话执行 done 退出码改为非零。

## 验证与升级

插话规则、接管标记、Hook 跳过逻辑和非零退出码都有自动化测试覆盖，并用合成 Hook 输入验证；识别规则中的宿主标注来自真实会话记录核对。「真实会话中演练三类插话」需要真人输入，演练脚本见[协同与派工指南](../guides/tplan-and-dispatch.md)。

产品包版本为 `1.17.0`，TPlan runtime generation 保持 `1.7.0`，已固定旧运行时的 Mission 继续使用原版本。ROI Beta 已停止维护及后续发布。
