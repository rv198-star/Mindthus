# Mindthus v1.17.1：插话规则修复

发布日期：2026-11-24。修复版，不新增方法和规则——v1.17.0 部署后的真人演练已经完成，三类插话都按规则处理了，但演练和一次真实 Hook 拦截各暴露出一处需要修正的描述。

## 演练和真实拦截发现的问题

「改目标」演练里，子会话过了约 25 秒、随交付一起才告诉主会话——规则只写了「通知主会话一次」，没要求立即通知，任务一长主会话就很晚才知道。另一次真实 Stop Hook 拦截显示：拦截提示不是新开的回合，而是同一回合里一条 `HookPrompt` 类型的输入，包装为 `<hook_prompt hook_run_id="stop:0:...">[dispatch-hook] …</hook_prompt>`，所在回合的 `turn_trigger` 仍是 `composer`——只看回合标注会把 Hook 提示当成人的话。

## 这个版本修了什么

- **子会话立即通知**：改目标、范围、共享接口或停止、接管时，立即通知主会话一次，不等交付；范围内的纠正仍写进交付偏差清单。涉及 `human-interjection.md`、TPlan `collaboration.md` 和中文指南。
- **派工单写明规则位置**：Dispatch 首份派工单的必填内容里加一项——写明用户中途插话时按哪份规则处理、给出规则文件的位置；TPlan 协同的派工模板同步加上。
- **识别按条目不按回合**：识别表里 Stop Hook 一行改为真实的宿主记录方式（`HookPrompt` 条目 + `<hook_prompt>` 包装），并明确同一个 `composer` 回合里可能混着人类消息和 Hook 提示，要逐条看包装；`[dispatch-hook]` 前缀保留为辅助标记。

## 验证与升级

修正后的文档和此前一样通过全部自动化测试与打包检查；演练结论来自 v1.17.0 部署后的真实会话记录。

产品包版本为 `1.17.1`，TPlan runtime generation 保持 `1.7.0`，已固定旧运行时的 Mission 继续使用原版本。ROI Beta 已停止维护及后续发布。
