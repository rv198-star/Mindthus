# Mindthus v1.17.2：收件箱三步收敛与 Hook 安装指引

发布日期：2026-11-25。小版本，不新增方法。把交付收件箱的日常路径从六个命令收敛到三步，并把用户级 Stop Hook 的安装说明补全为可照做的三步。

## 收件箱日常三步

此前每次交付都要 bind、put、done、discharge 四个命令，缺一步义务就悬着，给审计会话派工漏传 --kinds 还会被误拦。这个版本把日常路径收敛为：**bind 登记回程义务 → put 登记交付 → done 处理后自动核销匹配义务**。done 按「先 worker==sender 精确匹配，否则同一轮同一收件人同一事件类型只剩一条 open 时才兜底核销」处理，多条不匹配保持 open，milestone 绝不核销；bind 默认接受 delivery/review/blocker，put 可省 --sender，list 和 obligations 省略 --task 就能扫全仓；主会话处理完手上的批次即收口回合，不顺着中途新消息滚雪球。Stop Hook 脚本无改动。

## Stop Hook 安装三步

此前的安装说明路径要用户手填版本，升级插件后路径失效 Hook 就静默停了；也没写确认信任和怎么验证。现在示例是你本机那版自解析 `/bin/sh` 命令——自动选最新安装版，升级不用改配置也不用重新确认——合并进 `hooks.Stop` 即可；第二步确认信任（桌面端 Review hooks 或 Settings > Hooks，CLI 用 `/hooks`）；第三步验证装好（在派工仓库结束一回合，看 `dispatch-local/hook-last-run.json` 有没有带真实 session_id 的 Stop 新记录）。脚本在 Python 3.9 及以上都能运行，示例里的解释器换成你机器上的 python3 即可。安装示例随附 CI 测试，改坏了会被拦下。

## 验证与升级

新默认与自动核销经真实历史场景 dry-run 验证；相关测试在系统 python3 和 /usr/bin/python3（3.9）双跑通过。

产品包版本为 `1.17.2`，TPlan runtime generation 保持 `1.7.0`，已固定旧运行时的 Mission 继续使用原版本。ROI Beta 已停止维护及后续发布。
