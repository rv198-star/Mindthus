# Mindthus v1.17.3：会话角色边界与派工契约收敛

发布日期：2026-11-27。小版本，不新增方法；纯文档与派工契约收敛，收件箱脚本与 Stop Hook 脚本均无改动。

## 两类默认角色与红线

批处理只有两类角色。**Owner/Leader**（总策划、业务线 Owner、交付协调）守目标方向与规范底线、拆任务派工、验收或组织独立审计、裁决升级事项；默认不亲自改实现代码或跑长链路测试/批量远端取证，派工确认启动后让出回合等回传，不用带超时的 wait_threads 循环盯线。**Worker**（执行开发、调研、独立审计席，审计席只读不改）在约定边界内执行或只读审计、自证并按约定路径回传一次后结束回合；默认不私自新建子会话转包、不绕开约定收件人、不擅自改变目标或共享契约。平级 Owner 之间的长周期跨线委托不绑成单轮 Worker 义务，否则 Stop Hook 会在对方日常协调回合反复拦截。

## 首份派工单契约

首份派工单现在必须显式写清三项：角色（Worker，或只读审计的 Reviewer）；唯一反馈对象与触发条件——回父会话还是直交指定审计席，以及固定版本就绪、真实阻塞或约定的唯一检查点三者之一才回传；自决档位二选一——`strict` 严格按固定规格、遇计划外变化即停并向父会话发 blocker 裁决，`bounded`（默认）在目标与共享契约不变时自选路径、计划内偏离自处理但全部写进交付偏差清单，触碰目标、共享接口、对外发布或权限时升级。配合这条契约，收件箱明确只走上行：子会话用它回传交付、评审、阻塞，Owner 不拿 `put --event milestone` 向下塞派工指令或排队通知。

## 换人只用于真失败

新建接替会话仅用于会话报错、不可用或压缩后仍不可恢复退化；上下文占用比例（例如 75%）绝不是自动停派或机械换人线，健康会话优先在原会话压缩并沿恢复记录继续。

## 验证与升级

改动为零脚本文档收敛：SKILL.md 体积预算、打包、收件箱、Hook 安装示例与发布边界测试均在仓库 python3 和 /usr/bin/python3（3.9）双跑通过。

产品包版本为 `1.17.3`，TPlan runtime generation 保持 `1.7.0`，已固定旧运行时的 Mission 继续使用原版本。ROI Beta 已停止维护及后续发布。
