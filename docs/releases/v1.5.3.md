# Mindthus v1.5.3 发布说明

发布日期：2026-07-25

发布形态：`v1.5.3` 是 Stable-only release；GitHub Release 提供 Stable plugins、Stable
skills 和 `SHA256SUMS`，不发布 marketplace，也不把旧 ROI Beta
冒充为本版资产。

## 版本定位

`v1.5.3` 收敛 TPlan 的真实性与运行时边界。它让执行过程图只呈现实际可证实的时间，
让正式写入口在修改 canonical artifact 前验证 provenance，并为未来显式绑定的 Codex
执行补齐状态、关联、隐私与 hook 协议。它不新增方法论，不回填历史 Mission，也不声称
Desktop 或 hosted/model/Token 采集已成为默认能力。

## #141：时间线真实性

- `partial` trace 与 `snapshot_only` Mission 不再把可见片段或缺失数据输出为精确
  `started_at`、`finished_at`、`elapsed_ms`。
- 有已观测 span 时，报告可渲染明确标记的 `observed_trace` 窗口；没有 span 时保持
  `not reported`，不会以零值替代未知。
- 标准时间树重放生命周期、active path 与终态。trace 缺头、缺尾、时间倒退或 snapshot
  不一致都会保留降级，而不是让成本数据提升 lifecycle coverage。

## #142：正式写入口 provenance 前置检查

- 新 Mission 写入 immutable runtime fingerprint，记录 package/source、build hash 与
  capability identity。
- Mission state、evidence、execution trace、step log、archive、interaction guard 与
  Codex telemetry sidecar 的支持写入口共用该前置检查；已知不兼容 runtime 在任何 canonical
  artifact 被改写前失败。
- legacy Mission 可读且带警告；仅第一次非 guard 支持写入会将其标记为
  `legacy_adopted`。`runtime_doctor.py` 可诊断重复根、选择错误、缺文件与兼容性。

## #143：状态、关联、隐私与 hook 协议

- `requires_human` 的恢复 cursor 是一个明确、受限的 terminal exception；对应 trace
  commit 与 Mission snapshot 一致，普通阻塞仍须记录 active-node 变化。
- SubAgent 用独立的、非加性 `agent_turn` envelope 记录，绝不创建 Task/SubTask/Step 或
  参与重复资源计费。Hook start/stop 只在同 turn、同类别与同稳定 ID 下关联，重用或不成对
  事件保持可诊断而不伪造零时长。
- 未来执行可用显式 Codex session/thread-to-Mission binding 生成 hooks。adapter 只写
  哈希关联 ID、类别、数值时长/用量、状态与允许元数据；工具参数、输入输出、prompt、
  response、命令、transcript 与 connector payload 都会被丢弃或拒绝。
- hook 文件生成只证明绑定已创建，不能证明 host 已加载。coverage 只有看到实际成对回调后
  才标为 observed；当前未覆盖的 hosted tools、model/turn、Tokens、waits 保持
  `not_reported`。

## 验证

发布构建完成以下本地可复现验证：

```bash
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/build-release-pack.py --package plugins --out /tmp/mindthus-1.5.3-plugins --force
python3 scripts/build-release-pack.py --package skills --out /tmp/mindthus-1.5.3-skills --force
```

隔离安装态的 `runtime_doctor` 已确认 `1.5.3` Mission fingerprint 为 `exact`，并确认
生成的 hooks 指向隔离 cache 中的 `1.5.3` adapter。实际 Codex CLI 同 session E2E 已在
活跃的 user hook source 上记录一个 Bash 调用的成对回调和一个 `script` span；coverage
标为 local-tool `observed`，执行树不再为空，且 Mission 和 host state 中未出现测试命令
内容。此前的项目层 hook source 未被当前 host 枚举，即使文件和 trust override 存在；
因此安装流程现要求先用 Hooks manager 或 `hooks/list` 验证 source 已激活。

SubAgent lifecycle 的 adapter 协议有单元测试覆盖，但本轮真实 CLI 尝试中 host 模型两次只
发出空等待、未产生 spawn 调用；它不能被写成 SubAgent host E2E 已通过。该未观测通道保持
`not_reported`，不影响已验证的 local-tool callback 结论。

## 发布边界

- `v1.5.3` GitHub Release 提供 `mindthus-plugins-1.5.3.tar.gz`、
  `mindthus-skills-1.5.3.tar.gz` 与 `SHA256SUMS`。
- 本版为 Stable-only。`v1.5.2-roi-beta` 仍是独立实验资产，未重新以本版 shared core
  构建、资格验证或发布；它不能被描述为已包含本次修复。
- GitHub CI 因费用停止，本版使用本地可复现测试、隔离 release-pack 与真实同 Mission
  local-tool callback E2E；SubAgent host callback 尚未观测，不伪造或绕过不存在的 E2E
  成功状态。
