# Mindthus v1.5.4 发布说明

发布日期：2026-07-30

发布形态：`v1.5.4` 提供 Stable plugins、Stable skills 与补充发布的 ROI Beta
experimental asset，并由 `SHA256SUMS` 覆盖三份压缩包。本版是 1.x Stable 线的 TPlan
bugfix patch；ROI Beta 从同一冻结 Stable core 重新组装，不取代 Stable。

## 版本定位

`v1.5.4` 收敛 #146、#147、#148 的审计返修结果。它让 Codex App / CLI Hook 遥测接入更
稳健，让缺失遥测时的用户输出更安静，并阻止 TPlan 因残留 Mission 文件而机械续跑旧任务。
本版不新增方法论，不迁移历史 Mission，也不声称 host/model/Token 遥测在所有 Codex 环境中
默认可得。

## 补充发布包：1.5.4 ROI Beta（GPT/Sol）

- `v1.5.4-roi-beta` 从冻结的 `v1.5.4` Stable core
  `17fcfabf697ca104919bb5a87ad7391b8bf52188` 重新组装；因此 #146、#147、#148 的
  TPlan 修复与 Stable core 字节一致。
- ROI Beta 仍只替换薄的 `using-mindthus` 入口和一条已经资格验证的 3L5S Anti-Spiral
  句子；package、marketplace、cache 与 skill namespace 均为 `mindthus-beta`。
- 它只面向高能力 Codex / GPT-Sol 的受限实验，不触发自动迁移；需要完整被动唤起、
  跨模型一致性或保守默认行为时，应安装 Stable。

## #146：Codex Hook 遥测激活与路由

- Codex telemetry binding 新增 fail-closed 激活生命周期：只有精确 hook source 被枚举、四个
  handler hash 可信且 enabled 后，App/CLI Hook 回调才允许写入 Mission telemetry。
- 稳定 dispatcher 的 Hook 定义不再携带 Mission path、session id 或 thread id；宿主
  registry 负责 session -> Mission binding generation 路由，避免每个 Mission 重写已授权的
  Hook hash。
- 审计返修后，hook generator 通过单入口提交 binding state、coverage sidecar 与 dispatcher
  registry：写入前先检查 session 是否已属于其他 Mission；失败时原 binding、coverage、
  registry 和旧 session 路由保持不变。
- 文档隐私表述收窄为：raw session/thread id 只留在 host-controlled state-dir 的 registry 与
  per-Mission sidecar 中，不进入 Mission coverage report 或 execution trace。

## #147：无遥测数据时的简化输出

- Standard 执行图不再在每个节点重复显示未采集的 LLM、脚本、工具、等待与 Token 字段，而是
  收束为 Mission 级覆盖说明。
- `partial` 改称“已观测执行窗口”，`snapshot-only` 改称结构快照，避免把不完整 telemetry
  说成精确 Mission 历时。
- Audit 和 JSON 输出仍保留完整通道状态、诊断原因与 `presentation_density`，便于调试缺失数据。

## #148：Mission 重入恢复判断

- 残留 runtime/shared-context 只产生候选，不再自动授权继续执行。即使 objective 与
  acceptance evidence 匹配，也必须显式提交 `resume_existing` disposition 与 rationale。
- 缺少当前意图、终态 Mission、`requires_human`、stale context 或 runtime provenance 异常都会
  阻止静默续跑。
- 审计返修后，re-entry runtime snapshot 在同一个 Mission 锁内读取
  Mission/narrative/evidence/trace，并基于同一批 bytes 计算内容摘要；assessment 期间新增的
  blocker 不会被 CAS 误认为已经审查。

## 验证

发布构建完成以下本地可复现验证。ROI Beta 构建命令需在 `v1.5.4-roi-beta` 源码 tag 上运行：

```bash
python3 -m unittest discover -s tests/tplan -p 'test_*.py'
python3 -m unittest tests.tplan.test_codex_telemetry_dispatcher tests.tplan.test_mission_shared_context tests.tplan.test_codex_telemetry_adapter tests.tplan.test_codex_telemetry_activation tests.tplan.test_skill_contract
python3 -m unittest tests.test_release_boundary_contract tests.test_packaging_docs tests.test_log_mindthus_runtime tests.test_v1_0_readiness tests.test_v1_0_1_usage_log tests.test_v0_9_acceptance tests.tplan.test_runtime_provenance
python3 scripts/build-release-pack.py --package plugins --out /tmp/mindthus-1.5.4-plugins --force
python3 scripts/build-release-pack.py --package skills --out /tmp/mindthus-1.5.4-skills --force
python3 beta/2.0-beta/build-internal-beta.py --out /tmp/mindthus-1.5.4-roi-beta-marketplace --archive /tmp/mindthus-beta-1.5.4-roi-beta.tar.gz --force
```

## 发布边界

- `v1.5.4` GitHub Release 提供 `mindthus-plugins-1.5.4.tar.gz`、
  `mindthus-skills-1.5.4.tar.gz`、`mindthus-beta-1.5.4-roi-beta.tar.gz` 与
  `SHA256SUMS`。
- `mindthus-beta-1.5.4-roi-beta.tar.gz` 是补充发布的 ROI Beta experimental asset，不是
  `1.5.4 Stable` 的替代版。
- GitHub CI 因费用停止，本版使用本地可复现测试与 release-pack 构建验证；未重新声明 App GUI
  或 SubAgent host callback 的新增实机验收。
