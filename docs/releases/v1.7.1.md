# Mindthus v1.7.1 发布说明

发布日期：2026-08-18

发布 tag：`v1.7.1`

## 版本定位

`v1.7.1` 是 1.x Stable 线的小型判断质量 bugfix patch，不新增方法论、route 或 judgment owner。

它修复两个相邻的可见失败：当一个真实竞争框架仍未被充分构造时，回答可能给出弱反方或停在
“双方都对”；即使内部找到了会改变结论的变量，也可能把 `权重 / target function /
decisive discriminator` 一类内部抽象直接漏给用户，形成正确但不自然的表达。

## 修复内容

- `Pressure Surface Check` 在真实 competing-frame judgment 尚未收敛时，要求构造一个真正
  可能获胜的最强竞争框架，而不是只列 objection。
- 随后只找一个真正能改变 verdict、evidence、action、stop 或 handoff 的 decisive
  discriminator；如果没有任何差异会改变行动，就停止压力检查，不制造平衡 prose。
- 结果立即交回原有 judgment owner；Frame Fitness、Whole Elephant、Decision Context、
  Evidence / Claim Ceiling、EDSP 等原 owner 继续负责 framing、定义权、用户目标、取证和
  malformed binary。
- Visible Translation Boundary：内部可以保留抽象判断表示，对外必须翻译成用户实际面对的
  选择、损失、条件、证据或行动，例如“5K 多花的钱，值不值得换更锐的文字？”。
- 低风险 direct / deterministic / preference 任务继续保持 sleep，不新增 mandatory question
  或 mandatory debate。

## 证据边界

本修复来自 #152 的预注册案例、当前会话 P0/P1/C-lite 调试和用户可见表达回看。当前会话
已经知道研究假设与 rubric，因此这些结果是 protocol-debug evidence，不是独立 P2 证明。
维护者决定将最小修复作为 `v1.7.1` 发布；独立 P2 与冻结 holdout 保留为 post-release
validation，不能被倒写成发布前已完成的独立证据。

## 兼容性

- Stable package / plugin manifest version：`1.7.1`。
- **TPlan runtime generation 继续保持 `1.5.4` / `mindthus-v1.5.4`。** 本 patch 不修改 Mission
  runtime fingerprint，不让既有 Mission 因 Stable patch 版本变化而失配。
- 不新增 schema、method route、judgment owner、persistent state 或 interaction ceremony。
