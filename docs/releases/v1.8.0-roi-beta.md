# Mindthus v1.8.0 ROI Beta 发布说明

发布日期：2026-08-21

`v1.8.0-roi-beta` 是 `v1.8.0` GitHub Release 的 supplemental experimental asset，
与 Stable 同步发布，不是独立 Stable release，也不取代 `v1.8.0 Stable`。

## 组成与边界

- Shared Product Core 固定为 `v1.8.0` release commit
  `42887387800806b08796c5972590272414c28c97`，tree
  `276c1df23a2503bd2a202a6d22cf6ff982c1c9d2`。
- 历史 ROI.2 runtime shape、owner routing 与 3L5S Anti-Spiral correction 保持冻结；
  原 qualification ref 仍为 `4ee3e034db6bf8d1e34002d7f162e2b008516490`。
- v1.8.0 新增一个 bounded Thin Core adaptation，使 ROI 入口同步 Stable 的
  Root-Cause Replacement 恢复语义；实现 ref：
  `64df52651fcc710929ec5fff0e629eedd7b38b2a`。
- v1.8.0 RCR compatibility qualification ref：
  `641a7f3b865864b01b26676b58d540aa8c0d2c5b`。

因此 Beta 继承 Stable 的 Root-Cause Replacement、WAE Ownership Closure、
competitive-frame convergence、Judgment Trace、Case Export、case-prep、Test Lifecycle、
TPlan 等 shared-product-core 能力。RCR overlay 只补齐薄入口恢复语义，不新增 route、owner、
Hook、fallback 或第二条 3L5S correction。

## RCR Thin Core

新 Thin Core 保持 `2292 / 2300` bytes，并保留 ROI.2 原有 frame/whole、decision context、
evidence ceiling、Anti-Spiral 与 direct-execution 边界。

当证据已经确认错误 canonical rule / owner 时，薄入口要求直接替换 canonical logic、移除旧
exception，并以肯定式 mainline 描述正确行为；真实 veto / safety / authority 边界继续显式
保留。根因本来就在局部实现时继续局部 Debug，不升级成 mandatory refactor。

## Qualification

确定性 compatibility qualification 已通过：

- exact v1.8.0 shared-core commit/tree；
- 非声明 runtime delta 文件在 namespace normalization 后与 Stable byte-identical；
- Root-Cause Replacement primitive/runtime manifest、WAE/TVG handoff 完整；
- 历史 ROI.2 3L5S correction 精确保留；
- Beta namespace isolation；
- runtime diagnostic `--strict`：`status=ok`；
- 两次 archive build byte-reproducible。

Fresh `gpt-5.6-sol / xhigh` matched calls 在 OCI 发布节点因缺少 Codex API credential 返回
HTTP 401，未发生模型执行。因此本版**不声称**新获得模型质量、胜率或 Token ROI 提升证据。
历史 ROI.2 live qualification 继续支撑 thin-core runtime shape；本次新增证据只支撑 RCR
compatibility、shared-core 继承、负例边界和可复现构建。

完整记录：
`beta/2.0-beta/qualification/v1.8.0-rcr/RESULT.md`。
