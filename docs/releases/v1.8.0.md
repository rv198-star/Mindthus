# Mindthus v1.8.0 发布说明

发布日期：2026-08-21

发布 tag：`v1.8.0`

## 版本定位

`v1.8.0` 是 1.x Stable 线的根因恢复语义 minor release。

本版新增 `Root-Cause Replacement / 根因替换` 认知原语，补齐 Anti-Spiral 在“停止继续局部修补”之后的恢复动作：当证据已经确认错误的 canonical rule、owner、contract、controller 或上游假设时，直接重写拥有定义权的正确逻辑，而不是继续通过 exception、fallback、override 或反向规则维持旧模型。

它是兼容性的能力新增，不是新的独立 Skill，也不改变既有方法的 judgment ownership。

## Root-Cause Replacement / 根因替换

核心短规则：

> **Fix the cause. Replace the rule. State the intended behavior directly.**
>
> **修根因，换规则，直接写正确逻辑。**

主路径包括：

1. 用证据绑定上游 broken cause；
2. 找到拥有定义权的 canonical owner；
3. 以 delete / rewrite / equal-replace 直接替换错误逻辑；
4. mainline 用肯定式表达目标行为、有效状态和成功路径；
5. boundary / veto / safety / authority 保留明确禁止性语言；
6. 重新验证受影响的 contract、测试、调用方、迁移、文档与回滚面。

本原语不负责发现根因，也不能把“我觉得这是根因”升级成事实。根因仍是假设时，先服从 Evidence / Claim Ceiling。

## Anti-Spiral 恢复链补全

Anti-Spiral 继续负责识别第三次局部触碰、负反馈、加层冲动和弱 evidence-delta continuation，并先刹车回看上游。

当上游证据已经确认 canonical logic 或 owner 错误时，恢复链进入 Root-Cause Replacement。两者职责分离：

- Anti-Spiral 决定何时停止重复局部修补；
- Root-Cause Replacement 规定根因确认后的正确修复形态。

普通 debugging 不会因为本版自动升级成重构。明确 failing test 持续提供因果约束时可以继续沿因果链修复；根因本来就在局部实现时，局部修改就是正确的根因修复。

## WAE / TVG / using-mindthus 接入

- WAE 在 evidence-confirmed controller mismatch 后，把恢复形态交给 Root-Cause Replacement：控制权回到正确 owner，迁移 adapter 只服务真实外部 contract 或 staged migration，并需要 removal condition。
- TVG 如果发现 bounded artifact 的薄弱来自错误 canonical model，会先退出 value-gain loop，完成根因替换后再决定是否恢复强化。
- `using-mindthus` 保持高频入口薄层，不新增 owner；只在 evidence-confirmed canonical error 后提示 Root-Cause Replacement。
- 本版保留 v1.7.0 WAE Ownership Closure 与 v1.7.1 competitive-frame / Visible Translation Boundary，不回退这些现有判断能力。

## Primitive Runtime

`before-continue` primitive activation 增加 Root-Cause Replacement reminder，并要求检查：

```text
if_root_cause_confirmed_replace_canonical_owner
```

primitive checker 继续保持 `shape_only`：它只显式提醒可能相关的切面，不判断 semantic truth、root cause、evidence sufficiency、Gate success 或 exit state。

## 校准与负例

新增五类 calibration：

- 权限判断不断增长角色特例：先确认权限定义权问题，再收归 canonical Authorization Policy；
- prompt 通过第三条禁止式规则继续补洞：回到 task/output contract；
- 明确局部初始化遗漏：直接局部修复，不扩大成架构重构；
- Agent 自行宣布 PASS 后继续叠 reviewer fallback：WAE 先确认 authority mismatch，再重写最终通过权；
- 否定套否定的主规则：mainline 直接表达有效行为，hard veto 独立保留明确禁止语言。

这些负例用于防止两个过度推论：Root-Cause Replacement 不是 mandatory refactor；Affirmative Canonicalization 也不是禁止安全、权限或合规边界使用否定表达。

## ROI Beta 发布例外

Mindthus 的默认规则是 Stable release 同步提供同版本 ROI Beta supplemental asset；本版在发布前显式声明例外：**v1.8.0 不同步发布 `v1.8.0-roi-beta`。**

原因不是 Stable 能力不兼容，而是 ROI.2 runtime profile 会用已资格验证的薄版 `using-mindthus` 覆盖 Stable 入口，同时保留单句 3L5S Anti-Spiral correction。Root-Cause Replacement 恰好改变了这一被覆盖表面的恢复语义：Stable 在 evidence-confirmed root cause 后会从“停止局部修补”继续进入 canonical replacement；旧 ROI.2 薄入口没有经过这项新动作的独立资格验证。

直接重发 Beta 会把“shared core 文件存在”误写成“实际薄入口行为已经继承”。因此：

- 当前 ROI Beta 继续保持 `v1.7.1-roi-beta`；
- 不创建 `v1.8.0-roi-beta` source tag 或 asset；
- 后续若同步 Beta，需要先更新 ROI overlay，并重新验证 action-changing regression、Anti-Spiral near-negative 与 namespace/runtime contract，再单独发布。

这是 `docs/internal/release-defaults.md` 允许的发布前显式例外。

## 兼容性与运行边界

- 不新增 Skill namespace，不改变既有方法调用方式。
- `using-mindthus` 继续保持既有 attention budget。
- TPlan runtime generation 保持 `1.5.4` / `mindthus-v1.5.4`；本版没有修改 Mission runtime fingerprint generation。
- Stable 插件和发行包 manifest 升级为 `1.8.0`。
- 当前 ROI Beta 仍是 `v1.7.1-roi-beta`，不是 `v1.8.0 Stable` 的替代品，也不自动迁移。

## 验证

发布前在仓库根目录运行：

```bash
python3 -m compileall -q scripts skills tests
python3 scripts/check-test-lifecycle.py
python3 -m unittest discover -s tests -q
python3 scripts/build-release-pack.py --package plugins --out /tmp/mindthus-1.8.0-plugins --force
python3 scripts/build-release-pack.py --package skills --out /tmp/mindthus-1.8.0-skills --force
```

验证范围包括：

- Root-Cause Replacement 方法层级、Evidence / Claim Ceiling 和正常 debugging 负例；
- Anti-Spiral、WAE、TVG 与 `using-mindthus` 的引用式接入；
- v1.7.1 competitive-frame / Visible Translation Boundary 与 WAE Ownership Closure 回归；
- primitive activation `shape_only` 边界；
- Codex plugin、Claude Code plugin、Claude portable、Codex portable 与 OpenCode portable 发行布局；
- release pack 中 Root-Cause Replacement 条件资源同步；
- 完整 unittest suite、Test Lifecycle registry 与 release boundary contract；
- 发行包不包含 tests、`docs/internal`、缓存、日志或 bytecode。

## 发布边界

`v1.8.0` GitHub Release 提供：

- `mindthus-plugins-1.8.0.tar.gz`
- `mindthus-skills-1.8.0.tar.gz`
- `SHA256SUMS`

本版不提供 `mindthus-beta-1.8.0-roi-beta.tar.gz`，原因见上面的发布前显式例外。

本版不声称：

- primitive checker 能判断真正根因；
- 所有重复修改都应该重构；
- 所有否定性规则都应该改写成肯定句；
- staged migration 或真实外部兼容层都属于补丁坏味道；
- Stable 的新能力已经通过 ROI Beta 的独立资格验证。
