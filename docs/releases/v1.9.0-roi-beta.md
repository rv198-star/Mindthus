## SRA Thin-Core 接入

当多个已经足够可判断的候选争夺同一项稀缺资源，ROI Thin Core 直接把分配判断交给 SRA，
由 SRA 决定下一批资源、当前上限、延后/停止项、机动资源和重新排序条件。

以下情况不会仅凭“优先级”字样触发 SRA：

- 只有一个明确动作；
- 候选并不竞争同一资源池；
- 目标、候选、资源边界或比较证据不足；
- 活跃问题实际属于问题定义、结构判断、长期趋势、单一路径承载、控制权或 Mission runtime。

这些情况继续 direct、先补证据，或交还相邻 owner。Thin Core 不复制 SRA 实现，也不新增第二个
allocation owner。

## Qualification

确定性 compatibility qualification 要求：

- exact v1.9.0 Stable shared-core commit/tree；
- SRA Skill、公共方法说明、模板与运行脚本完整继承；
- SRA 薄入口正例和 direct / evidence-first / adjacent-owner 负例边界；
- 非声明 runtime delta 在 namespace normalization 后与 Stable 一致；
- 历史 ROI.2 3L5S correction 精确保留；
- Beta namespace isolation；
- packaged runtime diagnostic `--strict` 通过；
- 两次 archive build byte-reproducible。

Stable 的自然唤醒验收支持 Stable 发布门，不自动构成 Beta-specific 的自然唤醒率、相对胜率或
Token ROI 证据。本版只声明组成、继承、隔离、边界与可复现性。

完整资格记录见 `beta/2.0-beta/qualification/v1.9.0-sra/RESULT.md`。
