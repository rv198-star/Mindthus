# Mindthus v1.9.0 发布说明

发布日期：2026-09-04

发布 tag：`v1.9.0`

## 版本定位

`v1.9.0` 是 1.x Stable 线的稀缺资源分配能力 minor release。

本版新增独立 `SRA / Scarce Resource Allocation / 稀缺资源优先分配` Judgment Kernel。
当多个事项都值得做、却争夺同一批时间、资金、人力、注意力、风险额度或机会窗口时，SRA
决定当前先投什么、保什么、延后什么和停止什么，并把结论限制在一个可验证的授权周期内。

它不是普通待办排序、自动 ROI 计算器或通用项目管理器。候选还没有达到最低可判断程度时，
先补事实或由 3L5S 定义问题；已经选定一条主线后，其载体、暴露、时机和退出条件仍由 MPG
负责；Mission 状态、Pulse 仲裁、继续授权和任务变更仍属于 TPlan。

## SRA 的核心判断

SRA 固定先后次序：

1. 排除违反安全、合规、权限、伦理或不可逆伤害底线的候选；
2. 找出在时间窗和风险底线内能够达到目标门槛的可行组合；
3. 保护删掉后会使本轮目标失效的达标必要项；
4. 优先处理会改向、解除瓶颈、保护依赖或抓住关闭窗口的小事项；
5. 在剩余可行组合间比较风险、证据、机会成本和目标相关价值；
6. 从当前底座出发，决定下一份有意义的资源批次；
7. 必要时保留机动资源，不把容量自动填满。

一句话：

> **先保证目标能成立，再把下一份资源投给最能改变结果的地方。**

## Lite 与 Full

普通执行默认使用 Lite。Lite 只授权下一动作、一个有意义的资源批次，或到一个明确检查点；
同时说明：

- 当前决定与现在行动的理由；
- 微型收缩后仍能守住目标和风险底线的当前底座；
- 微型回补后选择的下一投入批次；
- 当前投入上限和授权边界；
- 被挤出的工作与重新排序条件。

Full 只在多个可行组合、多种资源约束、固定投入门槛、方向变化、重大承诺或不可逆风险控制
结果时展开。它形成主攻、支撑、维护、延后、停止与机动资源的完整分配，并声明决策有效期。

两档共享同一个收缩—回补核心：收缩找出不能再删的；回补决定下一份值得加的。Lite 减少的是
分析宽度，不省略方法核心。

## Candidate Horizon Probe

在决定优先级前，SRA 会短暂检查当前视野是否被正在做的任务占据，至少扫描：

- 当前路径；
- 硬 Gate、阻塞项或达标前置项；
- 会改变方向的未知、不可逆风险或正在关闭的机会窗口；
- 对同一目标最强的可行替代项；
- 保底、保留、延后和停止选项。

这个探针不是全面盘点。它只防止 Agent 在 A 和随手想到的 B 之间认真比较，却漏掉真正关键的 C。

## 上下文隔离的混合运行

SRA 保留目标、用户约束、权限、证据、假设和执行状态，同时把旧结论、候选宣传、环境推断与
沉没成本叙事放回正确层级。候选只做结构对齐，不会为了“公平”抹平真实证据差异。

普通、低风险、可逆的 Lite 运行一次情境化判断。进入 Full，或既有结论、当前任务叙事、候选
宣传、沉没成本可能显著污染判断时，运行两个互相不可见的视角：

- `challenge` 去掉当前身份、历史投入和既有结论，检查继续投入是否只是叙事惯性；
- `situated` 保留真实切换成本、可复用资产、剩余成本、承诺与权限，独立形成可执行分配。

Workflow 只负责密封输入、来源边界、结构比较、完整性检查和渲染。Agentic judgment 负责候选
角色、可行组合、收缩、回补与最终分配。两份 typed result 一致时直接采用 situated 结果；
冲突时只允许围绕冲突字段协调一次；证据不足时返回 conditional 或 blocked，不能伪造确定性。

## 方法与运行时边界

- 3L5S 负责发现、定义和拆解问题；候选达到最低可判断程度后，SRA 才接管资源分配。
- EDSP 负责结构歧义；SELA 负责整体趋势和局部优势；MPG 负责一条主线的路径承载。
- WAE 负责 Agentic / Workflow / Evidence 控制权；TVG 负责有边界产物的定向强化。
- Anti-Spiral 先阻止第三次局部修补；若释放出的资源需要在多个候选间分配，再交给 SRA。
- TPlan 保留 Mission identity、Pulse arbitration、continuation、authority 和 mutation ownership。
- 本版不新增全局 `allocation_review` Hook，不改变 TPlan schema 或 runtime fingerprint generation。

## 行为验收

本版在自然弱提示、显式独立调用与最终 SHA Agentic 场景上完成发布前验收：

- SRA 正例自然唤醒：10/12，83.3%；
- 非 SRA 场景误触发：0/12；
- 相邻方法归属：8/8；
- 直接任务保持休眠：4/4；
- 需要可见动作的回答：19/20；
- 显式独立 SRA：12/12 加载 SRA，12/12 给出可见动作。

最终 SHA 还复放了 ordinary Lite、polluted Lite、Full agreement、Full conflict 和
evidence-insufficient 五类运行。冲突场景只协调一次；证据缺失场景阻断最终化；所有 situated
与 reconciliation 输出都没有把沉没成本当作继续投入理由。

一条自然正例没有唤醒 SRA：提示只声明目标清楚，却没有给出各候选收益、延迟成本和三天内最小
闭环。回答拒绝编造这些信息，并提出有边界的临时安排后请求补充。该结果归因为 fixture / evidence
under-specification，没有加入案例特判。

这些结果支持本版的发布阈值，不证明普适路由正确、最优 ROI、生产收入或长期转化效果。

## ROI Beta 同步发布

Mindthus 按 Stable release 默认规则同步提供 `v1.9.0-roi-beta` supplemental experimental asset。

ROI Beta 从精确 `v1.9.0` Stable shared core 组装，继承完整 SRA Skill、上下文隔离运行时与其余
shared-product-core 能力。ROI Thin Core 只增加 SRA 的资源竞争入口，并继续保留已资格验证的
ROI.2 3L5S Anti-Spiral correction、独立 Beta identity / namespace 和 runtime diagnostic 坐标。

确定性 compatibility qualification 覆盖：

- exact Stable commit/tree；
- SRA Skill、模板、脚本和公共方法说明完整继承；
- ROI 薄入口只在多个可判断候选争夺同一稀缺资源时转交 SRA；
- 缺少共同资源竞争、候选或比较证据时保持 direct / evidence-first 边界；
- 非声明 runtime delta 在 namespace normalization 后与 Stable 一致；
- Beta namespace isolation、strict runtime diagnostic 与两次 archive byte-reproducibility。

Stable 的行为验收不自动升级成 Beta-specific 自然唤醒率或相对胜率；本版不新增这类声明。

## 兼容性与验证

- Stable plugin 和发行包 manifest 升级为 `1.9.0`。
- 不改变既有 Skill 调用方式；SRA 可直接调用，也可在真实资源竞争出现时由入口路由。
- TPlan runtime generation 保持 `1.5.4` / `mindthus-v1.5.4`。
- 发布前运行 Python compileall、Test Lifecycle、完整 unittest、Stable plugins/skills 构建、
  ROI Beta compatibility qualification 和可复现归档检查。
- 发布后重新下载全部资产并用 `SHA256SUMS` 校验。
