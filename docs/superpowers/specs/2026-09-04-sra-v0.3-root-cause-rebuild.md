# SRA Runtime Contract v0.3 — Root-Cause Rebuild

Date: 2026-09-04  
Base: `542ad7fd938e23ed1409b8b1eaca0f73dd4f3c36`  
Prototype reference only: local commit `19507265a2af4fc71c1de484e25e6364cc04c668`

## Decision

Rebuild SRA from the clean v1.9.0 baseline. Reuse only prototype components that survive
contract and behavioral tests. The prototype is evidence and source material, not the
implementation authority.

## Root Causes

The v0.2 runtime has one coupled failure chain:

```text
candidate ID + free prose resource commitment
    -> incomplete dual-view comparison
    -> contradictory allocation accepted
    -> outcome and runtime finalization diverge
    -> mutable run cache becomes workflow authority
```

The repair unit is therefore one version-bound v0.3 contract, not independent local
patches.

## Canonical Ownership

### Agentic SRA owns

- candidate relevance and completeness challenges;
- feasibility and necessity;
- candidate and bundle roles;
- contraction and replenishment judgments;
- qualitative value, risk, and sufficiency;
- conflict reconciliation;
- context normalization and challenge projection.

### Workflow owns

- schema versions and deterministic enums;
- resource, candidate, bundle, evidence, and authority references;
- quantity-family and unit compatibility;
- deterministic posture, capacity, outcome, and finalization consequences;
- packet, prompt, dispatch, command, comparison, final-source, and trace reconstruction;
- version-bound resume and repair of derived artifacts.

Workflow never computes semantic priority, ROI, or bundle sufficiency.

## Canonical Input

### Decision question

The caller supplies two sourced surfaces:

```text
situated_question
challenge_projection
source
projection_basis
```

The challenge packet receives only `challenge_projection`. Workflow rejects direct use of
original candidate IDs in the projection, but semantic de-anchoring remains an Agentic or
coverage judgment.

### Resource pool

Each scarce resource declares:

```text
resource_id
label
quantity_contract
capacity
window
```

Quantity contracts are:

- `measured`: exact or bounded values in one declared unit with additive `sum`;
- `ordinal`: values from one declared ordered scale with `exclusive` allocation;
- `indivisible`: named blocks allocated with block-set semantics.

Candidate demand, current allocation, next tranche, reserve, and investment ceiling all
reference the same resource pool and compatible quantity contract.

### Context fragments

Admitted context carries both a situated statement and a challenge projection. Protected
value and authority constraints remain available without granting inherited authority to
active-path identity, prior conclusions, advocacy, or sunk-cost narrative.

### Override governance

A downgrade of mode, view, or coverage requires:

```text
override_reason
approved_by
authority_ref
risk_acceptance_scope
expiry
```

`authority_ref` identifies an admitted authority decision and the approver must match its
holder. Overrides remain visible in packets, final decisions, integrity reports, and the
human-readable result.

## Canonical Decision Carrier

### Candidate allocation ledger

Every candidate has exactly one row:

```text
candidate_id
posture: floor | maintenance | candidate | defer | stop
current_allocations[]
reason
```

`floor` and `maintenance` carry current resource. `candidate`, `defer`, and `stop` carry
zero current resource. A deferred or stopped candidate cannot receive the next tranche.
An infeasible candidate cannot receive current or next resource.

### Full bundle carrier

Full judgments additionally carry:

```text
bundle_assessments[]
  bundle_id
  member_ids[]
  feasibility
  dominance_status
  dominated_by[]
  resource_requirements[]
  contraction_result
  target_support
  evidence_refs[]
  assumption_refs[]
selected_bundle_id
```

Bundle identity is normalized from sorted member IDs, not local `bundle_id`, so challenge
and situated views can be compared after alias mapping. A selected bundle must be
feasible or conditional and non-dominated; dominance references remain acyclic. A
selected bundle cannot include deferred, stopped, unclear, or infeasible members. Its
resource requirements must fit declared capacity, and the next-tranche candidate must
belong to it; maintenance outside it remains allowed.

### Next tranche, reserve, and ceiling

The decision records typed resource allocations for:

- current floor and maintenance;
- next tranche;
- reserve;
- investment ceiling.

Comparison includes resource identity, quantity, unit or scale/block, window, completion
signal, start condition, authorization horizon, selected bundle, and posture ledger.

## Outcome And Finalization

| Outcome | Immediate resource authorization | Runtime finalization |
|---|---:|---|
| `allocate` | yes | `finalized` |
| `conditional` | no, until the named condition | `conditional` |
| `infeasible` | no target-reaching allocation | `finalized` |
| `blocked` | no | `blocked` |
| `request_missing_context` | no | `blocked` |

Blocked, infeasible, and missing-context results carry no next resource or investment
ceiling. Human rendering must state that no action is authorized.

## Runtime Integrity

`raw-input.json`, deterministic packet construction, recorded judgments, and legal typed
transitions are authoritative. `run.json` and all derived files are caches.

The checker reconstructs and compares:

- mode, view plan, coverage plan, override record, and initial statuses;
- packets and output schemas;
- Agent prompts, dispatch records, and CLI commands;
- recorded judgment validity and hashes;
- comparison and reconciliation packet;
- final source, final decision, and finalization status;
- trace event type, order, payload, and event identity.

Malformed state always returns a structured blocked report rather than a traceback.

A repair command may rebuild caches and derived artifacts from raw input and recorded
judgments only while prepared packet hashes and judgment-event hashes still match. Trace
carrier facts override the mutable run cache. Repair never edits Agentic judgments or
launders changed authoritative inputs.

## Version Boundary

v0.3 writers reject v0.2 run directories with a clear instruction to prepare a new run.
Historical v0.2 release artifacts remain unchanged. TPlan schemas and runtime behavior are
outside this repair.

## Implementation Stages

1. Canonical domain model, resource contracts, outcome mapping, and failing tests.
2. Full bundle carrier and cross-field allocation invariants.
3. Challenge projections, resource-demand binding, and authority-bound overrides.
4. Deterministic runtime reconstruction, prompt/dispatch/command integrity, fail-closed
   checking, repair, and authorization-safe rendering.
5. Templates, fidelity reference contract, public documentation, packaging, full tests,
   and two post-implementation reviews.

## Exit Criteria

- all original audit counterexamples pass as permanent tests;
- Full has an executable bundle carrier rather than prose-only claims;
- all shipped templates validate against generated schemas and runtime validators;
- focused SRA tests and the complete repository suite pass;
- release packs contain every v0.3 runtime dependency;
- no duplicate outcome, authorization, comparison, or finalization table remains;
- post-implementation method and runtime reviews report no unresolved P0/P1 finding;
- `main` remains unchanged until the reviewed branch is explicitly merged.
