# SRA / 稀缺资源分配：资源收缩—回补循环

> 固定目标与风险底线，收缩发现当前最低可行底座，回补决定下一份资源投向。

## 这是什么

SRA 处理的不是“哪些事重要”，而是一个更窄、更硬的问题：

> 多个正确且有价值的事项竞争同一批稀缺资源时，当前到底投哪一组，哪一些只保底，哪一些延后或停止？

它的独特机制是 `资源收缩—回补循环`：

1. 先把一个可能达标的行动组合持续做减法，直到再减一步就无法支撑既定目标或风险底线；
2. 再从这个最低可行底座开始，一份一份地加回资源，判断下一份资源放在哪里最改变结果。

因此，SRA 不是静态优先级表，也不是把所有事项打分后从高到低排队。

## 核心判断

> 在目标、风险底线和资源约束不变的前提下，先收缩到刚好还能达标，再从这个底座回补下一份最值得投入的资源。

一句话：

> 收缩找底座，回补定增量。

这里的“最小”不是数学最优，也不是把方案削到最脆弱。它只表示：在当前证据、时间窗口、权限和风险要求下，这已经是仍能合理支撑目标的最低组合。

## 为什么不能只做优先级排序

普通排序容易把不同性质的东西混在一起：

- 安全、合规和权限是底线，不是待评分事项；
- 依赖关系决定先后，不等于价值更高；
- 多个动作可能必须组合后才产生价值；
- 一个小验证可能改变整个方向，不能因为工作量小就被排后；
- 某项已经做了很多，不代表继续投入仍然值得；
- 时间、资金、专家能力、管理注意力和风险额度不能随意换算成一个总分；
- 把一项任务拆成十行，不应该让它看起来比一行的替代方案更重要。

SRA 将这些逻辑分开处理，而不是压成一个漂亮但不可信的分数。

## 进入条件

同时满足以下两点时使用 SRA：

1. 至少两个有效行动、行动组合、继续/切换/维持/储备姿态竞争同一稀缺资源；
2. 判断会改变下一次投入、投入上限、保底线、储备、延后/停止项或重排触发器。

以下情况直接执行，不开 SRA：

- 只有一个明确阻塞项或必做下一步；
- 不同任务使用不同且不冲突的资源，可以并行；
- 选择低风险、可逆，试一下比分析更便宜；
- 候选问题还没定义清楚，此时先用 3L5S 或补事实。

## 第一步：锁定分配框架

只锁定本轮决策需要的最小框架：

- `parent_objective`：这次分配服务什么结果；
- `target_threshold`：怎样才算本轮达标；
- `time_window`：该判断在多长时间内有效；
- `risk_floor`：安全、合规、伦理、权限、生存等不可突破的底线；
- `decision_owner`：谁有权批准投入、停止、储备或改目标；
- `contested_resources`：真正被争用的资源池；
- `evidence_ceiling`：当前证据最多支持多强的结论。

资源变少不等于目标自动下降。若要把“完成目标”改成“先活着”或“只做部分完成”，必须由有权者明确重设目标。

## 第二步：扩展候选视野

不要只比较“正在做的事”和脑中第一个替代项。至少扫描：

1. 当前行动组合；
2. 硬阻塞、必要前置或固定门槛；
3. 会改变方向的未知、不可逆风险或正在关闭的机会窗口；
4. 对同一目标贡献最大的可信替代组合；
5. 维持、储备、延后和停止姿态。

候选必须保持可比粒度。不能因为把一个候选拆成多个子任务，就增加它获得资源的机会。

最小候选卡只需要：

```text
candidate_id
objective_contribution
resource_demand_vector
dependency_or_bundle_role
evidence_state
delay_cost_or_window
irreversibility_or_downside
```

缺信息时，只补足会改变当前分配的那一项，不追求把所有候选研究透。

## 第三步：形成“可能达标的组合假设”

互相补足才能产生价值的动作，应先组成 bundle 再比较。

例如“上线新支付”可能不是一个任务，而是：

- 支付接口；
- 最低安全验证；
- 回滚能力；
- 必要监控；
- 上线审批。

这时不能逐项和“页面视觉优化”混排。应先形成“支付可上线组合”与其他替代组合。

此时只称为 `target-reaching bundle hypothesis / 可能达标的组合假设`。未经收缩，不得直接称为“最小充分组合”。

## 第四步：资源收缩

对每个可信组合做现实压力测试。可使用的收缩动作包括：

- 删除一项；
- 降低范围、质量、频率或冗余；
- 用更便宜的组件替代；
- 在不丢失窗口的前提下延后；
- 转移到不冲突的资源池并行完成；
- 将完整工作替换成“足以支持当前决策的最小验证”。

每次收缩后追问：

- 在目标不变时，这个组合还足以达标吗？
- 风险底线和权限边界仍满足吗？
- 是否暴露了隐藏依赖或固定门槛？
- 主导约束是否换了？
- 这项是“现在不可缺”，还是只是“做了会更好”？

### 收缩停止点

当下一次现实可行的删除、降级、替换或延后会使目标不再得到充分支持，收缩停止。

此时得到 `current floor bundle / 当前最低可行底座`。

需要记录：

- 留下了什么，为什么此刻不可缺；
- 删掉、降级、替换、延后或并行了什么；
- 再减哪一步会首先失效；
- 每个必要性判断依赖什么证据和假设；
- 什么变化会使该必要性消失。

如果没有任何组合能在既定目标和风险底线下成立，结果是 `infeasible`，而不是偷偷降低目标。

## 第五步：资格、依赖与组合选择

收缩完成后，再比较幸存的最低可行底座。以下逻辑必须分开：

### 资格过滤

违反安全、合规、伦理、权限或目标门槛的组合直接不合格。

### 依赖与固定门槛

前置关系、不可拆的最小团队、必须完整完成的实验周期等决定执行顺序和资源块大小。

### 方向与瓶颈

有些动作体量小，却能：

- 反转主路径；
- 解锁大量后续动作；
- 移除主导约束；
- 保护即将关闭的窗口；
- 避免不可逆损失。

它们应被显式抬升，但不能因此把所有“小动作”都包装成关键动作。

### 支配与条件性

若组合 A 在所有争用资源上都不比 B 多，并且至少一个关键维度更好，B 可被淘汰。

若不同证据状态下会得出不同选择，应返回条件分配，而不是硬造一个总排名。

## 第六步：资源回补

从选中的最低可行底座开始，而不是从历史原计划开始。

一次只比较一个 `meaningful resource tranche / 有意义资源份额`。它可以是：

- 一个完整验证实验；
- 一个工程师日；
- 一轮评审；
- 一个可交付工作包；
- 能跨过固定门槛的最小团队或预算块。

判断下一份资源放在哪里，重点看它是否：

- 移除当前瓶颈；
- 改变或验证方向；
- 解锁更多下游选项；
- 保护窗口或阻止不可逆损失；
- 产生高价值决策信息；
- 提升达标概率、韧性、质量或未来选择权。

默认使用有证据支撑的定性比较、支配关系和条件判断。只有存在真实测量和合理共同单位时才使用数字 ROI。

### 收缩顺序与回补顺序不一致

这不是错误，反而常揭示真实结构：

- 门槛效应；
- 互补关系；
- 切换成本；
- 路径依赖；
- 未解决的方向不确定性。

保留这种不对称，不要为了形式把两条顺序强行做成镜像。

## 第七步：形成分配结果

SRA 输出的不只是一项“第一优先级”，而是六条资源通道：

- `main_allocation`：本轮主投入；
- `necessary_support`：主投入成立所需支撑；
- `maintenance`：维持运行或可逆性的最低投入；
- `reserve`：暂不投入、但有明确释放条件的储备；
- `defer`：仍有价值，但本轮不获得增长资源；
- `stop`：在当前目标与证据下不再值得继续投入。

同时给出：

- 下一份有意义资源；
- 当前投入上限；
- 授权到哪一个动作、份额或检查点；
- 证据上限；
- 判断有效期；
- 什么变化会触发重排。

## 自适应深度

SRA 只有一条主路径，不设一个会绕开核心的“轻量方法”。

普通、可逆、局部决策可以只做：

1. 锁目标、底线和争用资源；
2. 对当前组合做一次真实收缩；
3. 与最强替代的下一份资源做一次回补比较；
4. 只授权一个动作或检查点。

出现以下情况时，仍沿同一循环展开：

- 多个可达标组合；
- 多种受限资源给出不同答案；
- 固定门槛或不可拆投资；
- 切换成本、路径依赖或不可逆性显著；
- 方向性未知会使大量后续投入失效；
- 一轮收缩—回补后仍无法稳定行动。

扩展的是证据、候选、资源通道和压力情景，不是更换判断核心。

## 沉没成本与切换成本

从当前时点比较未来后果：

- `sunk_cost`：已经花掉、不可收回；不能作为继续理由；
- `switching_cost`：从当前状态转到替代方案新增的成本；
- `reusable_asset`：已完成且未来仍可复用的资产；
- `remaining_cost`：当前路径尚需投入的资源。

历史投入可以形成可复用资产或影响切换成本，但它本身没有继续投票权。

## 储备资源

资源不必全部投完。当保留选择权比立即投入更有价值时，可以显式储备。

储备要写清：

```text
reserved_resource
reserve_reason
release_trigger
expiry_or_review_time
```

储备可用于事故响应、回滚、生存缓冲、等待方向证据或保护即将出现的机会窗口。

## 默认可见输出

对用户先给结论，不展示方法墙：

```text
决定：直接执行 / 分配 / 条件分配 / 不可行 / 阻断
为什么是现在：与目标直接相关的原因
当前底座：目前证据下不能再删的组合
下一份资源：明确、有限的投入
投入上限：本轮最多投到哪里
保底 / 储备：最低维持或预留
延后 / 停止：本轮被挤出的事项
重排触发：哪些证据、资源、风险、目标或窗口变化后重算
```

结构化 trace 只用于审计、回放、验证或交接。

## 常见误用

### 误用 1：轻量使用时省略收缩—回补

只问“当前任务和替代任务谁更重要”不是 SRA。即使场景简单，也至少要验证当前组合能否再减，以及下一份资源放在哪里。

### 误用 2：先宣布最小组合，再用收缩证明它

这会把收缩降级成事后辩护。正确顺序是：先提出可能达标的组合，再通过收缩发现最低可行底座。

### 误用 3：把底线、依赖、角色、价值和边际收益排成一条固定优先序

这些是不同逻辑层。混成一条序列会让规则在复杂场景里自相矛盾。

### 误用 4：把任务条数当资源权重

拆得更细不等于更重要。比较的是组合贡献和资源需求，而不是行数。

### 误用 5：为了节省资源偷偷改目标

资源不足时可能确实需要降目标，但这必须成为新的、由有权者授权的决策。

### 误用 6：用形状验证器证明优先级正确

脚本只能检查字段、枚举、引用和证据风险，不能判断目标是否真实可达，也不能判断下一份资源是否真的最优。

## 与其他方法的关系

- `3L5S`：把候选问题定义到最低可比较程度；SRA 负责分配。
- `EDSP`：处理会改变候选集合或方向的结构歧义。
- `SELA`：判断长期系统效率与局部优势的方向压力。
- `MPG`：为已选主线设计承载者、暴露、时机与可选性。
- `WAE`：处理 Agentic / Workflow / Evidence 控制权错位。
- `TVG`：决定一个已成型产物内部是否值得再强化；当它与外部事项争同一资源时才进入 SRA。
- `Anti-Spiral`：发现重复局部修补并踩刹车；SRA 决定释放出的资源去哪里。
- `TPlan`：持久化 Mission 状态、权限、证据和任务变更；SRA 只负责语义分配判断。

不建立固定调用链。只有某个未知真正控制当前分配时，才交给相应 owner；返回结果作为约束继续分配。

## 停止条件

满足以下条件即可停止本轮：

1. 当前最低可行底座能承受相邻现实压力；
2. 下一份资源明确，或只取决于一个具名验证；
3. 剩余未知不足以改变当前动作；
4. 再分析一轮没有明确的正价值假设；
5. 执行证据和重排触发器足以接管剩余不确定性。

SRA 只授权声明的范围，不追求一次算出永久最优。
